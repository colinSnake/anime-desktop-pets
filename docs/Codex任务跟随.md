# Codex 本机任务跟随

2026-11-03 用户明确授权为任务跟随读取本机 Codex 会话文件。本功能只驱动现有工作差分，
不恢复桌宠聊天、历史或输入框。源码与冻结构建的验证范围见[验证记录](实际验证记录.md)。

## 行为

- 正常 `--watch` / `--launch` 联动时，检测到明确任务开始后播放 `work01` 开场，随后持续轮换其余工作差分，直到任务完成或中断。
  五个工作差分仍来自现有授权范围内的本机素材；日常自主池不混入工作动作。
- 完成或中断后取消工作态；若正在工作/待机，按原播放器回到普通待机，继续日常互动。
- 每个 rollout 内按 `turn_id` 区分任务。重复开始不重启姿态；同一会话已有任务时的新轮次（如切换会话后提交工作）仍会触发一次 `work01`。旧轮次完成不会取消另一个轮次；多会话聚合为“至少一个已确认任务仍活跃”。不是当前前台标签页或某个项目的精确绑定。
- `work01` 开场和后续每个工作差分配套显示短文案气泡；文案来自本地固定陪伴文案，不伪装成 Codex 任务标题或实时进度。任务真实标题未接入，且不从会话正文猜测。气泡不会重复拦住自身的任务完成信号；手动消息/额度气泡和拖拽、菜单、隐藏、减少动态效果仍优先。
- 拖拽、点击等待、菜单、气泡、额度查询与隐藏优先；这些交互结束后再切换姿态。
  系统减少动态效果开启时不进入自动工作态；恢复后可重新跟随。
- 额度功能仍只由用户显式触发，不因任务跟随后台查询。无消息内容、工具调用、任务进度百分比或完成通知。

## 数据来源与限制

参考 CCSwitch 的**读取本机 rollout**思路，没有复制其会话浏览、消息解析或恢复会话实现。
参考入口为 `farion1231/cc-switch` 的 `src-tauri/src/session_manager/providers/codex.rs`。
任务跟随是本项目独立编写的兼容适配器，不依赖 CCSwitch 运行，也不查询其数据库。独立的 TiMi 额度查询会按显式请求读取匹配的 CC Switch 配置，见[额度说明](额度气泡说明.md)。

默认读取 `$CODEX_HOME/sessions`，未设置时读取 `~/.codex/sessions`。
仅识别 `session_meta.payload.source` 和 `event_msg.payload.type/turn_id`：

| 字段 | 用途 |
| --- | --- |
| `source = vscode / cli / exec` | 允许本机交互任务；Codex 桌面当前也用 `vscode`。不据此宣称能区分桌面和 IDE |
| 对象形式的 subagent 或未知 source | 不计入跟随，避免子代理额外叠加 |
| `task_started` / `turn_started` + `turn_id` | 将该轮次加入活动集合 |
| `task_complete` / `turn_complete` / `turn_aborted` + `turn_id` | 从该文件的活动集合移除对应轮次 |

本机只读格式核对覆盖 Codex `0.166.0-alpha.5.1` 的近期文件，确认开始/完成事件与上述字段存在；
输出仅为版本、source 和事件字段名/计数，未输出正文或真实任务标识。中断另有合成回归。
另参考 `openai/codex` 的 `codex-rs/protocol/src/protocol.rs` 确认 v2 名称别名 `turn_started/turn_complete`，已加入合成回归。
这是本地 JSONL 兼容性来源，**不是官方跨客户端实时订阅保证**。未将新 app-server 进程视为
能够订阅桌面已有任务，也没有启动第二个 Codex 来发起或恢复会话。

- 不读 `archived_sessions`、索引数据库、认证文件、聊天数据库或账号数据，不修改 Codex 的任何文件。
- JSONL 行在后台内存中暂时经过 JSON 解码；未知字段（包含聊天与工具内容）不进入结果、日志、气泡或磁盘。
  不声称“底层完全不接触正文所在字节”。未完成行只在有上限的暂存缓冲内等待换行。
- 瞬态状态仅包含文件路径/偏移/文件身份、受限未完成行、活动轮次 ID及仅进程内递增反馈序号；不会复制到用户历史文件。
- 不用文本关键词或文件静默判断完成。15 分钟没有文件更新的未闭合任务降为 `unknown`，不报完成；
  因此长时间无输出的真实任务可能暂时不显示工作动画。
- 近期文件冷启动从头按预算分块回放，追平前为未知；大文件可能延迟。超大消息/工具输出行只跳过已识别的非生命周期类型；超大生命周期行仅投影结构化的 `type/turn_id` 前缀。若字段位于截断前缀之外、事件缺失/损坏、生产者未知、文件无法读取或发现范围超限，
  允许降为未知/断开，保持普通行为；不伪造完成。暂不单独识别“等待批准/等待用户输入”。
- 不发网络请求、不发起 Codex 任务、不请求辅助功能权限、不操作 Codex 窗口焦点。

## 运行与资源边界

`Coordinator` 每 2 秒向桌边小崽自身配置目录的 `codex-task-lease.json` 原子写入少量心跳元数据：
版本号、是否允许观察、时间戳。仅正常联动且 Codex 应用仍在运行时启用；暂停/退出即时写入关闭状态，
异常退出的心跳 10 秒过期。关闭后后台丢弃游标，不再扫描会话。

`PetController` 和 `PetInstanceRuntime` 仅在正常联动模式传入 `DRAGON_TASK_LEASE`；
`--preview-pet`、开机动画预览、`--check` 与控制测试不启用观察。
未经增强的 `--full-pet` 和 Swift PNG 降级不具备任务工作动画跟随。

正常观察器每2秒原子写入桌边小崽自身目录的 `codex-task-observer.json`：时间、进程PID、聚合状态/活动数、每只宠物的动作模式及延后原因（拖拽/菜单/气泡/额度/减少动态效果等）。不包含会话路径、会话ID、正文、账号或额度数值；查看时同时核对时间戳，旧进程退出后文件可能保留。

`dragon_tasks.py` 在单个 Qt 控制进程中共享一个工作线程和状态快照，GUI 每 500ms 取结果；
首次发现新文件可能另需最多约 5 秒，不能承诺即时反馈。
扫描最多四层 `sessions/YYYY/MM/DD`，每次目录发现最多 20,000 项、选择最近更新的 64 个 rollout，
每 5 秒重新发现；能发现原日期目录中的旧会话续接。单文件单次最多读 512KiB、全轮最多 4MiB，
近期文件首次从头分块恢复，历史不活跃文件最多读取 512KiB 尾部；单行缓冲上限 256KiB。已经追平的活跃任务遇到新增长输出积压时保留已确认状态，直到明确完成、中断、失效或过期。拒绝链接文件和不属于当前用户的文件。
缓存与解码仍遵守原有 48MiB QImage / 8MiB QPixmap 预算；新工作线程只读元数据事件，不解码媒体。
这些上限不是总 RSS 或长期 CPU 保证。

## 配置与验证

随包默认和旧配置缺省 `taskFollowingEnabled` 为 `true`。设为 `false` 可禁用；不覆盖现有用户配置：

```json
{ "taskFollowingEnabled": false }
```

它是现有 `companion.json` 的一个字段，不能用以上片段替换完整配置。更改后在用户选择的时机重开桌边小崽。
本轮不自动结束旧实例或安装新版；真实桌面联动待用户验收。

```bash
python3 scripts/test-codex-tasks.py
python3 scripts/test-provider-quota.py
./scripts/test.sh
./scripts/test-multi-pet.sh
```

读取器回归只用临时目录的合成 rollout；真实 Qt 适配器测试使用 offscreen、小型合成动作和临时 HOME。
覆盖单轮次/多轮次、逐轮次序号、冷启动历史抑制、同轮次重复/乱序完成、文件替换/截断、半行/超大行、过期、未知 producer、
历史日期目录恢复、链接拒绝、心跳失效，以及工作开场/回待机、交互延后、多宠共享与减少动态效果。
冻结自检使用合成生命周期事件和真实工作素材，不读用户会话、不查额度、不发起任务。
