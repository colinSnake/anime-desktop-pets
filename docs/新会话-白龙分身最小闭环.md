### 1. 用户已确认的方向

用户希望功能做减法，侧重单功能深度、鲁棒性、可扩展性和资源效率。经评估，决定保留并收敛分身功能，而不是删除：

- 新用户只需从当前龙妹创建同角色、同素材包版本的分身，不新增角色，不扩展为任意角色创建器。
- 沿用现有默认最多同时运行 **3只，含原宠** 的限制；后端已有的清单容量、引用保护与准入规则继续生效，不增加数量设置菜单。
- 分身共享只读素材，不复制媒体；位置、尺寸和活动偏好独立。创建成功后先停止，由用户明确启动。
- 菜单简短易懂，不要求用户手写 JSON，不以多层“从某个实例创建”作为新用户必经流程。
- 本轮只解决创建、首次切换、启停、独立偏好与失败恢复；不增加重命名、批量编辑、热切换素材、新角色或分身专用聊天等功能。
- 保留既有合法实例与第三方包引用，不因收敛新用户入口而静默删数据、禁用旧实例或覆盖其素材包。

### 2. 已知根因与真实状态

用户实测发现默认菜单没有此前声称的“实例管理 → 创建小分身”入口。此前说明不准确，不能继续把默认可用写成已交付。

已查到的原因：

1. `PetInstanceRuntime.init?(runtime:)` 要求 `pet-instances.json` 已存在、可解码且至少有一个启用实例，否则返回 `nil`。
2. `Coordinator.petManagementMenu()` 又要求 `multiPet` 存在且 `isConfigured` 为真，因此默认单宠用户无法进入首次创建。
3. 单宠由 `PetController` 管理，多宠由独立 Qt 控制器管理。**仅放开菜单 guard 或自动写一份示例清单不构成修复**：必须处理原宠归属、偏好与进程互斥。
4. 仓库已有多窗口 Adapter、同包 clone、Swift/Qt IPC、独占锁、独立偏好、共享缓存与回归测试，不要另起一套控制协议或播放器。
5. 真实多宠界面、Space/多屏与长时资源仍未验收；历史离屏通过不能写成本轮桌面通过。

以上来自本会话源码检查；下一会话先复核当前源码，不假定文件或构建未变化。本会话未修复功能、未重启进程。

### 4. 实现要求

#### 入口与操作反馈

- 默认增强单宠用户在宿主**状态栏菜单**能发现“创建小分身…”入口，无需预建 registry。已有多宠仍能管理自己的实例；避免状态栏和桌宠右键重复堆叠入口。
- 先确认创建源的真实素材包身份，不硬编码过时示例版本。未支持的原版或静态降级模式不显示假可用操作，必要时明确说明限制。
- 首次操作说明必要的运行模式切换；取消不改状态。创建中防止重复提交，失败反馈可操作，未确认成功不得显示“已创建”。
- 新分身可在管理菜单看到“已停止”，并可单独启动；不能创建后被待处理的“恢复全部”意外启动。
- 创建与运行名额是两种限制：创建不会占运行名额；运行上限按 starting/running/stopping 合计。到达上限明确提示，不暗中停止另一只。

#### 首次切换与生命周期

- 选择最小且可恢复的交接方式：先确认旧单宠已安全退出并排空，再交给多宠控制器；若现有架构无法安全热交接，可采用明确提示的受控应用重启边界，但不能悄悄重启或长期要求用户改配置文件。
- 只能管理本宿主明确拥有的 helper。独立启动、旧版、归属不明或其他控制器持有锁时，不复用、不强退，不启动竞争控制器；给出清晰提示。
- 原宠与分身归同一 Qt 控制进程，不让单宠/多宠两条路径同时渲染，也不为每只分身启动一个进程。
- 切换失败保留可恢复状态；结果不确定的变更不能自动重放。禁止主线程同步等待退出、Socket、素材扫描或 WebP 解码。
- 显示/隐藏、暂停/恢复、Codex退出、宿主退出与启动恢复都使用一致状态，暂停不能被分身菜单绕过；启动中取消、迟到回调、重复点击与退出竞态须覆盖。

#### 数据与偏好

- 初始化仅针对明确缺失的清单；已有合法清单保留，损坏、空清单、全禁用、符号链接、锁冲突分别处理，不能一律当“没有配置”后覆盖。
- 清单创建/修改必须尊重现有独占锁和引用锁顺序，避免 Swift 与 Python 各自无锁写同一文件。保证原子性、失败恢复和重启一致性。
- 原宠已设置的尺寸、位置与行为开关应在切换后保留。若需要转换，只处理本项目明确归属的偏好白名单，核对 Qt/AppKit 坐标与逻辑角色边界；不扫描或复制其他应用的历史、账号及认证数据。
- 不把真实用户目录作为测试夹具，不删除旧偏好或实例状态目录。分身首次位置应可见且尽量不与原宠完全重叠，受屏幕可用区夹限。

#### 性能和已有行为

- 保留单进程全局 48MiB QImage / 8MiB QPixmap 像素预算、单解码闸门、后台解码与有界预取；不将这些数值宣传为总 RSS 上限。
- 不新增每只独立的任务扫描器，不复制媒体或扩大缓存来掩盖问题；任务跟随与主动额度查询保持现有隐私及授权边界。
- 保持 Qt 屏幕包装器生命周期与 GUI 线程约束。保留任务期间真实拖拽甩动、右键不中断、连续甩动和位置保存不取消弹簧的防回归约定。
