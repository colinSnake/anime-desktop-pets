### 右侧舞台立绘文件

正式使用的本机桌宠素材统一放在 `.local/pets/`。每个角色一份目录，`cover.png` 是工作区封面，`videos/` 放桌面播放的原始视频或归档：

```text
.local/pets/
├── longmei/
│   ├── cover.png
│   └── videos/bailong-desktop-pet-v0.5.1-windows-x64-webm.zip
└── dafeiyu/
    ├── cover.png
    └── videos/idle.webm
```

工作区封面和头像使用用户提供的 2× 透明 PNG：龙妹 512 × 512，鲸鱼妹 444 × 556。两张原图分别保存在同目录的 `cover-original.png`（256 × 256、222 × 278）；仅 `cover.png` 是实际输入。macOS 构建校对龙妹的固定 SHA-256 后复制为 `branding/pet-cover.png`，旧版封面仍可回退。鲸鱼妹封面首次准备从待机 WebM 离线截取 222 × 278 的原图；启动时接受可回退的原尺寸或 444 × 556 的 8 位 RGBA 封面。两张新版都未二次缩放或编码，舞台布局不变。

龙妹的 35 段 WebM 原片保存在一个校验固定哈希的 ZIP，不用手动解压。鲸鱼妹的待机及精选动作使用固定提交、逐文件字节数和 SHA-256 allowlist；准备命令只向现有私有角色目录增量添加缺失动作，保留封面和待机文件。运行时再次校验，只把合格片段复制到本次临时会话；菜单只显示本机已校验动作。已存在的历史构建、对照素材及用户资料不搬迁。`.local/` 被 Git 忽略，不提交或公开分发。

仍用旧布局的本机 checkout 可手动归位：`resources/pet/preview.png` 改放为龙妹的 `cover.png`，把 `.local/downloads/` 或 `.local/animation-sources/` 里的固定 ZIP 放入龙妹的 `videos/`，把旧 `.local/pets/companion/` 的两份文件按上图分别放入鲸鱼妹（内部目录仍为 `dafeiyu`）。在 macOS 上，素材目录（含 `videos/`）和文件须归当前用户所有且为私有权限（分别 `700`／`600`）。启动脚本不会扫描旧位置、覆盖已有素材或自动下载；迁好后运行 `pnpm run dev:desktop --check` 离线核对。

以后再换封面时，先另存并保留透明通道与画布比例。工作区固定封面入口限制为每边 556 px、文件 1 MiB；龙妹只接收已核准的两份文件，鲸鱼妹仍校验上述尺寸和格式。更新素材时需要核对这些限制，不能用任意尺寸的图片覆盖。回退时先另存新版，再恢复 `cover-original.png` 为私有权限（`600`）的 `cover.png`；重新启动开发工作区才会加载变更。

### macOS 本机使用鲸鱼妹

从固定 `dsh-pet` checkout 准备鲸鱼妹素材（需要本机 `ffmpeg`，将参数替换为已有 checkout 路径）。命令会校验固定待机与精选动作；对于已准备的私有目录，仅增量补齐缺少的可选动作，不覆盖封面、待机或任何现有动作：

```bash
node scripts/prepare-local-companion.mjs "/path/to/dsh-pet"
pnpm run dev:desktop --check
```

重新打开新版开发工作区后，点列表中的「鲸鱼妹 → 添加鲸鱼妹」，或从「添加桌宠」选择。添加后保持停止，点击「启动桌宠」才创建透明窗口。鲸鱼妹使用自己的待机、右键分组动作、拖拽悬空循环和重甩「开心跃动」片段；松手物理仍沿用共享二维弹簧。轻放回待机。缺少可选动作时隐藏相应菜单项；跳跃素材缺失时重甩仍只移动窗口并回到待机。系统减少动态效果时不切换动作。与龙妹共用最多三个运行槽。悬停时显示「鲸鱼妹」名字气泡，使用与龙妹相同的已核验本机软糖体，字体不可用时回退系统圆体；不会加载龙妹素材。素材缺失或哈希不匹配时不启动鲸鱼妹，龙妹视频仍单独校验。

命令只读取固定 WebM 并离线截图，不运行原项目，也不读取或迁移账号、配置、聊天或任务；媒体保存到原有 `.local/pets/dafeiyu/` 私有路径，不纳入开发分发产物。普通素材包导入仍只登记。见[素材署名](../licenses/local-companion-media.md)、[实施计划](superpowers/plans/2026-11-19-pet-nook-local-companion.md)及[实际验证记录](实际验证记录.md)。

## 2026-11-18：React 聊天页对齐 macOS

用户最新明确要求聊天按 macOS 设计同步；这是此模块的视觉基准，不扩展为复刻其他旧页或改动已确认的桌宠方案 C。复用旧聊天欢迎标志／文案、用户右侧／助手左侧气泡、仅助手显示 `HH:mm:ss` 本地时间，消息与输入区分别布局；短窗口只滚动消息／输入正文，清空使用原生模态 `dialog.showModal()` 阻止整个工作区后台操作。正文以转义纯文本显示，不执行回复内的 HTML。

输入行为参考 deepseek-ai/deepseek-harness 固定 commit `ca33fd6843b205e279c7ccb6cb73a472c78f5760` 的 `packages/client/ui-conversation/src/client/input/editor/{keymap.ts,submission-policy.ts,ComposerContentEditable.tsx}` 与 `skeleton/InputBar.tsx`。只借鉴交互，独立实现，不复制代码或引入依赖；不移入附件、文件路径、斜杠工具、任务队列或加速投递。原生 textarea 保留选区、纯文本粘贴和撤销，由独立输入策略处理 Enter／Shift+Enter 与 composing／229／compositionend 10ms 防误发窗口，Escape 离开输入焦点。默认2行，最多7行（短窗最多3行，窄且矮窗口最多2行），更多内容在输入框内滚动；超1200字素显示计数并禁止发送，不静默删字。

`ChatWorkspaceController` 位于 App 层，按已保存的新实例 ID 分隔纯内存草稿／对话，切页不销毁；切角色取消当前等待，旧响应不能进入新会话。失败恢复只填空草稿，重试沿用原问题和历史快照，不重复用户消息；取消先作废请求再 abort。清空仅清除当前消息／失败状态，保留草稿，等待时不可清空。历史最多12条／6000字素，最新两条完整消息保留例外；请求历史逐条截至1200后再按预算裁剪。

## 界面结构

「桌边小崽」管理界面使用同一个可调整大小的窗口：透明标题栏与工具栏共享主题底色，工具栏下沿有细分隔线；下方为固定200pt侧栏与右侧内容区，侧栏边界叠加低对比度主题分隔线且不拦截鼠标事件。浅色模式下工具栏和内容画布纯白、侧栏浅灰，深色模式使用协调的深色画布，不叠加多层近似灰背景。工具栏左侧先显示放大的应用图标，再显示品牌文案；外观按钮略缩小并置于右侧。侧栏按“梦境区”（桌宠、聊天、身份、记忆、能力）、“工作区”（模型管理、语音互动、直播管理）、“系统区”（高级）顺序分组；角色页面直接切换，不嵌套第二条导航。右侧页面只保留主标题，不再显示标题下的副描述。目标页入口已移除，现有目标资料和聊天引用逻辑保留。外观图标按“跟随系统、深色、浅色”循环，选择持久化且即时生效；跟随系统使用半圆条纹外观符号，系统外观改变时会重新应用表面与文字颜色。界面以黑白灰为主，侧栏选中项使用低饱和青紫白品牌渐变，浅深模式分别调整底色透明度与前景字色。

模型管理页将服务商、Base URL、模型名称与 API Key 表单放在“服务连接”分组中，另以“凭证与费用”分组说明 Keychain 保存边界及测试请求可能产生费用；状态反馈和保存、连接测试、删除 Key 操作保持可见。当前模型协议实际可配置项只有服务商、Base URL、模型名称和 API Key，不展示尚未实现的温度、采样或超时旋钮。打开页面时只进行不弹认证界面的钥匙串项目存在性检查，不读取 Key 明文；真实在线请求仍按需从钥匙串读取。API Key 输入使用安全文本框并以圆点回显。单行字段使用38pt控件高度、原生圆角边框和垂直居中；卡片内部使用明确的内容容器约束，避免卡片撑满后表单仍缩在一侧。

“语音互动”提供本机麦克风选择/检测、语音聊天、参考音色、准确转写、回复显示与朗读设置。“直播管理”分为“接入状态”和“房间配置”：当前直播配置仅有平台与房间标识，平台授权、直播连接、弹幕读取和互动发送尚未接入；保存不会连接直播间，也不会代替平台 connector。语音与直播页面各自独立滚动，共享设置存储和固定保存/状态页脚。字段采用统一标签行、充足高度和圆角输入表面；自定义滚动文档使用顶部原点，确保初次打开从标题开始。页面外层滚动条采用 overlay/mini 样式；输入框内部按下述独立策略隐藏。

角色页复用 CharacterUI 工作区及其本地聊天、身份和记忆安全门禁。身份页的保存按钮位于标题行最右侧，状态与错误在标题下完整换行显示。主页面仅保留名称、性格、表达方式、与你的关系四项，一项一行，全部使用同款多行编辑框，不再用两列网格或单行名称框。身份定位、背景、核心价值、愿望与方向、知识范围和行为边界移入默认收起的“基础设定”，只读查看；新资料沿用内置默认，旧自定义资料不自动覆盖，空白项仍需用户预览并确认补入。字段提示副标题保持移除；本地 Markdown 格式和分享门禁不变。身份和聊天输入框复用 `CharacterInputSurface` 的青紫白渐变聚焦描边、灰色失焦描边及紫色光标；`Esc` 或离开页面清除对应编辑焦点。名称虽使用多行控件，保存值仍须为非空、最多80字且无内部换行的单个名称，避免破坏 Markdown 标题；失败时明确提示并保留原文件。记忆页分为“个人记忆/角色知识”分段入口，个人记忆只选择事实、偏好或经历类别，角色知识提供单条添加和批量导入；条目按“待确认/已确认”分组并显示数量。正文复用身份页三行编辑器，知识来源/引用/版本采用统一34pt控件；有效期、分享权限可编辑，内容修改显式保存，候选需保存后再确认。创建时间、类别和审核状态作为只读管理信息。聊天状态与重试提示固定在输入区上方而不是覆盖消息。能力页使用统一状态卡片，便于扫描可用、按需和待配置能力。角色卡片使用动态系统背景/分隔色，不加装饰性阴影。窗口关闭时取消录音并取消当前语音聊天轮次，重新打开时复用已创建的模块控制器。工作区卡片通过独立内容容器约束，不依赖自身约束；模型/语音滚动文档从顶部开始。

正常启动（`--launch`、`--watch`）默认不创建或显示管理窗口，避免遮挡启动动画和 Codex；需要管理时，左键点击 macOS 顶部菜单栏图标打开窗口。桌宠控制标题不带图标，字号与“我的桌宠”一致；运行状态以括号显示，服务连接状态在右上角显示。显示桌宠和暂停联动使用较小的原生 Switch 并靠齐最右侧，开启时使用黑色强调色；不再显示“桌宠操作”分组标题。实例列表默认展示，不再套“实例管理”折叠块；数量与标题同行并以括号显示，字号对齐控制状态。“添加桌宠”按钮仅显示文字，不显示 plus 图标。面板以紧凑卡片展示实例封面，名称和状态分别叠在封面左上和右上角；原实例卡片提供“停止/启动实例”和“创建分身”，分身卡片则显示“停止/启动实例”和“删除实例”。卡片采用160–220pt自适应宽度、124pt封面、26pt纯文字操作按钮；卡片名称、状态、错误及操作文字均较此前缩小，卡片按钮不带图标。删除需先停止分身并确认，删除仅从实例清单移除，保留素材包与独立状态目录；最后一个实例和原始龙妹受保护。卡片优先读取素材目录内的 `workspace-cover.png`，否则从默认动画异步截取首帧并按素材包缓存，缺少素材时使用静态预览。新增素材包通过工作区内附属于主窗口的“添加桌宠”sheet 导入，右上角 X 可通过结束父窗口 sheet 关闭；点击主工作区 sheet 外的空白也可关闭，关闭不受扫描或添加任务进行中限制；候选列表外围不加框，每个桌宠以固定140pt宽、封面120pt高的卡片显示，网格随可用宽度换列；名称和动作数分别位于封面左上和右上，版本号位于封面右下；不显示“内置桌宠”标识或封面下方名称行，不直接展示素材路径。卡片内仅保留底部“查看目录”按钮，在 Finder 打开素材目录；路径本身只用于搜索、提示和目录操作。工具栏将“选择素材目录”“刷新”、搜索框和“添加”放在同一行，移除“全选”；上述三个按钮及卡片底部“查看目录”统一使用26pt紧凑按钮样式，均为纯文字、不带左侧图标。候选名称左侧不再显示爪印或勾选图标，点击封面区域选择，仍以卡片底色、描边和辅助功能选中状态表达。弹窗仅保留“添加桌宠”标题，不再显示说明副标题；添加后默认保持停止。退出时 Coordinator 在停止运行时和异步等待之前先结束添加桌宠 sheet，避免附属窗口阻塞 AppKit 关闭主窗口。筛选仅控制可见项，已选素材按来源路径保留，搜索隐藏的选择不会丢失；状态计数包含隐藏的已选项，保留 ⌘/⇧ 多选，批量添加仍最多16只。通用动作按钮禁用时保持原文字颜色并整体降至60%不透明度。卡片视图与主题选中样式位于独立组件文件。最多同时运行3只桌宠且包含原宠，这是控制器的保守默认运行上限；实例清单最多登记32只，二者不是同一个限制。状态随运行时事件刷新，过渡阶段禁用重复操作；桌宠总开关仍启动全部已启用实例或停止活动实例。状态栏图标左键打开工作区，右键菜单只保留“退出”；每个实例仍由 Coordinator 及既有控制协议独立管理。

## 页面底色与内容层次

`CharacterUI/ManagementSurfacePalette.swift` 提供跨页面共享的动态 `canvas`、`card`、`input` 和 `border` 语义色。宿主通过 `WorkspacePalette` 引用，角色模块通过 `CharacterUIStyle` 引用，依赖仍由宿主指向现有UI模块；不增加新模块、不让角色UI依赖宿主。浅色画布明确使用白色，而非macOS会呈灰色的 `windowBackgroundColor`；深色使用接近黑色的统一画布。`CompanionWorkspaceWindow` 的原生背景与SwiftUI根视图、工具栏、内容容器使用同一动态色，透明标题栏延续该底色。

桌宠、模型、语音、直播和高级页面根部都铺满画布；聊天、身份、记忆、能力及保留的目标资料页由角色工作区统一提供画布。添加弹窗也采用同样的原生/SwiftUI底色。设置卡片、记忆块、能力/目标卡片和聊天固定输入区使用稍有对比度的内容表面，多行输入使用独立输入表面；身份页统一采用单列多行编辑框并隐藏滚动底色，不因宽屏扩展成多列。文字、错误/状态色和既有字段绑定不变。

## 聊天滚动与模型请求链路（2026-11-15）

聊天消息使用独立稳定 UUID；裁剪正文、裁剪有界历史及重建 session 均保留标识。列表不再按数组下标复用消息身份，自动滚动监听最后一条消息标识而不是条数，因此在12条上限或6,000字符上限导致消息数量不变时，仍能跟随新增消息。无标识的旧 Codable 消息可解码并生成本机标识；旧消息缺少时间仍保持未知。UUID 与回复时间只作本机消息元数据，不进入服务端 `role`/`content` 字段。

实际调用链为 `CharacterChatView → CharacterWorkspaceModel → Coordinator.replyToCharacterChat`：先处理显式记忆命令和本机确定性问答；需要在线回答时，才由 `CharacterChatProvider` 读取非敏感模型设置与 macOS 钥匙串中的 Key，构建已授权的身份、相关记忆/知识/目标上下文，再调用 `ModelProviderClient`。客户端从本机通过 URLSession 请求所配置 Base URL 的 `/chat/completions`（地址已含该后缀时不重复追加）。填写官方 API 地址就是请求对应官方服务，填写第三方中转地址就是请求该中转；仓库没有额外自建聊天代理，也不借用官方 Codex 的会话或订阅额度。普通在线聊天会发送当前文字与有界历史，长期资料仅按已有分享开关与审核规则挑选加入上下文，不把界面删除“临时聊天”提示理解为自动分享授权。模型菜单是手工保存的同服务模型列表，不联网发现、不证明账号权限。链路核对只读源码，不读取用户当前服务配置或 API Key、不调用真实模型。

## 2026-11-15：聊天可靠性与模型列表

- **文字与语音回复分开处理。** 文字聊天使用独立的完整回答提示、较大的回复预算与更长等待时间；语音仍使用短句预算。聊天显示保留服务端返回的完整文字，不再统一 `prefix(100)` 截断；若服务端以长度上限结束，界面会明确提示可继续追问。
- **聊天请求可停止、失败可重试。** 发送中显示原生停止按钮；取消先使当前尝试失效，再取消任务，因此服务端迟到的回复不会写入当前会话或覆盖后续请求。失败/取消保留原问题，恢复输入只在草稿为空时进行；重试不重复用户消息，清空本轮聊天不删除草稿、记忆或目标。
- **模型列表支持显式刷新。** 打开聊天模型气泡只读取已保存的模型，不自动联网。用户点击刷新后才对配置服务的 `/models` 发起 GET；服务端返回的模型与手工列表合并，默认模型不变，最多保留32个，失败时保留手工列表。刷新结果会校验服务配置未发生变化并拒绝重定向继续转发凭证。离线预览不读取钥匙串、不联网。
- **请求边界。** 在线文字聊天继续发送当前问题、有界历史和按分享开关选入的角色资料；消息时间与 UUID 只属本机 UI 元数据，不进入 API 的 `role/content`。
