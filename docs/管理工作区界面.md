# 桌边小崽管理工作区

更新：2026-11-13。

## SwiftUI 迁移状态（2026-11-12）

工作区主窗口外壳/工具栏/侧栏/导航、桌宠控制页、添加桌宠 sheet、模型、语音/直播、高级操作和角色聊天/身份/记忆/能力页均由 SwiftUI 呈现。模型、语音与桌宠导入状态仍留在各自控制器/模型；Coordinator 通过窄动作闭包提供运行时操作。角色 UI 保持独立 `CharacterUI` 模块。没有管理页面继续用 AppKit 手工拼装表单、按钮行、候选表格或侧栏布局。

AppKit 保留在系统集成边界：应用与状态栏生命周期、`NSWindowController` 窗口所有权/标题栏/关闭通知、嵌入既有页面控制器的 `NSViewControllerRepresentable` hosting bridge、系统文件面板、Finder、麦克风/权限、辅助功能和启动动画/桌宠运行时窗口。该桥接用于复用领域控制器，不承担页面布局。最低目标仍为 macOS 13、Swift 5.9；当前页面使用的 `ViewThatFits`、`onChange(of:)` 等 API 满足目标版本，不依赖 macOS 14 专属控件。

本轮完成自动化 Swift 测试、项目源码检查和 Debug/Release 构建；**未打开或启动真实管理窗口**。自动化验证不覆盖 SwiftUI 实际绘制、焦点/键盘行为、sheet 空白点击事件分发、系统文件面板和 Finder 操作，也不替代浅色/深色实机视觉验收。语音录音、钥匙串和在线模型请求未触发。

## 界面结构

「桌边小崽」管理界面使用同一个可调整大小的窗口：透明标题栏与工具栏共享主题底色，工具栏下沿有细分隔线；下方为固定200pt侧栏与右侧内容区，侧栏边界叠加低对比度主题分隔线且不拦截鼠标事件。浅色模式下工具栏和内容画布纯白、侧栏浅灰，深色模式使用协调的深色画布，不叠加多层近似灰背景。工具栏左侧先显示放大的应用图标，再显示品牌文案；外观按钮略缩小并置于右侧。侧栏按“梦境区”（桌宠、聊天、身份、记忆、能力）、“工作区”（模型管理、语音互动、直播管理）、“系统区”（高级）顺序分组；角色页面直接切换，不嵌套第二条导航。右侧页面只保留主标题，不再显示标题下的副描述。目标页入口已移除，现有目标资料和聊天引用逻辑保留。外观图标按“跟随系统、深色、浅色”循环，选择持久化且即时生效；跟随系统使用半圆条纹外观符号，系统外观改变时会重新应用表面与文字颜色。界面以黑白灰为主，仅侧栏当前选中项使用紫色渐变。

模型管理页将服务商、Base URL、模型名称与 API Key 表单放在“服务连接”分组中，另以“凭证与费用”分组说明 Keychain 保存边界及测试请求可能产生费用；状态反馈和保存、连接测试、删除 Key 操作保持可见。当前模型协议实际可配置项只有服务商、Base URL、模型名称和 API Key，不展示尚未实现的温度、采样或超时旋钮。打开页面时只进行不弹认证界面的钥匙串项目存在性检查，不读取 Key 明文；真实在线请求仍按需从钥匙串读取。API Key 输入使用安全文本框并以圆点回显。单行字段使用38pt控件高度、原生圆角边框和垂直居中；卡片内部使用明确的内容容器约束，避免卡片撑满后表单仍缩在一侧。

“语音互动”提供本机麦克风选择/检测、语音聊天、参考音色、准确转写、回复显示与朗读设置。“直播管理”分为“接入状态”和“房间配置”：当前直播配置仅有平台与房间标识，平台授权、直播连接、弹幕读取和互动发送尚未接入；保存不会连接直播间，也不会代替平台 connector。语音与直播页面各自独立滚动，共享设置存储和固定保存/状态页脚。字段采用统一标签行、充足高度和圆角输入表面；自定义滚动文档使用顶部原点，确保初次打开从标题开始。所有工作区滚动条采用 overlay/mini 样式；身份页保留 SwiftUI grouped 表单卡片并增加20pt水平、12pt垂直页面内边距。

角色页复用 CharacterUI 工作区及其本地聊天、身份和记忆安全门禁。身份页采用分组表单、字段标题和独立多行编辑区；记忆录入采用独立多行编辑区、来源字段和审核队列，聊天状态与重试提示固定在输入区上方而不是覆盖消息。能力页使用统一状态卡片，便于扫描可用、按需和待配置能力。角色卡片使用动态系统背景/分隔色，不加装饰性阴影。窗口关闭时取消录音并取消当前语音聊天轮次，重新打开时复用已创建的模块控制器。工作区卡片通过独立内容容器约束，不依赖自身约束；模型/语音滚动文档从顶部开始。

正常启动（`--launch`、`--watch`）默认不创建或显示管理窗口，避免遮挡启动动画和 Codex；需要管理时，左键点击 macOS 顶部菜单栏图标打开窗口。桌宠控制标题不带图标，字号与“我的桌宠”一致；运行状态以括号显示，服务连接状态在右上角显示。显示桌宠和暂停联动使用较小的原生 Switch 并靠齐最右侧，开启时使用黑色强调色；不再显示“桌宠操作”分组标题。实例列表默认展示，不再套“实例管理”折叠块；数量与标题同行并以括号显示，字号对齐控制状态。面板以紧凑卡片展示实例封面，名称和状态分别叠在封面左上和右上角；原实例卡片提供“停止/启动实例”和“创建分身”，分身卡片则显示“停止/启动实例”和“删除实例”。删除需先停止分身并确认，删除仅从实例清单移除，保留素材包与独立状态目录；最后一个实例和原始龙妹受保护。卡片优先读取素材目录内的 `workspace-cover.png`，否则从默认动画异步截取首帧并按素材包缓存，缺少素材时使用静态预览。新增素材包通过工作区内附属于主窗口的“添加桌宠”sheet 导入，右上角 X 可通过结束父窗口 sheet 关闭；点击主工作区 sheet 外的空白也可关闭，关闭不受扫描或添加任务进行中限制；候选列表外围不加框，每个桌宠以固定160pt宽的封面卡片显示，网格随可用宽度换列；版本号/内置标识和动作数分别叠放在封面左上和右上角，名称在封面下居中显示，不直接展示素材路径。卡片内仅保留底部“查看目录”按钮，在 Finder 打开素材目录；路径本身只用于搜索、提示和目录操作。工具栏将“选择素材目录”“刷新”、搜索框和“添加”放在同一行，移除“全选”；上述三个按钮及卡片底部“查看目录”统一使用26pt紧凑按钮样式，均为纯文字、不带左侧图标。候选名称左侧不再显示爪印或勾选图标，点击封面区域选择，仍以卡片底色、描边和辅助功能选中状态表达。弹窗仅保留“添加桌宠”标题，不再显示说明副标题；添加后默认保持停止。筛选仅控制可见项，已选素材按来源路径保留，搜索隐藏的选择不会丢失；状态计数包含隐藏的已选项，保留 ⌘/⇧ 多选，批量添加仍最多16只。通用动作按钮禁用时保持原文字颜色并整体降至60%不透明度。卡片视图与主题选中样式位于独立组件文件。最多同时运行3只桌宠且包含原宠，这是控制器的保守默认运行上限；实例清单最多登记32只，二者不是同一个限制。状态随运行时事件刷新，过渡阶段禁用重复操作；桌宠总开关仍启动全部已启用实例或停止活动实例。状态栏图标左键打开工作区，右键菜单只保留“退出”；每个实例仍由 Coordinator 及既有控制协议独立管理。

当前主要入口为 `CompanionWorkspaceWindow`。视觉使用原生窗口与 SF Symbols，不更改动画桌宠、Qt 菜单或气泡样式。

工作区实现按职责拆为 `WorkspaceSection`、`WorkspaceShellView`、`WorkspaceNavigation`、`WorkspaceControls`、`WorkspacePetsPageController`、`WorkspaceActionPageController` 和对应页面/行/实例卡片。共享工作区标题、分组卡片、开关和主操作按钮采用 SwiftUI 组件；角色模块保有模块内的语义颜色和表单组件，避免反向依赖宿主。窗口控制器只编排窗口、导航和页面生命周期。业务状态与副作用留在所属模型/控制器，通过闭包交给页面，不在通用组件中直接访问 Coordinator。

## 页面底色与内容层次

`CharacterUI/ManagementSurfacePalette.swift` 提供跨页面共享的动态 `canvas`、`card`、`input` 和 `border` 语义色。宿主通过 `WorkspacePalette` 引用，角色模块通过 `CharacterUIStyle` 引用，依赖仍由宿主指向现有UI模块；不增加新模块、不让角色UI依赖宿主。浅色画布明确使用白色，而非macOS会呈灰色的 `windowBackgroundColor`；深色使用接近黑色的统一画布。`CompanionWorkspaceWindow` 的原生背景与SwiftUI根视图、工具栏、内容容器使用同一动态色，透明标题栏延续该底色。

桌宠、模型、语音、直播和高级页面根部都铺满画布；聊天、身份、记忆、能力及保留的目标资料页由角色工作区统一提供画布。添加弹窗也采用同样的原生/SwiftUI底色。设置卡片、记忆块、能力/目标卡片和聊天固定输入区使用稍有对比度的内容表面，多行输入使用独立输入表面；身份页保留系统分组表单，隐藏滚动底色，保持原生分组层次。文字、错误/状态色和既有字段绑定不变。

“我的桌宠”实例卡片的封面使用淡冷灰表面，底部操作区沿用画布色，细描边在内侧绘制。深色下封面比画布略亮，输入/中性操作有独立表面；运行中主按钮随主题反转文字与填充颜色，禁用/按下状态保持可辨。缺少封面的占位与封面图片均在封面区居中，实例启停、创建、删除和确认流程不变。

## 紧凑按钮与搜索框

`WorkspaceControlStyle` 定义26pt紧凑高度、34pt普通高度和7pt圆角。添加弹窗的选择目录、刷新、添加及查看目录按钮均使用固定26pt外框；`WorkspaceSearchField` 使用原生SwiftUI TextField和相同高度，取消系统roundedBorder的固有高度差，保留文字绑定、键盘焦点、辅助功能标签和忙碌禁用。搜索使用12pt字体，并通过fixedSize只固定文字的自然高度，再由26pt外框居中；避免本机11pt原生文本在未编辑时13pt、编辑时14pt造成的1pt跳动，不对焦点状态施加不同偏移。`WorkspaceSearchFieldTests` 在隐藏窗口中验证浅/深色、空值/有值、焦点进入/退出的原生NSTextField/NSTextView行框与光标矩形、真实编辑器写入Binding及禁用状态。搜索聚焦时使用强调色向内描边，普通状态与按钮共享边框颜色。

普通控件使用1pt向内描边：浅色为22%黑色、深色为30%白色，避免系统separator叠加低透明度后过浅。突出“添加”保留实心主操作样式，禁用状态仍整体60%不透明度。桌宠页“添加桌宠”保留加号与动作调用，复用同一紧凑按钮样式；素材目录按钮和搜索框没有引入额外图标。样式仅负责视觉，扫描/搜索/导入及实例行为继续由所属控制器管理。

## 添加候选封面流程

扫描返回候选后，`PetManagerWindow` 独立启动封面准备任务；后台 `PetCoverLoader` actor 串行读取现成 `workspace-cover.png`，缺失时从默认动画截取第0帧，候选缩略图最大256px，实例卡片保留512px。目录包读取 `manifest.json`，内置素材读取 `素材清单.json`；`.petpack` 使用 macOS 自带 `unzip -p` 只读清单与默认素材条目，归档上限256MiB，清单/素材条目分别限制1MiB/64MiB和每次读取5秒截止时间，不展开归档、不登记实例、不写素材目录。封面按来源和尺寸保存在有界内存缓存中；刷新扫描可重试此前缺失的封面。

卡片内容先按10pt内圆角裁切，再固定预留2pt空间，外层以12pt圆角绘制底色与向内的 `strokeBorder`；封面、材质角标和按钮不占用描边像素。选中描边由1.5pt调整为2pt，未选中由0.7pt调整为1pt，避免1倍渲染下小数线宽产生半透明边缘；装饰描边关闭命中测试。选中/取消选择使用同一内容内缩量，内部布局不跳动。滚动内容四周仍保留2pt间距，160pt是卡片整体宽度，内部预留空间不增加卡片宽度。

`PetManagerBorderTests` 在实际 `PetManagerWindow` 的隐藏NSWindow/NSHostingController/ScrollView/LazyVGrid中注入18个合成候选与内存封面，不调用open、不显示窗口；覆盖浅/深色、580/700/900pt窗口、搜索后单卡/完整网格及滚动一行后的首列，逐边采样完整2pt描边。单卡ImageRenderer回归同时覆盖1倍与2倍渲染。此前单卡2倍测试只证明向内描边没有越界，未覆盖完整容器或1倍下线宽；上述离屏验证仍不等同于真实sheet桌面合成验收。

封面状态独立于扫描/导入的 busy 状态：抽帧时可搜索和选择，不延迟添加；失败显示“封面暂不可用”，不阻止添加。重新扫描取消旧准备队列，并用扫描代次防止旧结果覆盖新卡片；卡片不显示实例运行状态或启停/分身操作。解码失败不代替正式导入校验，也不自动导入源目录。

## 离线预览

`scripts/preview-character.sh` 使用 `/tmp` 下独立 SwiftPM scratch 和临时数据目录打开完整工作区，并从资源目录加载应用正式图标。模型页的保存、Keychain 删除和连接测试均禁用；语音页的麦克风、演示、语音保存和直播配置保存均禁用；桌宠控制操作不会启动或停止实例；角色聊天保留离线能力，需在线回答的问题会拒绝执行。预览不启动桌宠 helper、不访问在线模型。预览模式中的“添加桌宠”使用合成候选和内存模拟导入，不读取、复制或登记真实素材；扫描/准备失败状态由既有模型测试覆盖。

## 验收边界

Swift 全量测试及本地源码检查只验证构建、业务状态和静态边界，不等同于窗口视觉验收。需经用户明确要求后启动 `scripts/preview-character.sh`，检查顶部工具栏、标准与窄窗口、侧栏固定宽度、三组导航与页面顺序、服务状态指示、开关对齐、滚动、键盘焦点、主题图标循环/重启持久化、系统外观跟随、卡片圆角和关闭时录音清理。合成素材预览可检查添加页的搜索、多选、加载/禁用和模拟导入；真实素材扫描/导入、sheet 外点击、系统文件面板、Finder、状态栏左右键分流、退出菜单以及真实桌宠服务交互仍需在明确隔离条件下人工验收。
