# 宠物库与素材包（第一阶段）

更新：2026-11-01。实际工程为 `dragon-codex-companion`，不是参考目录 `codex-pet`。
本阶段交付离线盘点、导入底座和由宿主菜单启动的独立素材库窗口；素材包支持校验、预览、删除和停止态切换。删除/切换都以锁保护 profile 实例引用。运行中热切换未实现。
当前伴侣为 0.6.9，增强 helper build 23 / `dragon.20`。

2026-11-01 格式完整性更新：`.petpack` v1 的 `movement` 分组现在必须携带完整且可运行的移动时段与朝向；非 `movement` 分组不得声明移动参数。此门禁用于防止素材包看似导入成功、实际却无法被移动运行时消费，不代表素材包已可激活。

## 1. 已有资源与使用原则

- 原始 Mac 包、原版 App、v0.5.1 扩展归档均已在本工程 `.local/`，无需再次下载。
- 增强资源位于 `.local/pet-build/source/outputs/白龙桌宠素材/`。
- 共 35 个有效动作：6 待机、15 互动、5 工作、3 特殊、6 移动；原 work 数组的空占位不是动作。
- 当前画布全部为 720×720，总 WebP 文件大小 1,343,901,152 字节（约 1.25GiB）。
  不能沿用过小的“几十 MB 包体”假设；盘点不再复制媒体，后续多实例也应复用文件。
- 基础与扩展素材保持只读。现有菜单、气泡、自主行为、后台顺序解码与呈现时钟不替换。
- 这是桌宠画布尺寸，**不能用于判断启动 MP4 的分辨率或主窗口是否真正就绪**。
- 上游授权说明仅用于追溯；有素材不代表本项目取得公开再分发权利。

## 2. 命令入口

在工程根目录使用已有专用 Python（含 Pillow），不需要新装依赖：

```bash
# 逐个完整解码35动作，核对时长/哈希/扩展来源，写新报告；已有报告拒绝覆盖。
.local/pet-build/venv/bin/python scripts/pet-library.py audit-bailong \
  --report .local/pet-library/bailong-catalog-new.json

# 指定独立测试库，不猜测或修改上游数据目录。
.local/pet-build/venv/bin/python scripts/pet-library.py \
  --library .local/pet-library/test-library import /absolute/path/example.petpack

# 仅列出清单，不解码、不激活；空库不会被自动创建。
.local/pet-build/venv/bin/python scripts/pet-library.py \
  --library .local/pet-library/test-library list

# 所有测试仅使用临时目录、合成包及合成WebP。
.local/pet-build/venv/bin/python scripts/test-pet-library.py
```

盘点报告包含归一化 `manifest`、原始文件相对路径、基础及扩展来源声明原文的路径和 SHA-256。
报告本身不是 ZIP 包、不是素材安装，也不包含账号或对话信息。不会自动打出另一份约1.3GB白龙归档。
普通用户可通过伴侣状态栏菜单「打开宠物素材库…」打开本地素材库；窗口不会启动、停止或切换运行中的桌宠。

## 3.1 独立素材库窗口（当前已实现）

使用专用 Python 环境打开本地素材库：

```bash
.local/pet-build/venv/bin/python scripts/pet-library-ui.py \
  /absolute/path/to/library
```

窗口支持：

- 后台导入 `.petpack`，导入失败时保持素材库原状；
- 查看已导入包的名称、版本和动作数量；
- 对选中包重新执行完整清单、文件哈希和动画解码校验；
- 选中详情使用精确 `id + version` 解析器，在素材库锁内确认路径身份并校验完整包内容，不采用隐式“最新版本”；
- 逐帧预览动作 WebP；重复打开预览时只保留一个预览窗口；
- 明确显示“已导入不代表已激活”，不会修改运行实例。

正式构建把窗口打包在主 App 的 `Contents/Helpers/DragonPetLibrary.app`，运行时无需依赖仓库 Python 虚拟环境。
默认库目录为 `~/Library/Application Support/DragonCodexCompanion/PetLibrary`，目录权限为用户私有。
窗口支持删除未被实例引用的素材包版本。删除在 profile 引用锁与素材库锁保护下执行；清单缺失、损坏、包路径为符号链接或任一实例（包括已停止实例）仍引用该 id/version 时均拒绝删除。删除会先将包原子移出可见包目录，再清理隐藏临时目录。
窗口支持按实例和精确包版本执行停止态切换；运行中的实例由控制器拒绝，需先停止。切换成功只代表引用已原子保存，将在下次启动加载；导入仍不代表自动激活。0.6.10 / helper build 24 已为同 Qt 控制进程的白龙实例加入共享48MiB QImage / 8MiB QPixmap预算与单解码闸门；不是RSS总上限，长时资源仍待验收。
关闭窗口不会退出桌宠；测试使用临时目录和合成素材，不读取账号、聊天或额度数据。

## 3.2 播放器接入与切换边界

实现状态：**停止态播放器接入已实现，第三方包桌面验收待完成**。helper 根据实例 `package.id + version` 解析素材库内的包；待机、互动、工作和移动组映射到现有播放器动作池，待机默认项遵循 `defaultAction`，每个动作的 WebP 路径锚定至该包。缺失的非内置包会使实例启动失败，不静默回退。`special` 组目前不绑定拖拽/落地/额度钩子。

- **实例身份**：每个窗口按不可变定义读取精确 `package.id + package.version`，不选 latest、不按目录顺序回退。创建播放器前使用素材库解析器校验该版本；动作媒体引用必须源自已验证 manifest 中的相对 `assets/*.webp` 路径。
- **动作模型**：保留 `id`、`name`、`group`、`file`、`durationMs`、`frameCount` 和 `presentation.scale/offset/anchor/loop`。不复制约 1.3GiB 白龙媒体，也不改写白龙内置清单。
- **调度语义**：`idle` 进入自主待机池；`interaction` 进入手动表演及既有自主展示池；`work` 仅在任务状态参与工作调度；`special` 由显式事件调用；`movement` 只由移动/拖拽控制器调用，并使用 `startMs/stopMs/facing` 驱动位移，不得当作普通循环待机。默认动作必须是有效 idle；缺少的可选组为空池。
- **媒体与缓存**：保持后台 WebP 顺序解码、首帧就绪后启动时钟、过期 generation 丢弃、像素预算及 Qt GUI 线程约束。缓存身份包含规范化媒体路径、尺寸和帧索引，避免不同包/版本按相同动作 ID 串帧。同包实例可共享只读解码结果，但动作、位置、偏好和调度状态独立。
- **停止态切换事务**：经控制器确认实例停止后，先在素材库锁内精确解析并验证目标版本，再按统一锁顺序取得 profile 引用锁，重读 registry、构造候选 registry 并原子写入。仅持久化成功后更新控制器内存快照。任何失败都保留旧引用；成功只承诺下次启动使用新包。
- **锁顺序与删除**：现有删除操作的顺序是素材库锁、再 profile 引用锁；registry 单独写入只取得 profile 引用锁。未来同时需要两把锁的切换操作必须沿用“素材库锁 → profile 引用锁”，并使用可在已持有引用锁时执行的原子写入路径，不能嵌套调用当前会再次取锁的 `InstanceStore.save()`。引用重检、目标包确认和 registry 替换置于同一临界区。停止实例引用也保护对应包版本。
- **运行中切换**：另行实现候选播放器、首帧就绪确认、提交与回滚。失败时停止候选并保留旧窗口/引用；不得先改 registry 再加载，也不得复用普通偏好更新接口。

已自动覆盖控制器层的精确包校验/缺失版本/符号链接、运行实例拒绝切换、磁盘与内存同步、切换失败保持旧引用、IPC 请求校验；素材解析器覆盖包内容哈希与完整解码。尚未覆盖或完成的验收包括：第三方包真实窗口首帧/动画体验、切换/删除压力并发、跨包缓存长时间运行观察，以及专用 `special` 事件语义。运行中候选播放器切换仍属后续功能。

## 3. `.petpack` v1 合约

ZIP 容器，UTF-8 JSON 清单。只接受文件条目，不需要显式目录条目：

```text
manifest.json
assets/idle.webp
assets/drag.webp
...
notices/source.txt
...
```

必需清单字段：

| 字段 | 含义 |
| --- | --- |
| `schemaVersion` | 整数 `1`；未知版本拒绝 |
| `id` / `version` / `name` | 稳定包 ID、独立版本、显示名；同 ID/version 不覆盖 |
| `runtime` | 仅 `webp-v1`；包不能提供脚本、插件、可执行文件或安装钩子 |
| `sources[]` | 每项含 repository、release、archiveSha256；记录来源，不自动联网校验 |
| `rights` | scope 仅 `private-local-only`、明确 statement、非空 notices 路径列表 |
| `defaultAction` | 必须指向一个待机动作 |
| `actions[]` | id、可选 name、group、file、sizeBytes、sha256、width、height、frameCount、durationMs |
| `actions[].presentation` | 可选 scale、offset、bottom-center anchor、loop；保留当前素材锚点 |
| `actions[].movement` | `movement` 分组必填，且只能含 `startMs`、`stopMs`、`facing`；时段须满足 `0 ≤ startMs < stopMs ≤ durationMs`，朝向为 `left` 或 `right`。其他分组禁止此字段 |

group 为 idle / interaction / work / special / movement。不强制第三方角色拥有35动作，默认待机必需。
当前解码器支持有正帧时长的动画 WebP，不接受伪装后缀的 PNG、WebM、静态无时长素材。
来源、声明与哈希由制包者提供，**不是签名或可信作者认证**；人工权利审核依然必要。
动画文本只作为数据，不会读取路径执行或发起模型请求。

兼容说明：素材运行时尚未接入激活，因此在首次激活前收紧 v1 校验。此前已导入且 `movement` 动作缺少完整元数据的包，在重新验证时会被拒绝；需由制包方补齐有效字段后重新导入。非移动动作及仅包含待机/互动/工作/特殊动作的合法包不受此约束影响。

## 4. 安全与资源预算

- 归档≤2GiB，解压总量≤2GiB，单动作文件≤128MiB，单元数据文件≤1MiB。
- 最多512个文件条目、128个动作、每动作1000帧、4096×4096画布、120秒。
- 限制单动作与整包的累计解码像素工作量；逐帧加载，不将整动画缓存到内存。
- 归档压缩比≤200，压缩算法仅 stored/deflate；加密包、链接、设备、可执行位均拒绝。
- 禁止绝对路径、`..`、反斜杠、冒号、控制字符、重复路径、大小写冲突与非NFC名称。
- 先审查全部 ZIP 中央目录，后按字节预算流式写入；不调用 `extractall`。
- 清单限定实际文件集合；缺失/未声明文件、重复JSON键、未知schema、错误大小/哈希均失败。
- 用 Pillow 完整顺序解码，检查真实格式、尺寸、帧数、非均匀总时长与清单一致。
- 库写入通过本地独占文件锁串行化；同文件系统暂存，全部通过后 rename 原子发布。
- 异常删除本次暂存；不删除旧版本、不修改运行实例、不自动激活导入结果。
- 现有 conversations.json、preferences.ini、认证与 Codex 配置不读取、不迁移、不改写。

限制说明：这些是格式/预算与正常进程失败回滚，不是第三方解码器沙箱或断电持久性保证。
强制结束可能留下隐藏 `.import-*` 暂存（不会被列表当作已安装包）；自动清理与空间管理后续实现。
锁保证使用本工具的写入者互斥，不防范同账号恶意进程并发篡改库。尚无签名、市场、网络下载、
在线授权核验、卸载、升级切换或运行时权限机制；不能将测试通过宣传为任意不可信文件绝对安全。
