# TTS 与语音聊天闭环审查

更新日期：2026-11-09。依据当前源码、合成资料与故障注入回归整理；本轮没有读取 API Key、访问在线服务、加载真实 ASR/TTS 模型、播放用户参考音频或打开麦克风/扬声器。实际执行结果见[实际验证记录](实际验证记录.md)。

## 当前链路

| 入口 | 当前流程 | 数据与资源边界 |
| --- | --- | --- |
| 互动气泡朗读 | helper 发送单条 cue → 宿主 latest-wins → TTS-only ready → 合成 → 播放排空 → 可接下一条 | 开关独立于聊天回复朗读；仅加载 TTS；参考音频与准确转写需预先配置；预热不生成声音 |
| 主动语音聊天 | 最长20秒录音 → 本机 ASR → 明确记忆指令/身份/能力/目标/记忆等本机回答 → 必要时在线模型 → 同一份短回复交给气泡和可选 TTS → 气泡结果与音频排空后完成 | 本机答案不发模型请求；普通问题的转写会交给所选服务商；录音临时文件在完成/失败/取消后清理；窗口关闭会取消未完成轮次 |
| 在线演示 | 用户主动发起 → 在线生成 → 可选 TTS/气泡 → 退出演示子进程 | 不录音，不加载 ASR；仍是可能计费请求，本轮只审查接线，没有实际发起 |
| 临时文字聊天 | 本机规则 → 必要时在线模型 → 当前窗口有界历史 | 目前没有“自动朗读文字聊天”开关；不能把互动气泡朗读等同于所有文字消息均朗读 |
| 直播语音桥 | 外部合成事件 → 有界文本转换 → Speech Runtime JSONL | CLI 协议与模拟事件已存在，真实 B站/抖音登录和消息来源仍未接入 |

ASR/TTS 使用源码目录下 `.local/voice-runtime/` 的本机环境与模型；不是安装包自带的完整语音发行环境。参数和参考音频变化后，语音轮次会先回收不兼容的受控进程再启动；默认不并发加载两份模型。成功主动聊天保留兼容进程用于后续聊天；互动 cue 失败或超时则先结束失败进程，再处理待播提示。

## 本轮修复与证据

| 问题 | 修复 | 自动化证据 |
| --- | --- | --- |
| 声卡工作线程失败后，队列仍有未完成条目，`join()` 永久等待；满队列也可能阻塞关闭哨兵 | 排空检查消费者异常并有30秒上限；关闭不向满队列追加哨兵，对阻塞写入尝试 abort，限制等待并清理剩余 PCM；初始化失败关闭已创建流 | 假声卡断开、满队列、阻塞写、排空超时、重复关闭与 start 失败注入 |
| 播放错误误报“合成失败”，空 PCM 也可能报音频开始 | 分开合成与播放错误；仅在非空 PCM 被输出层接受后报 `audio_started`；排空成功才发成功 idle；连续排队轮次重置首块状态 | direct respond 写入/排空错误、空 PCM、连续轮次事件回归 |
| 失败 cue 留下不可用输出流，后续点击一直复用坏进程 | 错误/超时后结束受控运行时，完成回收后才处理下一条 cue；当前 cue 与待播 cue 都有明确归属 | Coordinator 故障后第二次点击创建新进程；卡住的合成超时后可再次接收 cue |
| 子进程提前关闭 stdin 时宿主写入可能收到 SIGPIPE | 在管道写端启用 `F_SETNOSIGPIPE`，向调用方抛出写入错误 | 关闭 stdin 但继续存活的 shell 子进程；测试宿主继续运行 |
| 旧进程退出回调中启动新进程，可能误完成新进程的关闭等待 | 退出时先取出本代等待者，再通知退出、完成本代回调 | 旧进程退出后创建替代进程，其完成回调等待自身真实退出 |
| 语音转写与文字聊天维护两套角色业务分支，容易漏同步目标/知识等规则 | 语音复用同一身份/目标/知识/记忆处理方法，保留语音记忆来源；失败/退出取消待处理回复任务 | 合成离线身份、目标、知识、记忆与重开回归；mock payload 检查分享/过期门禁 |
| 正式模式的本机身份/能力/记忆/目标答复在分流前检查模型设置和钥匙串；不探测时若仍显示“需要设置”也会造成误报 | 本机能力快照不探测在线状态，并显示“按需检查”；本机答复及预览拒绝在线问题都不会加载在线凭证，只有在线分支加载凭证后才构造在线能力上下文 | 常规模式本机问题注入 provider 计数为0；离线预览拒绝普通问题时 provider 计数为0；合成在线问题凭证加载与 completion 各调用一次；能力回答不把按需检查写成尚未可用 |
| 合成在线回复测试若用真实 URLSession 会产生外部请求风险 | Coordinator 注入在线 provider 边界，测试使用合成凭据和 completion closure，断言人格/授权记忆进入上下文、私有/待审/过期记录排除 | 不构造 URLSession 请求，不访问 Keychain 或网络；不读取真实密钥 |
| 忙循环式卡住 cue 测试耗 CPU，超时恢复观察受冷启动时长干扰；优雅关闭和独立终止回退存在重复强杀计时器 | fixture 改为阻塞等待输入且忽略 TERM，仅模拟首进程故障；测试先预热隔离 TTS 加载与合成超时，并验证 cue 不误报成功、下一进程 ready 后完成；supervisor 统一通过 terminate 路径进行单一有界 SIGKILL 回退 | `SpeechWarmupTests` stalled cue 测试及 `SpeechRuntimeSupervisorTests` 生命周期回归；完整离线套件结果记录于[实际验证记录](实际验证记录.md) |
| 本机回顾可能太长，超过气泡512字节或 JSONL 文本上限 | 文字聊天保留原答案；语音和在线演示统一使用最多160字符、512字节的同一份短回复，超长显示省略号，避免显示与朗读取不同片段 | 长中文、ASCII、多标量 emoji、空白归一化与 JSONL 大小回归 |
| 子进程在完成前以退出码0结束时，聊天忙碌状态不释放；卡住也缺少本轮边界 | 主动语音/演示对未预期退出均报错；默认180秒轮次上限；错误、取消、超时统一回收计时器、回调、输入文件和访问授权；失败关闭等待0.2秒后按 supervisor 有界升级 | 子进程生命周期、cue 时限和恢复回归；语音完整阶段的真实模型验收未执行 |
| 演示未标记忙碌，互动朗读可能替换其回调；idle 可能先于气泡处理完成 | 演示独占语音轮次；只加载需要的 TTS；等待气泡处理与音频排空后收尾，不把无回复 idle 当作成功 | 宿主编译、共有生命周期/文本协议测试；真实在线演示未执行 |
| 气泡 socket 响应慢时在 AppKit 主线程等待 | IPC 移到后台；轮次结束后忽略迟到呈现结果，busy 重试仍受轮次时限约束 | 宿主编译/离线集成；真实 helper 忙碌体验待验收 |
| 麦克风授权尚未返回就关窗，迟到授权可能启动不可见录音 | 录音请求持有一次性 ID；取消立即结束待授权请求，迟到结果不启动设备；重复开始被拒绝；关窗取消当前语音/演示轮次 | 注入授权的取消后迟到成功、重复请求、拒绝后重试；不申请实际麦克风权限 |
| TTS 生成虽放在线程中，MLX 求值和 PCM 转换仍阻塞 asyncio 循环 | 一整块生成、求值和 PCM 转换放到工作线程；返回字节前释放临时数组引用 | 假 MLX/NumPy 记录线程，确认生成/求值/转换均在循环线程之外 |

音频队列最多24块，每块限制为最多5秒 PCM；这些是防止无界缓冲的上限，不是模型实际块时长或内存实测。`audio_started` 表示输出队列接受首个非空 PCM，不等于用户已经听到声音。PortAudio/系统设备若连 abort/close 都阻塞，最终仍依赖宿主对自己拥有的语音子进程进行有界结束；不能宣称设备驱动可被 Python 绝对中断。

| P1 | 用户感知首音延迟、尾音完整、连续轮次听感、声纹一致 | 真实输出设备上记录冷/热首音、尾音、数字/英文/中文及重复短句；本轮没有音频质量或 P50/P95 结论 |
| P2 | 主动聊天成功后 ASR/TTS 常驻，没有统一的空闲模型卸载策略 | 实测短间隔连问与长时间不用时的 RSS、GPU 内存及重载时间，再选择保留时长；不能为了省内存破坏首句延迟 |
| P2 | 录音会话启停仍有同步原生调用 | `AVCaptureSession.startRunning/stopRunning` 和采样队列屏障需结合真实设备耗时评估；如阻塞明显，再迁移到专用串行队列并验证授权/关闭竞态 |

| P2 | 拖拽、菜单、暂停、设备切换尚无统一“打断当前句”语义 | 目前菜单/模态只延后互动 cue，关窗/退出/超时可停止语音轮次；不能描述为已支持通用抢话或所有动作即时取消播放 |
| P2 | 真实配音环境尚未随发行包交付 | 源码本机路径已可运行；独立安装机、模型完整性、设备选择及安装/升级流程另验收 |
| 后续 | 直播真实来源、通用语义检索/知识自动更新、多角色语音聊天 | 仍属规划，不能用 CLI 假事件或单角色测试代替 |

## 本机验收顺序

1. 先使用[龙妹聊天与记忆验收](龙妹聊天与记忆验收.md)的隔离角色窗口验证旧身份补齐、知识导入和目标回顾。此阶段不使用真实模型或音频。
2. 使用通过字体、构建指纹和签名校验的新包，检查配置路径；本轮不会自动覆盖安装包或结束旧进程。
3. 用户自行确认参考音频/准确转写、麦克风与输出设备，先测互动气泡，再测本机语音问题。
4. 由用户决定是否发起在线模型请求。分别记录合成、输出排空、气泡 busy/成功、取消与重试，不将文字出现当作已经朗读。
5. 记录真实时间、设备、版本、复现步骤与现象，不提供 Key、用户音频或聊天正文作为自动化输入。
