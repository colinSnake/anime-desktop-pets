# 本地开发与使用指南

更新日期：2026-11-04。本文承接原根 README 中的素材导入、运行模式、配置和安装说明。
根 README 只保留项目入口；实现细节见[架构说明](架构与设计决策.md)，版本变化及实际测试结果见
[验证记录](实际验证记录.md)，未完成项见[路线图](roadmap.md)。本文档整理不代表重新执行构建或桌面验收。

## 1. 准备本机资源

在项目根目录执行命令。需要 Apple Silicon Mac、macOS 13+、Swift 5.9+ 与 Python 3；
重建增强 helper 另需专用 Python 3.12 环境及固定上游依赖，按[构建说明](桌宠增强与性能构建.md)准备。
已打包的 helper 自带 Python/Qt；这不等于源码构建不需要 Python GUI 依赖。基础宿主无需 Node 工具链。

本机已有素材时不要重复导入或下载。全新检出不包含私有视频、角色媒体和本机配置，需要自行提供有权使用的文件：

```bash
python3 scripts/import-local-assets.py \
  --video /absolute/path/to/startup.mp4 \
  --pet-preview /absolute/path/to/preview.png
```

导入目标是 `resources/media/startup.mp4` 和 `resources/pet/preview.png`；来源与 SHA-256 写入被忽略的
`resources/assets.local.json`，不修改源文件。不同内容覆盖已有目标必须显式使用 `--overwrite`。
这里的 PNG 用于静态降级，不能代替完整动作素材。

完整龙妹的固定上游包获取与校验见[完整桌宠接入](完整桌宠接入说明.md)；增强版另需准备10段扩展素材，见
[扩展动作接入](扩展动作素材与运行时接入.md)。不因 Git 检出而获得第三方素材的再分发许可。

开机视频的 1080p → 4K 本地超分入口为 `scripts/upscale-startup-video.py`，需要独立工具和模型。原片备份、批量帧处理、验证及替换命令见[4K 超分说明](开机动画4K超分.md)。超分只处理启动视频，不改变桌宠动画。

## 2. 构建与只读检查

完成上节准备后，按顺序构建增强 helper 与宿主：

```bash
# 仅缺少已校验固定上游包时获取；联网下载，不启动桌宠。
python3 scripts/prepare-full-pet.py fetch
python3 scripts/build-pet-runtime.py build
./scripts/build.sh
./scripts/test.sh
./scripts/petctl.sh --check
```

产物为 `build/桌边小崽.app`，版本0.7.11/build31；`CFBundleName/CFBundleDisplayName`同步使用「桌边小崽」，Bundle ID与内部可执行名保持兼容。本机ad-hoc签名不等于公证或可公开发行。macOS可能因新构建签名变化要求重新确认文稿文件夹及辅助功能权限；仅用户在系统设置手动批准，应用不自动请求或绕过权限。
若参考源码目录有未提交改动，按[构建说明](桌宠增强与性能构建.md)指定固定 `--source-revision`，
不修改参考仓库，也不把其未提交内容混入构建。

默认增强 helper 外置引用 `.local/pet-build/source/outputs/白龙桌宠素材`，而不是重复内嵌约1.25GiB动画。
可用 `DRAGON_PET_ASSETS_DIR=/绝对路径/白龙桌宠素材 ./scripts/build.sh` 指定目录；生成配置中的绝对路径仅适合本机。
需要自包含 helper 时使用 `python3 scripts/build-pet-runtime.py build --bundle-assets`；自包含不等于取得发行授权。

`./scripts/build.sh --full-pet` 明确选择未经增强的固定原版（25动作）；`--native-pet` 选择 Swift 静态降级。
默认增强版为35动作。不要把 PNG 呼吸效果当作完整动画播放器。

构建成功后脚本清理闲置历史 App 归档；删除前若归档新近被进程打开则跳过并继续，已由并行清理移除的候选也会安全跳过。`python3 scripts/clean-builds.py --dry-run` 可预览清理范围。
使用 Bash 时执行 `bash scripts/clean-builds.sh --dry-run`（或直接 `./scripts/clean-builds.sh --dry-run`）；
`.py` 文件须由 Python 解释，不能执行 `bash scripts/clean-builds.py`。去掉 `--dry-run` 才会实际清理闲置归档。
不删除当前唯一可用构建、源素材或环境，不强退正在使用旧归档的进程。

磁盘回收可显式执行 `python3 scripts/clean-builds.py --caches --dry-run`，核对后去掉 `--dry-run`：
只扫描三个现有 Swift scratch 下 `out/` 的编译缓存、中间文件与索引，以及 `.local/pet-build/work`、
`pyinstaller-cache`，以及仅当 `.dragon-generated` 内容精确匹配构建器标记时的 `generated-source` 暂存目录。
`Products`、scratch 根目录和包管理元数据保留，不整体删除 `.build/` 或 `.local/`。
只有当前 `BailongPet.app` 的 Bundle ID、深度签名及全部符号链接自包含检查通过，才可删除冗余的
`dist/BailongPet` 目录；旧 helper 归档也要求当前 helper 可用，旧宿主归档要求当前宿主包仍存在。
不清理 `source`、`venv`、下载、源动画、预览、基准报告或其它验证证据。`generated-source` 可由保留的固定上游、原版与扩展素材及补丁重建；所有权标记不符或缺失时绝不纳入候选。
清理前及每个删除操作前检查进程/文件占用和路径，链接路径不作为候选；编译进程存在、占用检查失败时停止，
被占用目录跳过。不要与构建并行执行；不会结束任何进程。后续构建会重建缓存，首次耗时可能增加。
普通构建继续只清理闲置历史 App 归档，不自动开启 `--caches`。

这些构建、检查和测试不会启动正常桌宠、安装登录服务、应用主题或调用图片服务。
`--check` 检查配置、资源与客户端发现，不证明真实播放、焦点和多屏交接通过验收。

### 离屏卡片预览与 Python 崩溃排查

固定源码及专用 PySide6 环境准备后，可生成菜单／气泡截图，不显示真实桌面窗口、不查询真实额度：

```bash
/usr/bin/sandbox-exec -p '(version 1) (allow default) (deny network*)' \
  .local/pet-build/venv/bin/python scripts/preview-pet-ui.py
# 可追加 --output-dir /绝对路径/预览目录，默认输出到 .local/pet-build/previews/cards/。
```

此入口使用临时 HOME，并在导入 Qt 前强制 `QT_QPA_PLATFORM=offscreen`、`QT_STYLE_OVERRIDE=Fusion`。
不要为追求原生截图而强制 `macOS` 样式：2026-11-03 的本机报告中，该组合在
`libqmacstyle` 的 `QToolButton` 绘制路径出现 SIGSEGV。Fusion 截图不证明原生 macOS 外观已验收；
真实桌面样式不改。`scripts/test-preview-pet-ui.py` 通过子进程覆盖继承样式、深浅色截图和气泡反复切换／延迟销毁，
由 `./scripts/test.sh` 在环境具备时禁网运行。无需为此修复重建 helper 或宿主。

后续18:27—18:29的屏幕访问崩溃已在本机定位到另一条生命周期问题：
PySide6 6.9.2 的 `QWidget.screen()` 返回值父级启发式会将共享屏幕包装器关联到调用气泡；
销毁气泡后该包装器失效，即使屏幕原生对象尚未正常销毁。`Bubble` 改用
`QApplication.screenAt(窗口中心)`，找不到时回退应用主屏幕，不调用 `QWidget.screen()`。
真实 Adapter 停止时也显式 `deleteLater()` 销毁独立气泡；这与离屏 Fusion 修复互不替代。
`test-qt-lifecycle.py` 在临时 HOME／合成素材下覆盖24轮启停、带焦点按钮、GC后屏幕有效性及多宠隔离。
运行时修订须先重建 helper 再重建宿主；不要只修改脚本就认为运行中的旧进程已经修复。

遇到系统 Python 崩溃弹窗时，先检查 `~/Library/Logs/DiagnosticReports/Python*.ips` 的时间与原生调用栈，
区分样式绘制、窗口销毁和图像初始化；不要据此直接重装全局 Python，也不要结束其他项目进程。

## 3. 主动预览与 Codex 联动

以下命令会运行实际应用，只在用户主动选择安全时机后执行。每次选择一种模式：

| 命令 | 用途与边界 |
| --- | --- |
| `./scripts/petctl.sh --preview-animation` | 预览本地启动视频，不启动或激活 Codex |
| `./scripts/petctl.sh --preview-pet` | 预览桌宠，不读取 Codex 任务 |
| `./scripts/petctl.sh --launch` | 启动或复用 Codex；也是直接打开 App 的默认模式 |
| `./scripts/petctl.sh --watch` | 观察 Codex 后续启动，不退出或重启既有客户端 |

这些模式持续占用前台，视频结束不代表应用退出。仓库内 `petctl.sh` 会自动将当前 checkout 作为 `DRAGON_DEV_ROOT`，供开发态语音运行时和模型路径发现使用；直接从 Finder 启动打包 App 不会自动获得 checkout 里的私有语音环境。一个宿主应用管理多个桌宠实例，不应同时启动多个宿主协调器。
切换模式前先从菜单栏退出旧宿主，或在另一个终端运行 `./scripts/petctl.sh --quit`。
宿主按普通 macOS 应用显示在 Dock 和应用切换器；菜单栏状态项使用透明的窗口伴星线性模板图标，与带底色的 Dock App 图标分开。桌宠窗口仍保持独立，不会因宿主显示在 Dock 而变成普通窗口。
构建会保留当前可用包后再替换；若要保留所有历史构建归档，可使用 `DRAGON_SKIP_BUILD_CLEANUP=1 ./scripts/build.sh`。

`./scripts/preview-full-pet.sh` 是手动切换入口：先验证25/35动作后端，再请求当前宿主退出、等待清理并预览。
它可能中断现有桌宠展示；无法退出时会停止切换，不强制杀进程。自动测试不得调用该入口。

Codex 已运行时只显示桌宠，不补播视频；关闭窗口不等于退出进程，不能通过再次点 Dock 代替冷启动验收。
启动视频可用 Esc、Command+. 或跳过按钮撤掉；超时和失败会清理覆盖层，但不保证启动第一帧完全无闪现。

## 4. 日常控制

在另一个终端中向 `./scripts/petctl.sh` 每次传一个参数：

| 参数 | 作用 |
| --- | --- |
| `--status` | 查看宿主状态 |
| `--show` / `--hide` | 显示或隐藏桌宠 |
| `--dismiss` | 结束当前 Codex 会话中的桌宠显示 |
| `--pause` / `--resume` | 暂停或恢复协调 |
| `--quit` | 退出桌边小崽，不退出 Codex |

状态栏主菜单在多实例模式可启动/停止全部桌宠，单宠模式提供显示/隐藏；“实例管理”中按实例启动/停止、调整尺寸、创建同包分身或删除已停止分身。新分身默认不随宿主启动自动恢复，单只启动后才加入自动恢复，单只停止会关闭自动恢复。菜单状态来自 helper 最近确认的状态，握手期间会显示读取中。删除需确认，只移除清单记录，不删除素材或状态目录。动画桌宠右键管理本只的显隐、尺寸、活动和动作预览；静态降级右键只保留隐藏。退出宿主从状态栏执行，退出单只动画桌宠从其自身菜单执行。开发 CLI 与 Socket 合约见
[多宠控制协议](多宠本地控制协议.md)，实例状态隔离见[生命周期说明](多宠实例模型与生命周期.md)。

默认增强版龙妹在实例清单确实缺失时，状态栏还会显示“创建龙妹分身…”。首次创建会先说明并确认控制器切换：仅当旧单宠是本宿主启动、受控的增强 helper 时，宿主才请求其正常退出并异步等待确认；确认后由单一多宠 helper 接管原宠并登记一只停止态分身。取消不改变运行状态；退出失败或结果不确定时不会启动竞争控制器。若控制器启动或清单结果不确定，先退出并重新打开桌边小崽，让它根据磁盘状态恢复单宠或多宠模式，不要连续重试创建。损坏、空、全禁用或符号链接清单不会按“缺失”覆盖。运行中的旧版本不会热加载，桌面验收请等当前桌宠退出后再启动新构建；不要为此强制结束进程。
现在从“实例管理 → 桌宠管理…”选择其它桌宠：窗口自动扫描本机构建时记录的项目 `resources/pets`、`pets`、`.local/pets` 以及已导入包；点击“选择目录或桌宠包…”可一次选择多个本地目录或 `.petpack` 文件，目录选择保存在当前 profile 的 `pet-search-folders.json`。扫描最多5层、4096条目和128个候选，提示达到上限时请选择更具体的目录。

列表支持 ⌘/⇧ 多选和全选，一次最多添加16只；后台校验完整媒体、哈希及声明文件后登记新实例，默认停止且不自动恢复，需从实例管理启动。已存在的精确包版本引用不会重复登记。只有含有效 `manifest.json` 的 `webp-v1` 包目录或 `.petpack` 可用，普通应用和散图目录不直接导入。首次添加需显示本宿主拥有的增强龙妹并确认安全交接；只登记原宠和实际所选桌宠，不额外创建分身。运行状态只显示“龙妹 · 运行中”等阶段，自动恢复规则保留。

独立素材库窗口及其旧菜单入口已移除，主 App 不再打包 `DragonPetLibrary.app`。现有素材与实例数据保留；开发 CLI、停止态切换协议和引用保护见[素材包底座说明](宠物库与素材包.md)。菜单分工、能力限制及窗口协议见[菜单功能与交互边界](菜单功能与交互边界.md)。

额度仅在菜单「查看 Codex 额度」或双击等显式请求后刷新；不提供独立聊天/历史，不展示或保存聊天正文，
增强版另有独立的[任务跟随](Codex任务跟随.md)，不通过额度推断任务。额度细节见[额度气泡说明](额度气泡说明.md)。

## 5. 配置与本地数据

完整模板为 `config/companion.example.json`，用户配置和运行数据默认位于：

```text
~/Library/Application Support/AnimeDesktopPets/
  companion.json       # 可选用户配置
  pet-position.json    # 原生桌宠位置；多宠另有实例偏好和状态目录
  companion.log        # 有大小上限的生命周期日志
  control.sock         # 本地控制接口
  instance.lock        # 宿主单实例锁
```

需要定制时复制完整模板，修改后重开桌边小崽即可，不必重启 Codex。
`DRAGON_DATA_DIR` 可隔离本地状态，`DRAGON_RESOURCE_DIR` 可指定资源根目录；相对媒体路径以资源根目录解析。
这是「桌边小崽」的应用数据目录，不是内置龙妹动画素材目录。内置素材来自构建指定的资源根目录或 App 内资源；`DRAGON_RESOURCE_DIR` 可单独指定。数据目录保存 `companion.json` 用户配置、`pet-instances.json` 实例清单、`PetLibrary/` 已导入宠物包（其中包含其动画素材）、`instances/` 各实例偏好和位置状态、`pet-search-folders.json` 搜索目录、龙妹位置、诊断日志及本地控制 socket/锁文件。可从状态栏菜单「高级 → 打开数据文件夹」查看或备份。

旧版 `~/Library/Application Support/DragonCodexCompanion/` 会在宿主正常退出后首次启动新版时迁移为 `AnimeDesktopPets/`，并保留旧路径符号链接以兼容旧版安装器和日志路径。若两个目录同时存在，程序会停止并提示，不会自动合并或覆盖。显式设置 `DRAGON_DATA_DIR` 时仍使用指定路径。

源码模板保留原生后端；默认增强构建生成外部后端配置，helper 相对路径为 `../Helpers/BailongPet.app`。
已有用户 `companion.json` 优先，不会被打包默认值静默覆盖。若旧配置明确指定 `native`，
需自行更新完整配置或先备份再移开旧配置；不能直接删除用户设置来“修复”后端。

当前 App 文件名及系统显示名统一为「桌边小崽」；Bundle ID、内部可执行名及配置文件名保持兼容。

## 6. 安装与登录服务

默认构建依赖本地素材目录，移动 App 不会自动迁移这些素材。本机历史安装镜像不代表当前 helper 的最新版，
也不是可移植或已公证发行包。安装前确认版本及资源路径，旧实例由用户正常退出，不自动结束可能持有任务的进程。

登录服务与普通手动打开 App 不同，需完成人工验收并由用户明确选择。以下命令只输出计划：

```bash
./scripts/install.sh
./scripts/uninstall.sh
```

只有明确添加 `--confirm` 才实际安装并加载登录服务，或卸载本项目服务。
目标 App 为 `~/Applications/桌边小崽.app`，LaunchAgent 为
`~/Library/LaunchAgents/local.dragon.codex-companion.watch.plist`。检测到已知旧监视器冲突时安装会停止。
安装只管理 `~/Applications/桌边小崽.app`，已加载的登录服务仍须先显式停止。安装前在暂存目录完成复制和签名验证，应用替换失败会恢复原包。
卸载只识别当前包路径，并先校验归属及登录项可执行路径；拒绝符号链接和无关应用。停止服务失败时保留App及登录项，不继续移走；用户配置、素材与官方Codex客户端保留。安装／卸载仍须明确 `--confirm`，回归使用隔离HOME和替身系统命令，不代表真实安装验收。

## 开机视频与客户端加载时序

`--launch` 在发送 Codex 启动请求前建立视频覆盖层，二者同时推进；不等待稳定窗口后才开播。
覆盖层是非激活浮动面板，Codex 在视频背后保持前台。已有进程不补播、不自动调整尺寸；
`--watch` 发现新进程即覆盖，但不能追补进程创建时的启动参数，也不会重启现有客户端。

### 窗口与视频尺寸一致

当前视频为16:9。新客户端主窗口稳定后，宿主在已有辅助功能授权下，通过系统AX窗口尺寸／位置接口将它调整为
屏幕内的视频尺寸（默认最大1280×720逻辑点，受当前可用屏幕裁切），随后重新读取**实际**窗口边界并跟随。
首次稳定窗口出现时如果 Chromium 的 AX 窗口还未就绪，宿主会按间隔重试；动画结束时还会做一次最终校准，
确保 Codex 自身窗口在覆盖层撤掉后仍保留视频目标尺寸。
不按请求成功就假定窗口已经同尺寸，也不调整已有会话、全屏窗口或对话框；客户端最小尺寸限制优先。
只读取窗口角色、尺寸／位置和全屏状态，不读取窗口标题、页面或对话正文。

授权入口：桌边小崽菜单 → **允许关联窗口大小**，然后在系统设置中允许「桌边小崽」。点击菜单只打开设置；应用不会自动请求权限。
`petctl --check`的`startupWindowSizing`明确报告是否具备授权。
未授权、窗口不可调或受到最小尺寸限制时，视频按实际窗口**等比例铺满并裁边**，不拉伸、不再留下左右黑边；
此回退不等于已经成功把客户端改为16:9。

### 防止覆盖导致客户端延后渲染

2026-11-04本机启动日志确认视频与客户端请求都在09:49:04发起，09:49:05已出现可见窗口，09:49:18视频结束；
用户仍看到后续loading，因此之前仅改焦点并未完成体验目标。可见窗口不能作为内容加载结束的证据。

正常联动期间覆盖层保持至多0.999透明度（99.9%不透明）直到视频结束；独立预览继续使用配置中的淡出。这样不会在视频真实结束前提前露出 Codex loading，避免完全不透明覆盖造成遮挡判定。
对具有Codex／Electron Framework的Chromium客户端，**仅新启动请求**附带
`--disable-backgrounding-occluded-windows`，使遮挡可见性不转成后台渲染状态。
这是针对覆盖引起的降速，不关闭所有后台定时器节流、不打开调试端口、不注入JS，也不修改官方应用包或用户配置。
参数作用于该次客户端进程直到退出；对未来版本不保证兼容，也不将其宣传为官方Codex集成API。
原理核对依据是Chromium的`content/public/common/content_switches.cc`、
`content/browser/web_contents/web_contents_impl.cc`与macOS遮挡检查实现；本机框架包含该开关字符串。
用户反馈的loading仍需下次冷启动实测，不能仅凭源码机制宣称已消失。

### 交接与跳过

正常联动使用右上角“跳过”按钮；键盘留给 Codex，不注册全局快捷键或申请输入监控权限。
独立 `--preview-animation` 仍主动激活预览，支持 Esc／Command+.；覆盖层获得键盘焦点时也保留按键处理。
正常联动的视频播放结束后立即释放覆盖层，让 Codex 自身 loading 继续显示；视频与 Codex 启动请求仍然并行。
由于官方客户端没有提供可用的内容就绪接口，宿主只把窗口可见作为窗口尺寸同步和启动观察信号，不把它宣传为页面加载完成。
独立预览仍在视频结束时正常结束。没有读取页面、截图、对话，也没有添加固定延迟伪装就绪。
本实现不保证任意环境都在约14秒内加载完毕，真实冷启动由用户选择安全时机验收。
