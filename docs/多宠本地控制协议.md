# 多宠本地控制协议 v1（MP1c 控制通道）

日期：2026-11-04。本次交付在实际工程 `anime-desktop-pets`。
这是Swift客户端 ↔ Qt控制器 ↔ 实例生命周期内核的本机接入；默认单宠首次龙妹分身入口及启停、删除已接通，正式发布安装与本轮真实桌面验收仍未完成。

默认增强单宠且清单缺失时，宿主状态栏提供首次创建入口。首次交接只针对本宿主拥有且窗口协议受控的单宠 helper：先正常请求退出并等待进程结束，再启动多宠控制器；清单初始化由 helper 在素材库锁和实例引用锁下原子完成。原宠白名单偏好保留，新分身拥有独立偏好并以 stopped 登记。退出确认失败或状态不确定时不会启动第二控制器。

## 2. 所有权与启动边界

- 调用方显式给出profile。目录必须是当前用户所有、权限0700、非符号链接。
- 端点固定为profile内的 `pet-control.sock`，权限0600；完整路径小于104字节。
- 先由 `InstanceStore` 获得目录独占锁，再创建服务器；活socket、普通文件、链接均拒绝覆盖。
- 只清理本用户、已确认连接被拒绝的失效socket，不接管其他桌边小崽或旧龙妹的唤回端口。
- 客户端只连接、不创建profile、不冷启动、不安装或启动helper/Codex，不自动重试。
- 目录/权限是同用户本地边界，不是跨用户服务或防同账号恶意程序的认证机制。

真实helper先创建QApplication，再构造store/controller/server，最后由 `server.finished` 连接到应用退出；
不能将 `controller.shutdown_finished` 直接连接app.quit，否则可能在关闭确认尚未排空时就退出。

## 3. 报文格式

一个连接仅一条UTF-8 JSON，用换行结束；JSON可分片到达。拒绝重复键、额外命令和未知字段。

```json
{"protocolVersion":1,"requestId":"unique-request-id","command":"start_pet","instanceID":"white-dragon"}
```

命令白名单：

| command | 额外字段 | 行为 |
| --- | --- | --- |
| `status` | 无 | 返回PID、实例阶段、包引用与独立偏好；不读账号/聊天 |
| `start_pet` | instanceID | 启动预注册实例；已经starting/running则幂等，不创建第二只 |
| `start_selected` | instanceIDs | 1–32个唯一ID；整体检查身份、启用状态、清理阶段和运行容量，再分别创建 |
| `stop_pet` | instanceID | 停止单只；不退出其他实例或整个Qt应用 |
| `stop_all` | 无 | 停止当前实例，控制器继续可用 |
| `set_preferences` | instanceID、preferences | 局部更新尺寸/位置/行为；不允许脚本、路径或账号参数 |
| `clone_pet` | instanceID、cloneID | 复制实例定义并持久化；要求源实例存在、新ID唯一；新实例保持stopped |
| `add_pets` | packages | 1–16个唯一精确 `{id, version}` 引用；要求已在本地完整校验/导入。锁内批量原子登记，新实例 stopped 且默认不自动恢复，已有引用幂等返回 |
| `delete_pet` | instanceID | 删除非原始龙妹且已停止/清理完成的实例定义；不删除包或状态目录 |
| `shutdown` | 无 | 发起全部清理，完成后排空确认、关闭通道；不是立即强杀 |

instanceID限制与[实例模型](多宠实例模型与生命周期.md)一致。preferences仅支持size、x、y、
scheduledActivity、movement、hideInFullscreen；真正位置配对校验在合并当前偏好后进行。
本地 `add_pets` 仅接收已导入包的精确引用，不接受路径、脚本或远程地址。不提供远程注册、任意路径加载、执行脚本、读取凭证、额度查询或历史接口。

成功响应：protocolVersion、相同requestId、`ok:true`、result。
result含controllerPID、status（shuttingDown/maximumRunning/instances）和outcomes。
每个状态包含id/package/enabled/preferences/phase/error；阶段是stopped/starting/running/stopping/failed。
错误响应使用 `ok:false`、error.code/message，不同时包含result。

**确认收到不等于首帧就绪**：start确认后必须看phase是否running；ready只能由窗口首帧已可呈现时发出。
shutdown确认可能仍为stopping，只有各适配器真正清理后控制器才结束。不能把Socket连接成功当作UI可用。

## 4. 批量、去重与不确定结果

- 未知ID、禁用、重复ID、清理中或超容量会在任何实例开始之前拒绝整批。
- 实际窗口工厂失败按outcomes分别返回accepted/changed/error，不强退此前成功或原本就在运行的实例。
  因此顶层ok=true不代表批量中每一只均成功，更不代表已经running。
- 同一requestId、相同请求的响应在当前进程内有限缓存，重复收到不再次执行。
- `clone_pet` 的重复requestId只返回第一次确认，不会登记第二个实例；不同请求复用同一requestId会拒绝。
- 同一requestId对应不同请求会拒绝；每次新操作必须用新ID，状态查询也应使用新ID。
- 缓存最多64项、2MiB、只在内存中；淘汰或重启后**不保证跨时段恰好一次**，不作为事务日志。
- Python/Swift客户端均不自动重发。发送后遇到断开、错误确认或超时，明确报“结果不确定”，
  用户/调用方应先用新的status请求核对，而不是重新启动控制器或直接重做破坏性操作。
- 缓存返回的是原确认快照，不是当前状态；重试确认后同样需要新status查看现状。

## 5. 预算与异常处理

- 请求含换行最多8192字节，响应含换行最多128KiB。
- 最多16条已接收连接；接收/发送期限2秒，超限或超时关闭该连接，不杀控制进程。
- Python/Swift客户端有一次RPC的总截止时间，默认2秒，可设0.05–10秒。
- 多请求同连接、无换行断开、畸形UTF-8/JSON、过大报文不触发任何启动动作。
- shutdown先停止监听，已有连接排空确认；清理超时仍由生命周期内核保留名额和锁，不假报成功。
- UI未来调用Swift同步客户端时应放在非主线程；本轮不把阻塞RPC放入现有菜单或GUI线程。
