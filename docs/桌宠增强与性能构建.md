## 2026-11-05：预缩小 WebP 资产实验结论

先前只测一个默认待机动作的普通RGBA派生，发现预乘alpha路径存在像素差；该临时样本不是正确的运行时输出参照，不能据此评价派生质量。本轮改按运行时`decode_image()`的预乘alpha后Lanczos缩放路径，离线评估完整35动作。

完整清单35动作、4426帧、约1.282GiB源WebP。每帧先在Pillow中按运行时预乘alpha并缩放到256×256，再重新编码成临时lossless WebP；通过RIFF帧头恢复逐帧时长。随后将派生帧与同一运行时缩放输出合成到黑、白背景逐帧比较：35/35动作的可见像素一致，帧数、帧时长数组及循环次数一致。派生总量约284.9MiB，减少77.8%；总目标像素处理量减少87.4%。3次顺序完整解码微基准中位数为源解码+缩放28.54秒，派生解码3.29秒，约8.67倍；这是Pillow端的离线微基准，包含不同分辨率导致的工作量差异，不代表Qt窗口CPU/RSS或播放帧率提升。

此次评估仅证明256px分支在当前Pillow转换和背景合成判据下可行，不是部署批准：播放器当前用Pillow/libwebp顺序读取，但产品路径还需由冻结Qt/PySide6 helper验证真实动画帧、dispose/blend与首帧等待。实例尺寸菜单有128/192/256/320/384五档，Retina设备还可能要求不同物理像素尺寸；只生成256px会令小档重复缩小、大档放大，画质与成本均未覆盖。若继续，先分别评估五档或按设备像素比选择的派生缓存，并核算约数百MiB额外磁盘、源资产哈希缓存失效及缓存清理策略，再做Qt真实解码和单/多实例窗口A/B。当前没有改正式素材、源清单、helper、构建输入或用户profile，不宣称产品性能提升。

## 2026-11-03：右键菜单不再打断松手弹簧（dragon.39）

## 2026-11-02：拖拽姿态与收尾规则（dragon.25）

此前只在 `AutonomousBehavior.release_drag()` 内排除了轻放弹簧，真实 `Pet.mouseReleaseEvent()` 却仍在返回 False 后调用 `landingAnimation`，因此轻放仍出现旧落地／疲惫飞行。现在增强版所有“不甩动”松手分支直接播放默认待机，保留落点；不会调用随机待机，也不会补播落地。原版 `--full-pet` 不变。

- 轻拖（合速度低于80逻辑像素/秒）使用普通待机姿态；活动姿态退出阈值60px/s，避免边界抖动。
- 明显位移用方向走路；横速600px/s进入跑步、低于480px/s退出；飞行需竖速180px/s、合速度280px/s且竖向分量大于横向的0.75倍，退出阈值为150/230px/s、比例0.6。只改变表现，不替用户移动鼠标。
- 按住时从 `moveStartMs` 进入，只循环至 `moveStopMs`，不播放准备／停止／疲惫收尾。姿态最多每50ms判断，64个有界样本覆盖常见高频输入；停住80ms后由现有tick在下一次判断回普通姿态，不新增定时器。
- 松手仍需至少24px最大位移与最近150ms合速度280px/s，速度包含松手前的停顿；80ms无移动则不再认作甩动。小幅快抖、慢拖长距离、甩后停稳、关闭位移或减少动态效果均直接默认待机。
- 明确甩动保留现有有界弹簧与方向动作、当前帧接续及短混合；动作在有效运动段结束后直接由默认待机承接余下轨迹，不播独立落地或素材的疲惫收尾。普通自主／手动移动保留完整动作。25动作兼容模式的明确甩动仍保留原有三跳，轻放同样直接待机。

人工验收时仅由用户正常退出旧桌宠并打开新构建，再检查：轻拖后立即轻放、慢拖长距离、快拖后按住约0.1秒再放、小幅快抖，均应停在落点且无疲惫飞行；持续拖动只显示相应活动姿态，竖直轻拖不能进入飞行；明确甩动才应有重力反弹，并在有效运动段结束后普通待机承接。也检查关闭位移／减少动态效果时的轻放，以及拖动途中再次按住／多屏边界。原版 `--full-pet` 和已安装的旧包不会自动变更。

真实手感、窗口管理器事件频率、长期CPU/RSS仍须用户在安全时机验收；不自动启动、安装或重启已运行桌宠。

## 1. 为什么要改辅助应用

原版 Swift 静态降级不是完整桌宠。原版 25 动作与新增 10 动作由独立的 Python/PySide6 辅助应用播放；
因此文本布局、帧解码和右键菜单必须在该辅助应用内部修复，单改 Swift 外壳不会生效。

原始下载 App 与源仓库保持原样。增强层代码放在 `apps/pet-runtime/bailong/`，第三方补丁和固定来源

`.local/pet-build/source/outputs/` 独立保留已审阅的运行素材，不作为生成源码暂存目录。原始声明保留，
不修改官方 Codex、`app.asar` 或账号数据，也不安装额外登录服务。

## 3. 播放与内存算法

原版 `paintEvent → frames[index]` 会在 GUI 线程执行 Pillow 的 WebP seek、解码、
缩放和 QPixmap 转换。冷动作或前后跳帧时，绘制与鼠标菜单一起等待。

增强流程：

```text
GUI: 选择动作 / 时间索引 → 请求最新帧 → 非阻塞读取 QImage 成品 → GUI 创建 QPixmap
                              ↓
后台单线程：单个 WebP 解码器 → 顺序解码 + 最多提前 8 帧 → 预乘 alpha 缩放 → 有界 LRU
```

- 初始化只扫描 RIFF chunk 头得到帧数，不打开全部 35 个完整压缩动画。
- 一个后台解码线程、一个源解码器；切换动作更换 generation，丢弃过期结果。
- 白龙多实例共用进程级 QImage 48MiB + QPixmap 8MiB 总预算，并共享单解码闸门；
  活动播放器动态平分两层像素缓存额度，停止清理完成后回收名额。预取窗口同时受帧大小和缓存预算限制，
  小预算不会导致后台持续自我驱逐、空转。此预算不限制 Qt/Python、压缩源、当前画面或其它非缓存分配。
- QPixmap 只在 GUI 线程创建和使用；后台只生成拥有独立内存的 QImage。
- 新动作第一帧就绪后才启动播放时钟；等待时保留旧动作最后呈现的帧和原变换。
- 使用单调时钟取当前应呈现帧，解码落后时不排队追播过期帧。隐藏后不持续请求新帧。
- 原来的同步取帧接口仅保留给离线自检，真实绘制路径有测试保证不会调用它。
- 正常退出通知工作线程、关闭解码器并释放两层缓存。

**预算不是进程总内存上限。** Python、Qt、压缩 WebP、解码器、临时图像、字体与平台分配器
仍占内存。不要把“56MiB 像素缓存”表述为“桌宠只占 56MiB RAM”。

全局预算由 `AnimationResourceBudget` 在一个 Qt 控制进程内协调；多个不同控制进程不共享预算。
跨进程总资源与长时间运行峰值仍需实机观察，不能据此承诺 RSS 上限。

## 4. 灰边与锯齿的结论

深浅背景对照和原图局部放大表明，源 WebP 本身含浅色描边、抗锯齿过渡以及部分边缘底色。
不是所有灰边都是窗口投影，也不是换一条绘制 API 就能全部消除。

当前保证预乘 alpha 的 Lanczos 缩放，并以 Qt 的预乘图像格式继续合成，避免透明颜色串入边缘，
同时保留高 DPI 帧尺寸。不使用二值遮罩、硬阈值抠图或统一删灰，以免破坏白发、翅膀和细线。
Pillow 原来的 RGBA resize 本来就有预乘处理，因此不能声称此次缩放会让原稿轮廓发生明显变化。
素材自带底色若仍不满意，应对源蒙版进行逐帧修复或重新输出素材；当前未宣称完成这种重制。

本机对照：`.local/pet-build/previews/edges-comparison.png`，四列分别是源图、原缩放、
增强缩放、源边缘局部放大。这里只是素材与渲染对照，不是真实桌面截图。

## 5. 本机构建

已准备好的增强 App 可以直接使用；只有重建辅助应用时才需要专用 Python 环境。
首次构建在仓库根目录执行，按实际源码位置调整 `UPSTREAM_PET_SOURCE`：

```bash
python3 scripts/prepare-full-pet.py fetch
export UPSTREAM_PET_SOURCE=/absolute/path/to/bailong-desktop-pet-macos
python3.12 -m venv .local/pet-build/venv
.local/pet-build/venv/bin/python -m pip install -r "$UPSTREAM_PET_SOURCE/requirements-build.txt"
python3 scripts/build-pet-runtime.py build --source "$UPSTREAM_PET_SOURCE"
./scripts/build.sh
python3 scripts/clean-builds.py --dry-run
./scripts/test.sh
./scripts/dragonctl.sh --check
```

本机默认源码解析为项目旁 `github/codex-pet/bailong-desktop-pet-macos`，可不传 `--source`。
`stage` 子命令只准备源码而不打包，输出到 `.local/pet-build/generated-source/`，不覆盖运行素材目录。
源码哈希与固定基线不符会停止，不自动模糊套用补丁。

参考仓库工作树如果存在其它会话的未提交修改，使用固定提交导出一份临时干净源码：

```sh
python3 scripts/build-pet-runtime.py stage \
  --source "$HOME/Documents/coding/github/codex-pet/bailong-desktop-pet-macos" \
  --source-revision 8e5466d9a438deb6cb43f460e7f5a9bdb9d7a578
python3 scripts/build-pet-runtime.py build \
  --source "$HOME/Documents/coding/github/codex-pet/bailong-desktop-pet-macos" \
  --source-revision 8e5466d9a438deb6cb43f460e7f5a9bdb9d7a578
```

`--source-revision` 只读取 Git 对象并在临时目录解包，不修改参考仓库；提交仍必须通过
`integrations/bailong/upstream-files.json` 的逐文件哈希校验。未指定该参数时，构建脚本继续
严格检查传入目录，不会自动忽略脏工作树。

| 构建选择 | 行为 |
| --- | --- |
| `./scripts/build.sh` 或 `--enhanced-pet` | 打包精简增强 helper；35 个动作素材默认留在本地目录，不进入 App；若专用 Python 环境包含 PyInstaller/PySide6/Pillow，同时将独立素材库窗口打入主 App |
| `./scripts/build.sh --full-pet` | 显式打包未修改的固定上游 build 3，便于对照/回退 |
| `./scripts/build.sh --native-pet` | 显式打包原生静态降级，不宣称完整动画 |

增强素材默认引用 `.local/pet-build/source/outputs/白龙桌宠素材`。构建时可通过
`DRAGON_PET_ASSETS_DIR=/absolute/path/to/白龙桌宠素材 ./scripts/build.sh` 指定其它目录；
目录必须直接包含 `素材清单.json`。构建模板会写入本机绝对路径，适用于本机开发，不可直接
搬到另一台机器。已有 `~/Library/Application Support/DragonCodexCompanion/companion.json`
优先级更高，需要时在其中配置 `externalPetAssetsPath`。需要自包含增强 helper 时，构建它时加
`--bundle-assets`；这会重新将全部动画放进 helper，安装包仍会很大。

构建成功后会自动清理未被运行进程占用的旧宿主/helper 归档，当前 App 和仍在运行的历史版本保留。
也可手动检查或清理：

```sh
python3 scripts/clean-builds.py --dry-run
python3 scripts/clean-builds.py
```

补丁元数据记录基线 commit、原发布归档 SHA-256、补丁和增强模块哈希。包内保留原始
`BUILD_INFO.json` 作为基线记录，实际增强身份以 `DRAGON_PATCH.json` 和 Info.plist 为准。
本地新编译 App 使用新的 ad-hoc 签名，不冒用上游原签名，也未取得 Apple 公证。

如果运行的是其他版本的桌宠，桌边小崽会要求手动退出，不强杀可能持有任务的旧进程。
如果之前的用户配置显式选择 `native`，仍须改为完整外部后端再预览。

- 轨迹依赖单调时钟，首帧可用后才移动；自动轨迹等待超过 5 秒取消。屏幕边界变化时终止并收回可用区域。
- 任务/查询、拖动、按住鼠标、菜单/对话框、气泡、隐藏均阻止新自主动作；再次按住立即取消位移，保留当前位置，不抢焦点。

- 「自主活动」子菜单写入现有 `preferences.ini` 的 `autonomousEnabled` / `autonomousMotion`。
  关闭定时播放仍可松手弹跳；关闭位移同时关闭自主移动与松手弹跳，普通定时动画仍可播放。

这是已有角色画面加窗口轨迹，不含新肢体动作素材、窗沿识别、其他应用碰撞或屏幕底边重力系统。

- 新增 `dragon_playback.py`；松手默认按方向飞行，横向速度至少 600px/s 且竖向分量小于横向一半时跑步。使用最近 150ms 拖动样本，不读取桌面内容。
- 从素材 `moveStartMs - 200ms` 接入，保留完整运动和收尾，不在拖拽后重播数秒站立准备段。惯性最多 96px，飞行高度按屏内空间及竖向速度限制在 34–52px。
- 每次切换捕获已经合成的窗口画面；新入口帧未就绪时保留原画面，就绪后用 160ms 预乘 alpha 短混合。过渡期间入口帧固定、窗口不动；回待机同样过渡。不是光流、骨骼插值或 AI 补帧，不能宣称姿态完全一致。
- 读取 WebP ANMF 三字节时长建立非均匀时间轴，按清单总时长同比例对齐，不再按帧数平均索引。`animate` 接受新帧后才推进共享呈现时间，`paintEvent` 不拉取或替换帧；运动读取该呈现时间。
- 缺帧同时冻结呈现与位移，不追赶积压；每次推进最多 50ms，冷加载/中途缺帧超过 5 秒或解码失败时中断并回退。隐藏恢复重置计时锚点。交互与任务仍可抢占，重入从当前混合画面衔接。
- 系统减少动态效果关闭混合和位移，位移开关关闭时走旧落地但仍可平滑衔接；关闭定时调度不禁止手动松手动作。完整 25 动作兼容清单保留旧三跳路径。
- 缓存预算仍为 QImage 48MiB + QPixmap 8MiB；当前姿态、来源快照及混合临时层另占少量有界像素内存（512² RGBA 每层约 1MiB），不把 56MiB 写成进程总内存。

真实桌面帧率、混合观感、动作时长感受及 CPU/RSS 尚未验收；没有新的性能承诺。
