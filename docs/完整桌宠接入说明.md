# 完整动画桌宠接入说明

更新日期：2026-11-04。

## 1. 这次接入了什么

先前原生实现只显示参考 PNG 并整体上下浮动，并非真正的角色动作。
Swift 宿主应用统一调度完整龙妹 Mac 辅助应用；0.3.0 默认加入本地增强层，原版保留用于对照：

```text
桌边小崽.app
  ├── Codex 启动观察与视频
  ├── 显示/隐藏、状态与启动错误
  └── Contents/Helpers/BailongPet.app（独立进程）
        ├── 6 套待机动画
        ├── 15 个互动动画
        ├── 5 个工作动画
        ├── 查询、拖拽、落地 3 个特殊动画
        └── 左右走／跑／飞 6 个移动动画
```

当前默认增强版为35动作（helper build 36 / `dragon.42`）；固定上游原版 `--full-pet` 为25动作，
两者不可混用。上图表示增强版；原版为2待机、15互动、5工作及3特殊，动作过渡文件另行校验。
增强版在辅助应用内部修复文本、菜单与解码，
构建流程和测量见 [桌宠增强与性能](桌宠增强与性能构建.md)。
这不是把全部逻辑重写成 Swift，也不是接入了增强分支对现有 Codex 会话的任务监听。

在仓库根目录运行：

```bash
python3 scripts/prepare-full-pet.py fetch
```

继续验证签名、可执行文件、25 动作和实际播放文件；不删除隔离属性、不改签名、不绕过安全提示。

不会静默使用不完整 App，也不会为了显示角色自动回退静态图。

## 3. 构建行为

```bash
./scripts/build.sh
# 等价于 ./scripts/build.sh --enhanced-pet
```

默认构建前先按 [增强层说明](桌宠增强与性能构建.md) 编译辅助应用，再复制到 `Contents/Helpers/`。
增强版有新 ad-hoc 签名与 `DRAGON_PATCH.json`，原始下载 App 不变。
显式 `./scripts/build.sh --full-pet` 才会原样复制固定上游版本。两种模式都保留来源声明。
包内配置使用 `petBackend: "external"` 与 `externalPetAppPath: "../Helpers/BailongPet.app"`，
路径相对 `Contents/Resources/` 解析。移动整个桌边小崽应用不会依赖源码目录的绝对路径。
构建后验证外层与嵌套签名；本地 ad-hoc 签名不等于公证或再分发授权。

如只想验证旧的静态原生面板，必须明确选择：

```bash
./scripts/build.sh --native-pet
```

这会生成另一种构建模式，不能把它当作完整桌宠。之后恢复完整模式需重新构建。

## 4. 用户配置优先级

`~/Library/Application Support/AnimeDesktopPets/companion.json` 如存在，会覆盖包内模板。
因此以前保存的 `petBackend: "native"` 不会被新构建静默替换。
请先备份，再在完整配置中调整：

```json
{
  "petBackend": "external",
  "externalPetAppPath": "../Helpers/BailongPet.app"
}
```

这只是修改字段示例，不是可直接覆盖的完整配置。
改后只需退出并重开桌边小崽，无需重启 Codex。

外部模式中，`petSize`、`petImagePath` 和原生 `hidePetInFullscreen` 不控制上游桌宠；
其尺寸、全屏与对话偏好以它自己的功能和设置为准，保存在其独立数据目录。

## 5. 离线解码与交互自检

```bash
python3 scripts/prepare-full-pet.py self-test
```

这会执行固定版本上游程序的 `--self-test`，不是正常桌宠启动：

- 设置 `QT_QPA_PLATFORM=offscreen`，不显示真实桌面窗口。
- 使用临时 HOME、独立报告目录和不可用的 Codex 命令。
- 用系统 `sandbox-exec` 禁止网络；不执行真实额度查询或聊天任务。
- 验证动作解码、模拟拖拽落地、菜单和模拟对话 UI 等上游离线检查。
- 报告和离屏预览位于 `.local/reports/`；它不是实际桌面截图或真实聊天验收。

如果没有隔离工具，脚本停止，而不是退回真实账号/网络环境运行。

### 可选：逐帧审计与小型 GIF

如果本机 Python 已安装 Pillow，可进一步运行：

```bash
python3 scripts/preview-full-pet.py --audit-all-frames
```

该步骤真正解码每个主动作的每一帧，统计不同画面数量，并输出小型待机/互动 GIF 到
`.local/previews/`。这是上游素材的离线预览，不是原创海报，也不是已经完成桌面验收的录像。
Pillow 仅供这个可选开发工具使用，完整桌宠 App 已自带运行依赖。

## 6. 手动体验真正的动画

最方便的手动入口会校验 25 动作，退出旧桌边小崽并等待清理后切换预览，不启动或重启 Codex：

```bash
./scripts/preview-full-pet.sh
```

也可以先自行结束现有桌边小崽实例，再直接启动完整桌宠预览：

```bash
./scripts/petctl.sh --preview-pet
```

命令持续占用前台，需在另一个终端标签页操作控制命令，或用菜单栏退出。
不要把 `--preview-pet`、`--quit` 连续粘贴到同一个终端期待自动返回。
互动动画可能异步发送单向语音提示，客户端会在宿主确认前关闭连接；当前宿主对确认回写使用逐 socket 的 `MSG_NOSIGNAL`，断连不应再终止桌边小崽。自动化覆盖协议断连，但仍需按下方清单人工确认菜单动画与桌面表现。

建议依次验收：

1. 待机时角色自身是否有动作，而不是整张图上下移动。
2. 单击是否切换随机互动动作与台词。
3. 按住拖动是否播放拖拽，松手是否播放落地。
4. 右键是否有互动、工作、待机分类动作。
5. 桌边小崽的 `--hide` / `--show` 能否隐藏和唤回。
6. 系统全屏、切换 Space、跨屏拖动和位置恢复。

`--check` 应报告 `petBackend: "external"`、`petActions: 25`。
`--status` 中 `petState` 和 `petError` 可区分启动中、可见、运行但无可见窗口与失败。
可见性来自窗口边界信息，不采集屏幕图像。

## 7. 生命周期与限制

- 只使用桌边小崽的 Codex 监视器。**不要在上游菜单另启随客户端自动启动**，避免两套监听。
- 已有同 Bundle ID、兼容版本的桌宠时复用，不重复启动。
- 固定版本的“显示”会尝试连接同用户临时目录的上游唤回 Socket，只连接、不发送内容。
  如果现有实例使用不同临时目录或协议，可从其自身菜单栏唤回；不保证所有版本兼容。
- 用户主动的隐藏/显示命令会操作当前接入实例。
- Codex 或桌边小崽退出时，对本宿主启动且支持窗口控制协议的增强实例正常请求退出；旧版只尝试隐藏，不强杀。既有独立实例保留，不自动隐藏或退出。
- **不强制结束外部桌宠进程**，避免中断其可能运行的任务。完全退出它请使用自己的桌宠菜单。
- 首次运行若被系统安全检查阻止，应核查来源、哈希和隐私与安全性提示，不批量删除隔离标记。
- 真实键盘焦点、多屏与这些生命周期行为仍需人工验收，离线测试不替代它们。

## 8. 对话、额度与现有 Codex 任务不是一回事

未修改的固定上游 App 保留自己的额度查询、对话与历史 UI；当前 Companion `dragon.8` 增强构建已经移除自有对话/历史 UI 和独立用量窗口，仅保留手动额度气泡。
**本阶段没有测试真实账号、额度或聊天**。若用户直接运行未经修改的上游 App，其功能可能访问本机 Codex 账号、消耗额度或在所选目录执行任务；
这属于上游独立应用的能力，不由 Companion 自动触发，也不等于监听或接续用户当前打开的 Codex 对话。

现有 Codex 任务状态跟随、完成提醒去重与增强分支适配，仍是后续独立工作。
桌边小崽自身不读取认证或聊天正文；不能把这个边界误写成上游全部功能都不访问账号。
