React 桌宠页设置现采用用户选择的方案 C：右侧面板固定标题和保存栏、仅设置主体滚动；卡片主操作、设置和更多入口等宽等高，次级克隆/删除使用披露区。保存与运行时应用反馈、失败状态和草稿语义沿用既有 controller；不增加 IPC、服务命令或路径能力。该 UI 本轮按合成 React 浏览器环境验证，不等于真实 Electron 窗口验收。

## 2. 开发环境与命令

在仓库根目录使用 **Node.js 24.x、pnpm 10.32.0、Python 3.10+**。依赖版本与 `pnpm-lock.yaml` 固定；`.node-version` 为 Node 主版本入口。`pnpm install --frozen-lockfile` 安装开发依赖，不安装产品或启用服务；Electron 开发二进制可能在首次运行入口时下载。`packageManager` 固定 pnpm 10.32.0，`pnpm-workspace.yaml` 只允许 esbuild 的构建脚本；不使用 npm 或平铺依赖兼容开关。

```bash
pnpm install --frozen-lockfile
pnpm run check:cross-platform
```

`check:cross-platform` 依次执行 TS 检查、Node 单测、Python 标准库测试、生产资源构建和构建产物冒烟检查，不启动 Electron 窗口、Qt、录音或真实模型服务。Node 测试仅使用本地随机端口、自有临时子进程和合成凭证；不读取真实产品数据。

拆分入口（`test:workspace` 检查 pnpm 约定与服务包依赖边界）：

```bash
pnpm run test:workspace
pnpm run test:tooling
pnpm run typecheck
pnpm run test:cross-platform
pnpm run test:bridge
pnpm run build:cross-platform
pnpm run test:build
```

Python 命令默认 macOS/Linux 为 `python3`，Windows 为 `python`。可通过 `PET_PYTHON` 指定解释器的完整路径（是单个可执行文件，不是 shell 命令或附加参数）。PowerShell 使用 `$env:PET_PYTHON = 'C:\path\to\python.exe'`；POSIX 可用 `PET_PYTHON=/path/to/python pnpm run dev:desktop`。诊断 worker 使用 `-I -u`，不继承模型密钥、`PYTHONPATH` 或 Python 启动钩子。

仅当用户明确选择真实桌面预览时运行：

```bash
pnpm run dev:desktop
```

此命令构建后启动新开发工作区；不会接管/停止旧 Swift 应用或现有宠物。macOS 状态栏可用且工作区可重开时，关窗仅隐藏，菜单或 Dock 可以重开；显式退出才回收自有服务、诊断 worker 与开发播放器。状态栏未就绪或不可用时保留关窗退出，其他平台仍关窗退出。Electron 自己的开发 profile 位于系统应用数据目录下 `AnimeDesktopPets/cross-platform-dev`；不读取旧应用的配置、聊天、记忆或 Keychain 项目。M1b 默认显示重新设计的桌宠页；尚未接入的其他业务入口明确未迁移。已登记且与显式开发目录匹配的实例可逐个启停，最多同时三个；各自新建隔离 profile，不恢复上次运行、不接管旧实例。启动会应用该实例已保存的尺寸、全屏隐藏策略、位置和行为；运行中可单独应用已保存偏好，并临时显示/隐藏自有窗口。拖拽松手位置由该实例 worker 经固定版本事件交给服务单一写入者，持久化成功才更新配置 revision；UI 分开展示保存值、运行时反馈和失败，后台位置 revision 更新会保留未保存草稿。会话暂停状态仅在服务进程内易失；暂停同步关闭门禁，停止本服务拥有的实例和独立诊断播放器，拒绝启动、显示和偏好应用，但保留停止清理和配置保存。停止未确认则保持 `stop-unconfirmed`、继续占槽且不允许解除；成功解除仅解锁、不自动启动。任务读取已接原生授权和暂停撤销；真实读源验收及旧客户端启动/观察模式恢复仍待办。高级页另保留独立诊断播放器入口。Windows/Linux 实际播放器仍 blocked。未提供热更新服务器；不要把 Vite 开发服务器暴露给页面以绕过当前 CSP。

输出为 `apps/desktop/dist/`（忽略项）：`main.cjs`、`preload.cjs`、`ui/`、`branding/` 产品 PNG 与状态栏模板、`runtime/worker.py`、`runtime/guardian.py`、`runtime/player_worker.py`、`runtime/player_protocol.py`、`runtime/player_adapter.py`。服务另输出到所属 workspace 的 `apps/app-service/dist/entry.cjs`，桌面包以 `workspace:*` 依赖并通过包导出解析入口，Fastify 始终由服务包自身解析，不依赖根目录提升。构建全部写入本次 `.local/cross-platform-build-*` 暂存目录，完成所有编译/资源复制后才备份并替换两个 workspace 的 dist；普通失败逆序恢复旧目录，若连恢复也失败则保留备份位置供人工恢复。同一 checkout 不应并发执行构建；这不是掉电/进程强杀时两个目录的原子事务。这是依赖当前 checkout `node_modules` 与系统 Python 的开发构建，**不是独立安装包**；缺少独立发行所需的 Python、许可证归集、签名、公证和更新流程。

## 3. 模块与安全边界

- `apps/workspace-ui`：React/CSS；不拿端口或凭证，不直接读文件/启动子进程。
- `apps/desktop`：Electron 主进程；保留 `snapshot()`、`probeRuntime()`、`startPlayer()` 与 `stopPlayer()` 四个无参方法；`pets` 固定方法按实例传 revision/ID，显隐另传布尔值；不传显示偏好、路径、任意命令或环境变量；有界输入校验见第8节。
- `apps/app-service`：utility process；Fastify 仅绑定 `127.0.0.1` 随机端口，使用每会话随机 Bearer 凭证，拒绝 Origin/非预期 Host/多余参数，不开放 CORS、不记录凭证或原始异常。workspace 生命周期协调器只创建可信开发包白名单对应的运行时，最多三个；运行态不持久化，关闭时独立回收全部自有实例并排空配置存储。
- `packages/contracts`：协议版本、状态快照、运行时形状校验、平台能力声明。
- `apps/runtime-bridge`：诊断及新开发播放器的协议/生命周期装配层；复用 `apps/pet-runtime` 的 prepared 播放器，不重写画面/物理，不计入现有冻结 helper 指纹；不是自带源码/素材/依赖的独立播放器发行包。

界面来自 `pet-app://workspace/index.html` 与受限打包 JS/CSS；拒绝导航/弹窗/webview/权限请求，CSP 禁止网络连接和远程代码。应用服务父子引导经 IPC，不把会话凭证放进命令行、URL、页面或日志。首次 Python 诊断必须显式点击，失败不会修改任何旧运行状态。Node 启动独立标准库 guardian，由 guardian 创建实际 worker；父服务异常死亡时，guardian 通过 stdin EOF 独立获知断开并有界回收自有 worker，不依赖已经死亡的服务执行清理。stdout 在拼接前检查 4096 字节上限，协议失败后清空缓冲并只排空后续输出，不继续累计。关闭先取消运行时，再排空 HTTP 请求并退出，防止等待活动请求而无法执行清理。

## 5. 后续迁移顺序（以用户最新决定为准）

用户指定先完成页面再接余下业务。九个入口已具备 React 界面，现有桌宠、聊天与模型管理照常运行在既有开发边界内。下一批先从新实例绑定的角色资料桥开始，随后按下列产品范围推进；资料和能力未接入的操作继续禁用。

1. **配置/实例与工作区基础**：先盘点旧功能及数据格式，建立 TS 领域、隔离存储与重新设计的 React 页面。仅存储的设置不得标为已应用。
2. **macOS 桌宠闭环**：在已有 stdio 开发桥上逐项迁多宠、偏好、素材管理和暂停/显隐等行为；保留异步解码、物理与线程边界，不先重写播放器。
3. **角色、记忆、模型与聊天**：保留身份/知识/审核/撤回/上下文与安全存储；多厂商扩展另行审阅，不作为旧功能迁移前置。
4. **任务、语音与宿主交接**：迁只读任务适配、额度显式查询、现有 macOS 语音链路、启动视频/窗口同步/状态栏/CLI；默认使用合成数据，真实资料/账号/设备/桌面验收另获授权。
5. **macOS 替代门槛**：各功能、数据导入/回退、冷启动/退出、多屏/Space、资源和发行分别验证；达到门槛后才退役 Swift。
6. **再恢复 Windows/Linux 播放器与发行**：异步解码/窗口、旧平台依赖、Wayland 限制及打包阻塞继续明确记录，不在当前阶段移植。保留三平台合成 CI，不用它冒充真实平台验收。

阶段退出条件及数据唯一写入策略见[macOS 功能迁移清单](macOS功能迁移清单.md)。这份顺序修正取代此前“先移植 Windows/Linux 解码/窗口再迁业务”的安排，但不更改历史测试结果，也不代表上述业务已完成。

## 6. Qt 接入启动前检查（不打开桌面）

```bash
pnpm run check:qt
# 指定已有 Python 环境，不安装或变更它：
PET_PYTHON=/path/to/python pnpm run check:qt
```

该命令使用 `-I -S -B` 运行 `apps/runtime-bridge/qt_preflight.py`：禁用自动 site 初始化、`.pth` 与 `sitecustomize`，通过解释器旁的 venv 标识与 `sysconfig` 明确包目录，以 PathFinder 只发现顶层 `PySide6` / `PIL` 包、检查 Python 3.10+ 和仓库内三个既有多宠适配器源码文件是否存在。不导入 Qt/PIL/播放器、不创建 QApplication、不连接旧 socket、不读写真实 profile，不安装依赖、不读取素材内容或验证字体。Node 入口不继承模型密钥和 Python 注入环境，设置 5 秒超时与 4096 字节输出上限，严格校验并重建固定 JSON 结构/枚举和退出码，拒绝额外文本/字段。只发现解释器自身明确包目录；venv 以有界读取的 `pyvenv.cfg` 判断，只有显式 `include-system-site-packages=true` 才额外发现基础解释器的系统包目录。不执行 `.pth`；依赖 `.pth` 或用户 site 的可编辑/间接安装可能保守报告缺失，需使用直接安装依赖的可信环境。PowerShell 用 `$env:PET_PYTHON = 'C:\path\to\python.exe'` 指定解释器。

输出为无绝对路径的 JSON，`status=prerequisites-found` 仅表示本检查涉及的必要条件找到，**不是可启动/已集成**。模块可发现不保证动态库能加载、版本兼容或 WebP 可解码；上游 `pet.py`、素材指纹、字体授权、Qt 原生库和真实窗口仍需分别验证。`desktopStarted`、`nativeModulesImported`、`playerIntegrated` 始终为 `false`。

退出码：**0** 为上述检查满足，**2** 为缺依赖/源码、Python 版本不足或当前平台存在明确阻塞，**1** 为解释器/检查执行失败。`check:cross-platform` 只执行合成环境下的预检回归，不要求 CI runner 安装 PySide6，不将环境阻塞算作测试通过。当前默认本机 `python3` 未发现 PySide6 时会返回 2；不会擅自向其安装软件。本机若已有旧播放器构建环境，可显式用 `PET_PYTHON="$PWD/.local/pet-build/venv/bin/python3" pnpm run check:qt` 只读检查该环境；这不修改 venv，也不隐式将其设为产品默认解释器。

现有 `pet_instance_ipc.py` 使用 `os.getuid()`、Unix socket、POSIX 权限及路径约束，**不能直接当成 Windows 控制通道**。预检在 Windows 明确返回 `legacy-ipc-needs-port`，即使模块均可发现也不绿灯。后续需提供受限、会话鉴权、只管理自有 helper 的跨平台传输；不能用提升权限/放宽权限检查绕过。Linux 会话环境只作提示，Wayland 限制仍保留，`DISPLAY` 不能证明 XWayland。该预检保持只读及历史 legacy IPC 阻塞语义；新的 stdio 桥绕开旧 IPC，但不会据此解除既有解码/窗口的平台门禁。两者都不修改冻结 helper 输入，不触发旧 helper/宿主重建。


## 7. 单宠开发播放器（显式操作，非发行入口）

设计与执行清单见[stdio 桥设计](superpowers/specs/2026-11-16-player-stdio-bridge-design.md)及[实施计划](superpowers/plans/2026-11-16-player-stdio-bridge.md)。默认 `player.status=unconfigured`，诊断仍可独立使用。只有 Electron 主进程读取开发者显式指定的 `PET_PLAYER_SOURCE`（prepared app 源码目录）和 `PET_PLAYER_ASSETS`（含素材清单的目录），二者须是可信绝对路径；不自动寻找或构建，不允许页面或 HTTP 选择路径/脚本。源码本身是会执行的可信代码，不是可任意下载的插件沙箱。

获得真实预览授权后，可用以下参数打开工作区，再手动点击“启动开发桌宠”（本轮未执行该启动命令）：

```bash
# 交互输入已审核的真实素材目录；不要把示例占位路径当作真实目录。
printf '请输入已审核素材目录的绝对路径：'
IFS= read -r PET_PLAYER_ASSETS
if [ "${PET_PLAYER_ASSETS#/}" != "$PET_PLAYER_ASSETS" ] && [ -f "$PET_PLAYER_ASSETS/素材清单.json" ]; then
  PET_PYTHON="$PWD/.local/pet-build/venv/bin/python3" \
  PET_PLAYER_SOURCE="$PWD/.local/pet-build/generated-source/app" \
```

### 生命周期、安全与状态

- 流程为固定 `POST /v1/player/start` / `stop`（仅空对象）→ 自有 guardian → Qt worker，匿名 stdio 管道、不使用旧 Unix IPC/registry/fcntl，不开放新的公共控制端口。
- 私有播放器协议 **v3**：bootstrap 固定 version / session / id / command / config，preferences 必含有界 size、hideInFullscreen、scheduledActivity、movement，并可含完整有界 x/y 坐标对；后续固定 status / stop / apply / apply-behavior / show / hide。apply 只收 size/hideInFullscreen；apply-behavior 只收两个行为布尔值。每帧最多 4096 字节、64 hex 会话、32 hex 请求 ID、重复字段拒绝，旧版本拒绝（需一并重建新栈服务与 worker，不更改冻结 helper）。请求回复固定 version / id / ok / phase；正常清理后可发固定 `{version:3,event:"stopped"}`，拖拽回报固定 version/event/x/y；均无私有路径/凭证/原始异常。标准库诊断协议仍为 v1。
- `player` 为可选公开快照（兼容仅诊断的旧合成夹具）；固定 kind/status/detail，状态有 unconfigured / blocked / stopped / starting / running / stopping / error。running 要等待可见窗口与真实首帧，停止要等待适配器 stopped 确认及进程退出，不把已发送命令或兜底强杀当正常成功。停止超时/未确认会保留 error，close 拒绝，并由服务非零退出传回壳层。启动合并，停止/关闭能取消 pending start；错误后不自动重启。
- 每次启动新建 `AnimeDesktopPets/cross-platform-dev/player-sessions/session-*`，HOME、USERPROFILE、XDG、BAILONG_DATA_DIR、CODEX_HOME 指向该会话子目录；不读旧资料，不继承模型凭证、任务租约、Python 注入变量或旧素材库环境。会话目录目前保留供开发诊断，不自动删除历史目录；不应在其中保存真实聊天或密钥。
- 新进程复用 `pet_helper._factory`，不引入旧 `InstanceController/Store`。进程内替换账号/气泡网络客户端和上游菜单，仅保留本地动作、拖拽与停止；隐藏旧托盘，禁用额度、聊天、任务、语音及声音。窗口/信号/停止/删除均留 Qt GUI 线程，stdin 线程只投递有界队列。
- guardian 的 player 模式在父端 EOF 后给予 2 秒清理宽限，再 terminate / kill 自有 worker；诊断时限仍独立。转发线程可阻塞，但监督线程不依赖其完成即可回收；输出线程排空最后回复。不是对外部进程进行扫描或终止。

### 固定业务桥与安全

原有四个无参方法保留；`DesktopBridge.pets` 使用固定方法 `list / importPackages / add / clone / delete / save / setTheme / start / stop / applyDisplayPreferences / applyBehaviorPreferences / setVisible / pause / resume`。`importPackages()` 不接收任何参数：Electron 主进程打开系统文件面板并保留源路径，再将最多16项选择交给本地服务；服务端只对这些明确选择逐项校验和导入。renderer 仅收到基名、导入状态与 `{id,version}`，无路径回传接口。导入路由只由主进程使用随机会话凭证访问，不暴露给 renderer。主进程校验可信主 frame、准确参数数量与字段；服务端再次校验。启停输入只含 `expectedRevision` 和实例 ID，不写入存储 revision；导入 catalog 也不增加配置 revision。运行阶段易失，失败/未确认退出保守占用运行槽；不允许任意 URL/IPC/脚本/路径。认证、Host/Origin 拒绝、CSP 与禁止远程导航不变。

## 12. 多厂商协议核心（2026-11-18，内部第一段）

源码在 `apps/app-service/src/models/`，按 `config.ts`（纯配置／路由）、`common.ts`（规范消息／受限工具／原生私有回放）、四个协议文件、`protocols.ts`（固定注册表）、`client.ts`（有界传输）拆分。实施范围见[首段计划](superpowers/plans/2026-11-18-model-protocol-core.md)；原独立设计继续作为分层默认、凭证引用和跨协议历史的依据，不复制旧单服务数据模型。

- schemaVersion=2，最多32连接、每连接33模型、总配置1MiB；稳定连接／模型条目ID与 API 模型ID分开，显式双层默认，不按品牌猜协议或工具能力。凭证字段只接受每连接独立、不可变版本的 opaque 引用，不接收密钥正文；允许先保存缺Key配置，在线调用在读取凭证前明确阻止。URL保留部署前缀，不猜版本；远端要求HTTPS，只有精确回环主机可显式免鉴权。
- `ModelClient` 在首次 await 前固定路由、兼容项、用途预算和消息；只有显式调用才从注入接口读取该版本凭证。文字2048 token／60秒、语音160 token／25秒；已知输出上限只下调，不猜上下文容量。最多3个活动请求，不排无限队列；请求128KiB、单响应1MiB、发现累计4MiB／8页／256模型。发现仅输出候选，不改目录；超过分页边界显式标为 truncated，字节／格式错误则整体失败。
- Chat Completions／Responses 使用各自字段；Anthropic固定版本头与独立消息块；Gemini独立contents与函数结果。工具需已声明、能力已确认并与调用配对；不执行任何工具，也没有自动循环。原生推理、签名和必要item信息只存在WeakMap，绑定连接／协议／模型／地址／凭证版本与路由指纹；跨协议或原路由变更只编码公共历史，改动规范消息会使私有回放失效。
- 取消、关闭和超时拒绝迟到结果，等待凭证也计入超时；流式读取仅为有界接收JSON，不是流式聊天功能。拒绝HTTP重定向和自动重试，401／429等只回固定错误，不附带URL、响应正文、Key或cause。
- **协议核心本身不挂载 HTTP／IPC／renderer 入口，也不打开安全后端。** 配置磁盘写入与凭证注入见第13节，macOS 安全后端与可信管理桥见第14节。双层管理页见第15节；发现候选合并、临时模型选择和在线请求仍待接线，正式聊天继续禁发。旧 Swift 直连和回退保留；不自动导入旧账号或资料。

## 13. 安全凭证边界与原子配置（2026-11-18，内部第二段）

按[本段计划](superpowers/plans/2026-11-18-model-secure-storage.md)继续独立多厂商设计；不改原稿、不导入旧格式、不接UI。本段先在服务内部实现与合成验证，macOS后端与可信管理桥接线见第14节。

- `credentials.ts` 的 `SecureCredentialBackend` 是可信宿主的安全存储端口：固定 `local.anime-desktop-pets.models.v2` service、随机不可变account、仅新增不可覆盖；没有后端返回固定不可用错误，不读环境变量、不调用携Key的命令、不写明文文件。Key只进安全后端及内部在线请求；读取还核对快照connectionID与封装归属，交换磁盘引用也不能串Key。列表、配置读取和保存缺Key配置不读安全库。
- `configuration-store.ts` 只操作可信宿主显式给定的新隔离目录内 `model-providers.json`；schema v2／32连接／每连接33模型／1MiB，目录0700、文件0600、同用户、单硬链接，逐层拒绝symlink，打开后复核inode／dev与变更。macOS通过固定只读 `/bin/ls -lde` 保守拒绝全部ACL；输出不进日志或renderer。Windows没有可信ACL核验器时明确阻塞，不能以mode位伪称私有。
- 损坏／未知版本／非法UTF-8／超限／读取错误不回空；已观察到的文件消失也拒绝初始化。只在新目录且文件确实未存在时返回空配置。写入独占临时文件、显式fchmod并核验0600／所有者／链接数、fsync，短期排他 `.models-writer.lock` 内重新读取、核对原inode和bytes，最后rename；不抢占残留锁，不把钥匙串／网络等待放入写锁。
- `repository.ts` 只接受不含credentialRef的连接草稿和显式keep／replace／remove凭证操作；先完整校验，锁外准备新项目，再锁内检查连接revision并合并其他连接。全局默认连接与连接默认模型在一笔提交内更新；清空全局默认必须显式操作。新连接revision使用该次全局发布序号，重建同ID也不让旧编辑revision复活；磁盘连接revision不能超过全局序号。
- rename是生效点：发布立即更新内存／撤销门禁，再等待目录同步；目录fsync失败返回 `durability: unconfirmed`，不删已引用凭证。替换适配器若已rename再报错，按准备inode＋精确内容复核；不能确定是否发布时返回 `publication_uncertain`、保留新项目并关闭旧在线状态，不能谎报回滚。确认发布前失败保留旧配置／旧Key，新增未引用项目清理失败单独为pending。
- `createClient()` 为内部异步方法，先在短写锁内获取独立 `.models-online-owner.lock` 所有权标记并重新加载配置。该标记覆盖本profile的在线客户端和写入者：其他仓库可读但提交busy，即使共享store也不能借用私有令牌；所属仓库仍只在短期写锁内发布，不因请求等待长期占用配置写锁。并发关闭共用释放流程，等待本仓库操作结束后在短写锁内按inode释放标记，失败保留所有权供重试；残留标记不自动接管。第三段生产管理服务使用离线仓库，尚未创建在线客户端。
- 删除全局默认连接必须明确替代连接或清空；删除在途凭证读取／请求／发现立即取消，忽略不遵守abort的迟到结果，不回退另一厂商。普通保存保留原请求快照。旧／已发布凭证版本保守保留，不自动GC，也不宣称删除连接已删除Key；返回 `retainedCredentialVersions`。失败清理仅接受本vault签发、尚未发布的所有权句柄，不枚举钥匙串。

定向回归仍为 `pnpm exec tsx --test --test-concurrency=1 apps/app-service/test/model-*.test.ts`。全部使用临时目录、合成凭证与注入后端／假fetch；不触发真实系统安全库。管理桥和后续接线必须继续限制固定方法，不向renderer开放任意路径、URL、Header、命令或环境变量，不能将本地保存成功显示成连接成功。双层折叠／内联编辑／逐连接草稿与正式聊天仍待接入，真实连通性和费用另获授权。

## 17. 角色与语音／直播旧格式读取（2026-11-18）

`apps/app-service/src/migration/` 提供纯字节读取器，未挂载任一 HTTP、IPC 或旧角色目录导入入口；单个用户所选知识文本的独立预检见第 22 节。身份 Markdown 支持 schema 1–2，记忆 1–4、目标 1–2。保留旧条目 ID、时间、修订、来源、确认状态、目标步骤和历史分享值；调用方提供缺失身份时间的固定基准。拒绝超 64 KiB、无效 UTF-8、未知版本、歧义元数据/标题和错条目 ID。任何后续导入仍须验证目录、路径、跨角色归属与凭证样内容，隔离旧根并预检冲突。

旧语音／直播 JSON schema 1 读取平台、房间、文字展示、两项独立朗读选择和旧自主气泡同意代号。旧音频路径、书签和麦克风 UID 只在本函数内校验，不随记录返回；转写与历史偏好只列为待重新确认的材料。解码不授权任何在线或设备动作，也不改变工具链、桌宠和聊天页。固定桥及已完成的 Product Design 页面迁移见[新工作区迁移交接](新工作区迁移交接.md)。


## 18. 新实例角色资料隔离仓库（2026-11-18）

`apps/app-service/src/characters/` 是内部服务模块。可信调用方提供新 profile 下的私有根和新实例 ID；每实例只有一个 schema 1 快照，文件自身也校验实例归属。快照最多 1 MiB、64 条记忆、32 项目标、每个身份或记忆当前版本之外最多 5 个历史版本。目标及步骤由服务分配稳定 ID，只记录进度。身份可恢复为一个新版本；记忆按候选、确认和撤回流转，改内容或恢复旧版本都需重新审核。相同身份／记忆草稿不落盘，不消耗历史。疑似凭证检测覆盖记忆正文、来源、引用和版本；这是有限启发式。过期、重复或同依据的冲突知识不能通过确认。新格式没有线上分享或后台执行字段。

仓库复用私有目录校验：POSIX 根 0700、普通文件 0600，拒绝符号链接、硬链接和 macOS ACL。写入按预期实例版本串行，短排他锁内校验原文件，临时文件同步并核对后原子替换。临时目录故障解除后，只有还持有锁的仓库可以重试清理；关闭时会再次尝试；若此时仍不可用，调用方可在故障解除后重试关闭，仓库保持停止写入。不会接管前一进程的残留锁。损坏、未知版本、非法编码和已观察文件消失均不会退回空配置。替换后目录同步失败单列为未确认；替换结果不确定时只读核对，当前实例写入停止，不自动重试。Windows 私有 ACL 验证未实现；无明文权限降级。

角色仓库已将身份读写和历史恢复、记忆人工审核／编辑／历史恢复及目标计划接入 HTTP 与 Electron IPC，见第 21–22 节。接线验证当前实例归属和生命周期，阻止克隆共用或删除后访问资料；旧格式读取不能直接成为新资料或授权。详见[实施计划](superpowers/plans/2026-11-18-character-local-storage.md)。

## 20. 自有桌宠气泡播报（2026-11-18）

- Apple 芯片 Mac 开发 checkout 复用 `.local/voice-runtime/venv/bin/python` 与 `.local/voice-runtime/models/Qwen3-TTS-12Hz-0.6B-Base-8bit`，由可信主进程检查；缺少环境时语音页显示不可用。不开启录音、不下载模型、不配在线 Key。启用仅表示允许处理下一条互动气泡，不代表模型、声卡或实际听感已经验收。
- 固定 `speech` 桥只允许查状态、无参选择／移除参考 WAV、提交准确逐字稿启用、停止。路径由系统选择器交给服务，页面只收状态和参考是否就绪。参考须为普通 PCM WAV（1–30 秒、≤6 MiB、16 或 24 bit、单/双声道、8–48 kHz）；逐字稿上限 4096 UTF-8 字节。资料不写入普通配置，输入经 app 私有临时目录交给工作进程，逐字稿被读取后删除，语音进程退出清理参考副本。关闭应用后重选重开。用户明确要求时可通过系统选择器重新选择旧版使用的同一份合规 WAV，并填入它对应的逐字稿；不会载入旧版的书签、设备设置或同意。
- prepared Qt 回调在自有播放器运行、可见且未被任务门禁抑制时，发私有协议 v3 可选 `bubble-speech` 事件（120 个 Unicode 标量与 512 字节上限）；不改变既有 reply 和首帧／停止确认。只有服务认可的当前运行来源能入队，至多一条正在处理和一条最新候选。停宠、服务关闭、会话暂停会拦截迟到事件并回收播报；停止未确认时保守报错，可重试。每个语音 worker 使用固定本地 TTS 及音频输出，空闲 90 秒回收。
- 仅用合成 WAV、假模型、假音频输出和 Fusion/offscreen 验证，未启动真实 Electron/Qt 桌面、未合成真实音频或使用真实设备。语音对话、在线气泡和历史设置仍不接入。详见[实施计划](superpowers/plans/2026-11-18-pet-bubble-speech.md)与[验证记录](实际验证记录.md)。

## 21. 角色身份保存与恢复（2026-11-18）

## 22. 记忆审核、编辑、历史恢复与目标进度（2026-11-18）

- macOS `characters` 桥增加 `readMemories`、`addMemory`、`confirmMemory`、`withdrawMemory`，以及 `readGoals`、`addGoal`、`editGoal`。主进程校验主框架和请求，回环服务鉴权后通过实例注册队列读写。写入携带当前角色快照修订；请求上限 256 KiB，响应上限 1 MiB。记忆与目标各自只返回本页所需记录，不返回身份、记忆历史、路径或权限字段。
- 记忆页分别读取个人记录与角色知识；添加只进入待确认，确认和撤回为显式操作。知识必须有来源，有效期按所填日期的 UTC 日末解释。仓库拒绝疑似凭证，确认时拒绝已过期、重复或同依据的冲突知识。已确认只是本机审核状态：允许第 23 节的显式本机查询，不授予外发许可。
- 目标页可新建和编辑，手动勾选步骤、修改状态后须明确保存。服务为新目标／步骤分配 ID，并拒绝编辑时混入其他目标的步骤 ID。草稿和落盘进度分开展示。冲突或未确认写入需要先重读；同一目标有更新时保留旧草稿供核对，禁止覆盖。保留逐实例草稿，删除实例后丢弃迟到结果。
- `readMemoryHistory` 只按当前注册实例及显式条目 ID 读取，最多五个版本，响应上限 256 KiB；当前列表仍不返回历史。`editMemory` 与 `restoreMemory` 使用同一原子仓库，写入须携带当前全局修订，恢复另传条目历史修订。等值编辑不写盘；内容变更及恢复保留条目 ID、生成新版本并回到待确认。
- 页面沿用共享表单，在当前分类内编辑；另一份新增草稿保留。历史内联预览，编辑未结束不能恢复。切换实例不显示旧预览，删除后拒绝读写。冲突或未确认结果先重读，若同条内容已更新，旧草稿仍可查看和复制，但不可覆盖。
- 「角色知识」的 `selectKnowledgeFile()` 通过 macOS 可信主框架无参 IPC 打开原生单文件选择器。主进程只接受 `.txt`／`.md` 普通文件，拒绝符号链接和非普通文件，限制到 32 KiB、50 段、每段 1,000 字符；按空行分段，原样重复段合并，坏 UTF-8 和疑似凭证整份拒绝。仅将段落返回页面，文件名、路径和文件异常不跨桥；Markdown 前置属性只是文本。
- 预检逐实例保存在窗口内，用户补充来源后显式提交。填写引用时为各段加位置。`addKnowledgeBatch` 经固定桥与 `POST /v1/characters/:id/memories/import`，使用预期全局修订、权限隔离及一次原子写；容量、过期、当前／批内重复和同依据冲突拒绝整批。未知结果重读后重新预检，勿自动重放。入库为待确认，仍由用户逐条审核。见[知识预检计划](superpowers/plans/2026-11-18-knowledge-file-preflight.md)。
- `characters.searchKnowledge` 只接受当前实例 ID、已读全局修订和最多 120 UTF-16 单位的关键词。固定鉴权回环 `POST /v1/characters/:id/memories/search` 不读写其他实例，也不更新本机资料；关键词放在请求体，双向上限 2 KiB。先排除个人、待确认、已过期、疑似凭证及同依据未解决冲突，再按完整短语、关键词覆盖、创建时间与稳定 ID 排序。正文、来源、引用和版本均可匹配；回包只含同一修订的最多三个 ID。
- 记忆页使用同一快照显示检索结果正文和已有依据；切换实例／栏目、重读或发起写入时清空。未命中和失败分开提示，迟到结果不能回填，过期条目自动从搜索结果移除。详见[本机知识召回计划](superpowers/plans/2026-11-18-local-knowledge-recall.md)。
- 记忆／目标删除和聊天内的显式本机查询见第 23 节。逐项在线文字聊天授权另见第 24 节。旧角色目录导入、自动审核、生成建议及后台执行尚未开放。详见[审核与目标计划](superpowers/plans/2026-11-18-character-memory-goals.md)、[记忆版本计划](superpowers/plans/2026-11-18-memory-edit-history.md)与[实测](实际验证记录.md)。

## 23. 本机记忆／目标删除与聊天查询（2026-11-18）

- `deleteMemory`／`deleteGoal` 走已有的实例注册队列与私有原子仓库。固定鉴权路由 `POST /v1/characters/:id/memories/delete` 和 `POST /v1/characters/:id/goals/delete` 要求条目 ID 与预期全局修订。成功后分别移除当前记忆及其历史、目标及其步骤。页面在条目下确认，默认焦点为「保留」，Esc 取消；重读、写入和导航作废旧确认。冲突或写入结果未确认时先重读，不显示成功。删除不等于擦除备份或既有内存回复。
- macOS 聊天只响应 `你是谁`、`查看目标进度`、`查个人记忆：关键词`、`查角色知识：关键词` 四类显式输入。主进程和回环鉴权路由 `POST /v1/characters/:id/chat/local-context` 校验固定请求与实例；请求最多 2 KiB，响应最多 16 KiB，正文最多 4,000 个 UTF-16 单位。服务读取当前实例最新保存的资料快照，身份取名称与角色定位；目标最多三条，进行中的目标可列下一步；记忆仅匹配已确认内容，角色知识另按依据、期限和冲突过滤。疑似凭证不回显。
- 本机查询和答复只存于该窗口的内存会话，均排除在 `requestHistory()` 之外。停止等待、切角色或离开聊天后，迟到的答复不会写入；删除后的新查询不再召回该条目，已显示的答复可通过「清空本轮聊天」移除。逐项授权只保存本机，见第 24 节；在线发送和选模另见第 25 节。见[本批计划](superpowers/plans/2026-11-18-character-record-delete-and-chat-context.md)及[实际验证记录](实际验证记录.md)。

## 24. 在线文字聊天授权与服务端上下文（2026-11-18）

- 现有身份、记忆和目标页新增内联授权确认，列出用途与可用字段；默认焦点为「取消授权」，Esc、换页、切分类和重读作废未确认选择。撤回单独执行。确认入库与在线授权分开；普通草稿、历史、旧档案和其他实例无权授予或继承。更改内容、恢复旧版本或撤回审核后关掉原授权；相同内容保存保留原状态。授权不联网，不更改内容修订号，仅增加该实例的全局修订。

- 内部 `prepareOnlineChatContext` 在实例注册队列内读取最新快照。已授权身份只取名称、身份定位、性格、表达方式及边界；个人记忆只取正文；知识取正文与来源／引用／版本；目标只取相关标题、状态与步骤计数。检索在排序前排除未授权、无效及疑似凭证记录；知识的依据冲突即使另一条未授权也要排除。个人记忆、知识和目标各最多三项，以不超过 6 KiB 的 JSON 组装，不截断记录或证据。本机查询指令不进入该准备流程的上下文。
- 上下文只作数据，不通过 renderer 接口直接返回。出站时按第 25 节绑定角色修订与所选路由。见[本批计划](superpowers/plans/2026-11-18-character-chat-sharing.md)和[实际验证记录](实际验证记录.md)。


## 25. macOS 聊天选模和在线发送（2026-11-18）

## 26. macOS 模型连接测试（2026-11-18）

- 在已有连接卡片点「测试连接」，核对已保存地址、当前草稿默认模型 API ID 和可能计费提示，再确认发送一次。新连接或地址、协议、认证、凭证有变动时须先保存；可先测试草稿里的默认模型、输出预算和兼容项。保存、目录发现、测试各自独立。
- `model-probe.ts` 定义固定契约，经 macOS preload、可信主帧和鉴权回环 `POST /v1/models/test` 到服务。服务只取指定版本的连接和凭证，读 Key 后与收回复时再次核对版本。四协议共用有界请求核心：固定短提示、最多 32 输出 token、15 秒、64 KiB 回复，无工具、聊天或角色资料，不重试、不写配置，不返回厂商正文或原始错误。
- 改动草稿、保存、删除、取消编辑或离页会使相关旧结果失效；单纯折叠保留状态。可停止等待，但已出站请求仍可能由厂商处理和计费。有效文字只证明该次生成收到可用回复。
- 仅以合成凭证和注入后端验证，真实授权、服务及费用另验；未保存 Key 探测仍待迁，连接测试独立于第 27 节的合成验收预算。见[实施计划](superpowers/plans/2026-11-18-model-connection-test.md)与[实际验证记录](实际验证记录.md)。

## 27. 合成模型验收预算账本（2026-11-18）

- `ModelAcceptanceLedger` 仅供可信合成验收代码使用。新批次由调用方在单独授权后，选定已有且空的私有目录、明确批准 12 次并固定路由指纹。记忆批次、表达、语音和气泡共用这 12 次，按序号与固定用途登记；不存提示、地址、回复或凭证。相同路由的后续操作重开同一账本；旧 Swift 账本和锁保持原样，不读入、重置，也不能另开账本延长已批准批次。
- 持久守卫绑定账本和路由，持久化时排队、独占写锁、私有临时文件同步、原子替换和目录同步。落盘确认后才调用一次注入操作，失败或取消不退还；发布不明确时不调用，已写入的次数保留。缺失一边、损坏、未知版本、路径或权限不安全、残留锁均拒绝操作。
- 本批仅有内部预算和合成测试，不增加验收 CLI／服务路由、IPC、页面或真实凭证读取。聊天、发现和「测试连接」均不使用此额度。账本校验调用方提供的路由指纹；未来 runner 须在同一可信入口固定合成夹具和实际发送路由，只调用一次模型客户端。账本不识别所有者手工恢复的有效旧快照。真实 runner 移交及可能计费的验收另做。见[实施计划](superpowers/plans/2026-11-18-model-acceptance-budget.md)和[实际验证记录](实际验证记录.md)。

## 28. macOS 工作区状态栏与启动状态（2026-11-18）

## 29. macOS 外部客户端只读观察（2026-11-18）

- 从原生状态栏选「开始观察 Codex」，开启后立即读取一次，前一次完成 10 秒后再读。开关仅本次会话有效、默认关闭；关窗隐藏不会改动显式开关。选「停止观察 Codex」立即取消后续读取、丢弃迟到结果。退出等待正在执行的自有探针收尾。
- 可信主进程调用开发产物中的固定 macOS 助手 `codex-presence`，只查询旧宿主配置使用的固定 bundle ID `com.openai.codex`。无 shell、无自定义参数，单次最多等待 1.5 秒，输出有界。AppKit 查询只形成检测到／未检测到两种结果，超时、错误或协议异常均显示「状态未确认」，不会把失败当作未检测到。结果不持久化，也不通过 preload、IPC 或 HTTP 暴露。
- 观察结果不代表窗口就绪、任务活跃或桌宠联动。此功能不读任务、账号、窗口或旧资料，不申请权限、不启动或控制 Codex。离线冒烟只验证无效参数被拒绝。真实验收时，用户自行选择客户端运行与退出的安全时机，核对状态变化、隐藏后停止、重启默认关闭及退出无剩余探针。见[实施计划](superpowers/plans/2026-11-18-external-client-observation.md)和[退役清单](macOS旧宿主退役清单.md)。

## 30. macOS 显式启动 Codex 与本地启动动画（2026-11-18）

- 使用 `pnpm run dev:desktop:codex` 启动开发工作区并明确请求打开 Codex；如果工作区已经运行，从原生「Codex」菜单或状态栏选「打开 Codex」，不另起工作区。普通 `pnpm run dev:desktop` 不请求启动外部客户端。
- 可信主进程先读取固定 bundle ID 的一次存在性，随后用固定 macOS 系统命令打开该 bundle。冷启动时并行加载本机 `resources/media/startup.mp4`；已运行或存在性未确认时不覆盖现有画面。系统命令成功只表示打开请求获接受，不能确认窗口已加载。没有可用素材时照常打开 Codex；不读取旧路径设置，也不自动启动任何桌宠。
- 启动动画在独立沙箱窗口播放原视频和音轨；没有 preload 或新增 renderer IPC。只向独立内存分区提供固定页面与流式 MP4，限制本地视频为 128 MiB 的普通文件，拒绝符号链接。播放器确认开始后非激活显示；8 秒未开始、30 秒总超时、播放失败、渲染进程退出或宿主退出均清理。点「跳过」（窗口获得焦点时也可用 Esc 或 Cmd+.）只关动画，不取消已提交的打开请求。重复点击不会叠播，也不会自动重试系统请求。
- macOS 开发构建能复制现有本机原片及其来源说明，干净 checkout 缺视频也能构建，不新增媒体分发授权。视频先在指针所在屏幕居中。首帧显示后，主进程用独立的无参 `codex-window-bounds` 短时读取固定 Codex 进程的可见窗口框，不查询标题、内容或任务，不申请权限。只接收最多 64 字节的整数矩形，每次最多等待 750 毫秒，总计最多 12 次、8 秒，并丢弃动画关闭后的迟到读数。连续两次匹配到同一几何且完整落在唯一工作区内，才将 16:9 动画窗对齐一次。跨屏、整屏、读取失败或目标不明确时保留居中。
- 动画对齐不修改 Codex 的窗口或焦点，也不扩展状态栏观察或 renderer 桥。实际画面、原声、冷／热启动、焦点、多屏／Space 尚待实机验证；旧宿主通过 AX 调整外部窗口仍待迁。见[视频计划](superpowers/plans/2026-11-18-codex-startup-video.md)、[对齐计划](superpowers/plans/2026-11-18-codex-startup-window-alignment.md)和[旧宿主退役清单](macOS旧宿主退役清单.md)。

## 31. Codex 任务租约（2026-11-18，服务内部）

- `PetWorkspace` 持有只驻内存的租约；默认未启用。由可信主进程的「开始读取 Codex 本机任务…」和原生确认驱动，只走固定 utility 消息；「开始观察 Codex」仍只有存在性能力。没有 HTTP、preload 或 renderer 入口。
- 只接受当前会话的 `running` 结果续约。10 秒有效期从开始采样计时（单调时钟）；未检测到、未知或失败立即撤销。探针和读源各自最多一个在途，撤销时通知取消，旧结果不能在重新启用后生效。一轮结束后间隔 2 秒再确认存在性并采样；探针和读源各自有超时，撤销后未确认收尾时不创建第二个读源进程。
- `pause` 在排队等待和停止播放器前即撤销，配置冲突也不自动重获许可；暂停、停止未确认和关闭期间禁止启用。解除只恢复运行门禁。没有写入旧租约、任务文件或 workspace revision。
- 读源仅在 macOS 构建中打包，使用 Python 3.10+ 与 stdin 监护。逐级只读打开系统用户目录下固定 `.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`，拒绝符号链接、非本用户项、硬链接和非普通文件；不接受自定义 `CODEX_HOME` 或归档目录。不改冻结解析器、旧宿主及隔离播放器环境。最多检查 20,000 个目录项、选取最近 64 个文件，每文件每轮最多 512 KiB、总计 4 MiB（含头部）。
- worker 仅返回 `working`、`idle` 或 `unknown`，最多 4096 个活动轮次及非负安全整数开场序号。读取尚未追平或失败时不把该文件计为已完成，菜单只收到状态枚举。见[租约计划](superpowers/plans/2026-11-18-codex-task-lease.md)、[读源计划](superpowers/plans/2026-11-18-codex-task-source.md)。

- 自有实例的生命周期在首帧确认后才把聚合快照投影为私有播放器 v3 `task-animation` 命令；仅发工作状态、进程内开场序号和 6 秒有效期，不发任务身份。读进程重建后的新开场序号继续递增，新加入实例不补播已观测过的开场。命令最多一条等待确认，变化只保留最新待发帧，不占显示、行为或停宠的应答槽；Qt 独立检查超时，旧帧不能延长动画。高级诊断播放器不接此命令。
- Qt 只在 GUI 线程复用 prepared 播放器现有工作调度；没有旧读取器、心跳文件、任务正文、账号或联网。拖拽和松手弹簧、手动气泡、菜单、隐藏、减少动态效果仍优先；未知状态不续期，撤销或过期清除任务门禁及工作气泡，姿态在交互空闲后回待机。真实素材和多宠桌面验收仍待做。见[动画计划](superpowers/plans/2026-11-18-codex-task-animation.md)。
