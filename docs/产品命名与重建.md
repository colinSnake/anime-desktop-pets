### 环境变量

- `PET_DATA_DIR`：隔离宿主本地状态。
- `PET_RESOURCE_DIR`：覆盖宿主资源根目录。
- `PET_DEV_ROOT`：checkout开发资源发现，`petctl.sh` 默认设置为当前仓库。
- `PET_ASSETS_DIR`：指定宿主构建所引用的完整动画素材目录。
- `PET_SKIP_BUILD_CLEANUP=1`：构建时保留历史归档。
- `PET_RUNTIME_PYTHON`：覆盖多宠离线测试的Python路径。
- `PET_TASK_LEASE`、`PET_WINDOW_CONTROL`：宿主与helper内部任务心跳和窗口控制开关。
- `PET_BUNDLE_ASSETS`：helper构建内部使用，用户优先使用 `--bundle-assets` 参数。
- 其他自有构建/图片工具变量也使用 `PET_*`；旧 `DRAGON_*` 名称不读取。

### 保留角色和第三方命名

`apps/pet-runtime/bailong/dragon_*.py` 是龙妹播放、UI、行为等角色实现，保留名称；`white-dragon` 实例ID、`local.bailong.white-dragon` 素材包ID、龙妹专属 `dragon-release/` 与 `dragon-extra/` 素材目录、角色主题ID同理。它们不随用户修改身份名称变化。`BailongPet.app`、固定上游路径、原文许可证和第三方来源标识也不做机械替换。

历史验证记录、历史版本章节和已删除组件的名称是当时事实，不据此恢复旧功能。旧标识可出现在拒绝兼容的测试夹具、冲突检测及本文人工处置说明中，但不会被当成新标识的别名。

## 2. 数据与旧服务边界

数据只使用 `~/Library/Application Support/AnimeDesktopPets/` 或显式的 `PET_DATA_DIR`。不自动读取/搬运 `DragonCodexCompanion`，不创建旧路径符号链接；已有旧目录和文件不删除。当前产品数据目录若本身是普通文件或符号链接仍会拒绝写入，避免误操作其他位置。

新安装/卸载器只管理新Bundle ID、可执行名和LaunchAgent。它们不会替用户卸载旧服务；**重新构建本身不会让已加载的旧服务消失**。请在用户选择的安全时机正常退出旧桌宠，手工停止自己安装的旧LaunchAgent并备份其plist；不要重启或修改官方Codex。旧标签为 `local.dragon.codex-companion.watch`，若曾安装，可由用户在终端执行：

```sh
# 仅在确认旧服务存在、桌宠可以停止时由用户执行；本轮开发不自动执行。
launchctl bootout "gui/$(id -u)" "$HOME/Library/LaunchAgents/local.dragon.codex-companion.watch.plist"
```

已卸载的旧plist应由用户移出 `~/Library/LaunchAgents/` 备份，避免再次登录时加载。其他第三方监视器仍有冲突检查，不会被自动结束。

## 3. 首次重新构建

1. 先备份必要资料，正常退出旧实例/旧服务。不要把新的 `.app` 直接覆盖到仍在运行或身份不匹配的旧应用上。
2. 如果 `build/桌边小崽.app` 或 `~/Applications/桌边小崽.app` 仍带旧Bundle ID，先手工移到明确的备份位置。新发布器只识别新ID，会拒绝覆盖旧ID或其他未知应用；不会为方便升级放宽所有权校验。
3. 如 `.local/pet-build/generated-source` 仍只有 `.dragon-generated` 标记，先保留并移开该旧暂存目录，再重建。新的构建器只覆盖自己用 `.pet-generated` 标记的暂存源码，不删除未知目录。本轮离线验证已在确认无打开文件后将本机旧暂存源码移为 `generated-source.before-product-naming-<时间戳>`，原内容保留；没有移动用户数据或旧app。
4. 必须从固定上游重建helper，再构建宿主，不能复用旧冻结helper：

```sh
LOCAL_TEST_FONT=".local/pet-build/local-fonts/上首软糖体.ttf"
PET_SKIP_BUILD_CLEANUP=1 python3 scripts/build-pet-runtime.py build \
  --source-revision 8e5466d9a438deb6cb43f460e7f5a9bdb9d7a578 \
  --local-test-font "$LOCAL_TEST_FONT"
PET_SKIP_BUILD_CLEANUP=1 ./scripts/build.sh --enhanced-pet

python3 scripts/pet-build-inputs.py \
  --app 'build/桌边小崽.app/Contents/Helpers/BailongPet.app' \
  --require-local-test-font
codesign --verify --deep --strict 'build/桌边小崽.app'
./scripts/petctl.sh --check
```

本机字体仅限授权的私有测试，不得提交或分发。旧冻结helper缺少新元数据或输入指纹不匹配时，必须停止发布；不得改名JSON或手改哈希绕过重建。

完成用户验收后，安装及登录服务仍须用户明确选择 `./scripts/install.sh --confirm`。开发过程不自动执行安装、启动、卸载或终止进程。离线回归与真实桌面验收是不同证据，执行结果以[实际验证记录](实际验证记录.md)为准。

## 4. 命名遗漏复查

`python3 scripts/test-product-naming.py` 除检查模块、服务和冻结元数据外，还覆盖宿主窗口标题、剩余含 `dragon` 的文件名白名单，以及仓库 Markdown 的本地链接目标。文件枚举使用 Git 的 NUL 分隔输出，包含受版本控制的隐藏文件与非忽略的新文件，避免中文路径被转义后漏检；删除路径和忽略的私有数据、构建产物不作为当前源码。

2026-11-14复查修正两个窗口标题、共享文案中的旧兼容注释，以及历史验证记录中指向旧源码目录的链接。历史验证结论和角色专属命名没有重写；已有应用包、主题安装状态和运行服务未自动改动。

## 5. 构建报错恢复

`./scripts/build.sh --enhanced-pet` 只负责宿主编译与打包，会校验磁盘上已有的 `.local/pet-build/dist/BailongPet.app`，不会自行重建helper。旧 `dragon.43 / build37` 包缺少当前 `PetPatchVersion` 与 `PET_PATCH.json`，因此被拒绝；不是Swift编译失败，也不能通过改元数据或恢复兼容绕过。`build.sh --help` 和helper来源/输入校验失败时均提供含固定提交及审核字体的完整重建命令；本机字体要求提前到宿主编译前检查。

在仓库根目录执行（字体路径必须是已审核的本机文件）：

```sh
LOCAL_TEST_FONT=".local/pet-build/local-fonts/上首软糖体.ttf"
PET_SKIP_BUILD_CLEANUP=1 python3 scripts/build-pet-runtime.py build \
  --source-revision 8e5466d9a438deb6cb43f460e7f5a9bdb9d7a578 \
  --local-test-font "$LOCAL_TEST_FONT" &&
PET_SKIP_BUILD_CLEANUP=1 ./scripts/build.sh --enhanced-pet
```

`&&` 确保helper重建成功后才开始宿主打包；不要只执行最后一行，也不要在单行命令末尾加反斜杠。构建不等于安装或启动，不自动停止旧登录服务。

如宿主发布器提示 `Refusing unrelated app`，按第3节先确认旧构建没有运行，再将 `build/桌边小崽.app` 移到不会重名的备份目录；不要删除旧包、放宽Bundle ID所有权校验或误移动已安装/正在运行的应用。旧安装目录与服务另按第2节由用户安全处置。首次迁移的备份只需做一次，以后当前产品ID的重建会由发布器正常归档。
