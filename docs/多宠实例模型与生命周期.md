## 模型与状态约束

1. **Package** 只有稳定ID/version，不含任意可执行路径。素材由[素材库](宠物库与素材包.md)管理，运行前还需解析/验证。
2. **Instance** 有独立ID、启用状态、尺寸（128–384px，即以256px为基准的50%–150%）、位置、定时活动/移动/全屏让位偏好。
3. 首期32个配置项以内；同一 `package.id + version` 可以被多个实例引用，实例ID必须唯一。
   素材包只读共享，实例偏好、位置、状态目录和生命周期彼此独立。
4. 默认最多同时3只，构造时允许显式设1–8；starting/running/stopping均占名额。
   宿主恢复启用实例时先保留当前运行实例，再按剩余名额启动候选实例；超过名额的实例保持stopped，
   不会因为一批过大而导致全部恢复失败。数量门槛之外，白龙播放器共用48MiB QImage / 8MiB QPixmap总缓存及单解码闸门，由已注册实例均分；关闭等待线程时可取消，清理确认后回收额度。不是进程RSS或CPU百分比上限。
5. 生命周期 stopped → starting → running → stopping → stopped；错误先清理，再进入failed。
6. 旧开始回调不能复活已停止实例；重新启动使用新generation/窗口身份，旧信号被断开或忽略。
7. 单只停止不调用 `QApplication.quit()`；批量停止不等于退出控制器。退出控制器必须等待所有实例清理确认。
8. 清理超时保留强引用、stopping状态、名额和目录锁，不强杀、不假报已停止，不允许重复创建。
9. 尺寸偏好采用局部更新；不因改尺寸重置位置或自主活动。应用后原子持久化，写失败尝试还原窗口。

首次创建入口只针对增强单宠且实例清单明确缺失的情况。宿主确认窗口协议归属后，请求其自有 helper 退出并异步等待进程结束；成功后以单个多宠 Qt 控制器承接原宠并增加停止态分身。原宠尺寸、位置和行为白名单偏好迁移保留，分身偏好独立、初始可见位置错开。初始化在素材库锁与实例引用锁保护下原子写入；已存在、损坏、空、全禁用或链接清单均不当成缺失覆盖。退出未确认时不启动第二控制器。

新克隆 `enabled=true`、`autoStartOnLaunch=false`：创建后只承接原宠，不会因宿主冷启动或自动联动恢复而额外启动。用户明确单只启动后设置自动恢复；单只停止后清除此意图。手动“启动全部”仍按用户命令启动所有启用实例。旧清单缺少 `autoStartOnLaunch` 时普通实例默认 `true`，ID 以克隆器后缀 `-copy` 或 `-copy-N` 结尾的历史克隆默认 `false`，避免升级后继续重复启动同角色分身，同时不误判 `copy-pet` 等正常ID。删除仅允许原始白龙以外且已完全停止/清理的实例，只从清单移除；至少保留一个实例；素材引用和实例状态目录保留。

Swift模型的start/stop/failed返回ticket供宿主协调；运行时通过本机helper控制协议排队执行副作用，
只有收到匹配控制器状态才更新菜单。helper未报告有效status前不发变更请求；菜单在握手期间显示读取中，变更按序执行，防止旧轮询覆盖新命令结果。
结果不确定的命令不会重放。Qt控制器直接管理注入窗口，但不调用单例 `pet.main()`。

## Qt 窗口适配合约（当前白龙适配）

工厂签名：`factory(definition_copy, instance_state_directory) -> QObject adapter`。

| 接口 | 合约 |
| --- | --- |
| `ready` 信号 | 真正首帧已可呈现后发送；构造成功或仅窗口show不算就绪 |
| `failed(str)` 信号 | 错误通知，控制器随后请求停止；不立即释放对象或运行名额 |
| `stopped` 信号 | 解码线程、额度worker、定时器和屏幕订阅确认清理后发送；停止期间异步轮询，不阻塞共享GUI线程 |
| `begin()` | 信号连接后才开始；不得调用原单例main或新建QApplication |
| `request_stop()` | 取消异步工作并发起清理；不调用全局quit；长线程清理必须异步，不能卡住GUI |
| `apply_preferences(dict)` | 应用当前实例的完整已验证偏好；只对实际变化生效，不得因位置保存／无变化更新重启姿态时钟或取消甩动；不得改变另一实例或全局认证 |
| `preference_anchor()` / `restore_preference_anchor(anchor)`（可选成对钩子） | 以适配器自己的逻辑坐标快照／恢复实时位置；持久化失败回滚偏好后再恢复该锚点，不能误用较早保存的拖拽位置；未实现钩子的适配器保留原回滚路径 |

工厂构造阶段不得开始解码、创建账号任务或显示窗口；必须返回与控制器同GUI线程的QObject，
对象自身必须遵守失败时清理约定。控制器不会把任意QObject销毁当作真实线程清理证明。
异常销毁会保留stopping墓碑、运行名额和锁，并发出cleanup_stalled；不能因QObject消失就假定后台资源已退出。
当前适配器使用真实补丁 `Pet`，每只绑定独立 state directory 与 QSettings；白龙素材共享只读。
这不表示任意第三方 Package 已实现解析、信任或加载。

内核不持有账号/对话，不自动查询额度，不读Codex数据库，不增加独立聊天/历史。
运行时归属与全局偏好不因每只宠物复制一份；旧 `preferences.ini`/`conversations.json`不读取或迁移。

## 存储

调用方必须显式给出新的实例数据目录。其内容为：

```text
.pet-instances.lock
pet-instances.json
instances/<instance-id>/
```

QLockFile拒绝第二个控制器使用同一目录；活进程锁不按时间过期。不触碰旧桌边小崽/上游socket。
偏好JSON使用同盘临时文件、fsync与原子replace；失败删除临时文件、保留旧清单。
这不是断电/磁盘硬件故障保证，也不是正式用户数据迁移器；不能直接把旧桌宠目录指定成新实例目录。
