# Anime Desktop Pets 产品需求文档（PRD）

- 文档版本：0.9
- 更新日期：2026-11-07
- 产品阶段：本地开发原型（增强龙妹与同包多实例已接入；独立素材库已移除，改为宿主内置桌宠管理与本地多选添加；桌面整体验收未完成）
- 平台范围：macOS 原生桌面端，当前以 Apple Silicon 为验证对象
- 状态说明：本文同时描述当前能力和后续需求；交付顺序见[路线图](roadmap.md)

## 1. 产品定位

为 Codex 用户提供一个不侵入官方应用包的桌面伙伴，把启动视频、龙娘桌宠和
未来的原创背景组织成一致的体验：**启动有仪式感，工作时有陪伴，退出后能干净收尾**。

本项目是独立的桌边小崽应用，不宣称是官方插件，不接管 Codex 的核心任务、登录或对话能力。
当前采用 Swift/AppKit 宿主与 Python/PySide6 桌宠运行时，并已按应用边界迁入轻量 Monorepo；共享 packages 和 Studio 仍按需建设。

### 1.1 当前交付与验收快照（2026-11-03）

- 当前桌边小崽应用为 **0.7.2 / build 22**，增强辅助应用为 **build 32 / `dragon.38`**。原生 Swift 宿主
  负责启动与生命周期，独立 Python/PySide6 辅助应用提供完整 **35 动作**；静态 PNG 仅为显式降级。
- 日常待机轮询完整轮转15个互动和6个待机差分；工作差分只用于任务播放或原有手动菜单入口，移动动作保持独立调度分支。
- 拖拽释放仅在位移至少 24px 且最近释放速度至少 280px/s 时触发甩动；轻拖轻放停留在落点。拖动姿态判断最多每 50ms 更新。离屏回归通过，真实桌面卡帧与手感仍待验收。
- 菜单与弹窗这一轮调整已获用户认可（“这次改的很完美”），作为后续 UI 迭代基线：
  紧凑卡片、对齐勾选与文字、按内容定宽、圆角悬停、细线箭头、短内容及时收缩、长正文滚动。
- 最新实际检查见[验证记录](实际验证记录.md)；历史版本记录只适用于各自构建，不替代当前构建验证。
- 用户认可的是本轮菜单与弹窗体验，不代表冷启动、焦点交接、多屏、全屏/Space、长期内存、
  登录启动或卸载已经整体验收。保持这些场景为待验证项。
- 0.6.2 按用户要求移除桌宠自有对话/历史 UI 与独立用量窗口；额度改为桌宠旁宽度不超过 284px 的紧凑气泡，不改变已认可菜单和气泡绘制。
- 不读取或清理既有桌宠历史数据，也不展示 Codex 客户端历史。
- **产品取舍**：不保存完整聊天记录，也不把桌宠对话伪装成 Codex 会话。另行提供用户管理的角色身份和经确认的长期记忆；两者不是聊天历史，默认保存在本机。
- 本机任务生命周期跟随已接入增强 helper，真实桌面验收待完成；原创海报生成、背景实际应用、共享 packages、Studio 与公开发行均未完成；
  不将上游自带对话入口视为已接入当前 Codex 任务。

## 2. 用户与场景

| 场景 | 用户期望 | 产品行为 |
| --- | --- | --- |
| 新启动 Codex | 看到选定的龙娘开机动画 | 启动请求与视频并行；Codex 保持前台加载，窗口稳定后覆盖层贴合，可点击跳过 |
| 已在使用 Codex | 不被重复打断 | 只显示桌宠，不补播动画、不重启客户端 |
| 长时间编码 | 有陪伴但不抢焦点 | 小尺寸透明桌宠，可拖动、隐藏或暂停 |
| 切换全屏与多屏 | 不遮住主要工作内容 | 支持全屏让位、位置约束，并通过人工场景验收 |
| 更换角色与背景 | 统一风格且能恢复默认 | 后续提供素材规范、预览与明确确认后的应用入口 |
| 退出或关闭桌边小崽 | 不影响 Codex | 清理自身窗口与资源，不结束官方客户端 |

## 3. 产品目标与非目标

### 3.1 目标

- 一个调度器统一管理动画与桌宠，避免多个监视器重复拉起。
- 失败时优先保证 Codex 可用：播放错误、超时或用户跳过均可正常收尾。
- 配置与素材独立，便于后续替换原创角色、视频和海报。
- 构建、预览、测试和安装入口清晰，安装与主题应用均可显式控制。
- 按用户最新优先级推进多宠单开/多开与宠物管理；素材库图形入口按 2026-11-05 决定移除，只保留包工具与运行时契约；2026-11-06 确认将抖音/B站直播弹幕本地回复列为下一项产品需求。
- **2026-11-07 最新决策覆盖旧的本地 LLM 假设：** 语音回复采用用户配置的在线 OpenAI-compatible API/中转（OpenAI、DeepSeek、自定义 Base URL/模型名）；ASR 与参考音色 TTS 保持本机。API Key 使用 macOS 钥匙串，识别文本发送给用户选择的服务商，费用由服务商/中转负责并在界面披露。支持标准工具调用的服务可调用天气工具；官方 Codex 订阅凭证不视为 API Key，Codex/Grok 通过用户配置的兼容中转接入。
- **2026-11-07 数字个体方向：** 产品保持 macOS-only，数字个体与本地记忆继续使用 Swift/SwiftUI，不引入 TypeScript sidecar 或 Tauri。角色人格（身份定位、性格、价值观、愿望、关系和知识边界）、已确认记忆及用户手动目标按 `petId` 保存在本机 Markdown；普通低风险的明确“记住……”请求可按本地规则自动保存，冲突/敏感内容待审核，凭证类内容拒绝保存。模型不能静默改写人格或写入长期记忆。目标步骤和进度由用户维护，在线计划建议尚未实现。直播平台接入与独立发行包仍是后续工作。

### 3.2 非目标与硬边界

- 不修改官方应用包、`app.asar`、认证信息、聊天数据或 Dock 配置。
- 不因桌边小崽需要而自动重启 Codex，不绕过系统权限或静默添加登录项。
- 不承诺当前方案能替换官方原生启动流程或保证第一帧无闪现。
- 不把第三方角色、预览 PNG 或视频抽帧宣传为原创生成作品。
- 不承诺所有 Codex 版本都兼容私有接口或运行时主题。
- 当前不开发 Windows/Linux 版本；直播回复不自动向直播间发送评论。语音回复按 2026-11-07 决策使用用户主动配置的在线 LLM，TTS 仍在本地运行。
- 语音聊天的识别与 TTS 在本地；回复生成使用用户配置的在线服务，语音识别文本会发送给该服务。直播弹幕适配仍未交付；接收弹幕本身需要联网。

产品模型分三层：**Package** 为只读版本化素材；**Instance** 保存包引用及独立显示偏好；
**Global Settings** 保存全局启动/认证发现与总资源预算。用户看到的“单开/多开”是桌宠窗口数量，
不要求每只复制一份 Python/helper 或重新启动 Codex。同一素材包可以被多个实例引用；实例ID、偏好、位置和状态目录独立，媒体只读共享。

运行目标为 Swift 宿主统一调度一个 Qt 控制进程，进程内管理多个桌宠窗口；先解决当前单例锁、
局部停止、异步解码取消和退出清理，再接管理器，不直接把参考工程同步解码实现替换进本工程。
原有菜单、气泡、35动作与呈现时钟保留；实例之间不共用可变位置、缩放或行为状态。
Codex额度只在用户请求时读取，桌宠不维护独立聊天与历史，不批量触发请求。

管理器目标包含「已安装／运行中」与「素材」两部分；当前先交付独立原生轻量素材窗口，不强制另建 Studio/前端工程。
导入只安装，不自动启动；有运行引用的素材不可直接删除；损坏包失败不影响原桌宠。
逐个、选中批量、停止全部的行为必须清晰，关闭管理器不结束桌宠，退出全部才释放控制器。

现有资源和格式边界见 [宠物库与素材包](宠物库与素材包.md)。本阶段不更改已构建/签名 App。

### 4.1 启动动画规则

1. 以 Codex 进程 PID 为当前启动会话标识，旧异步回调不能清理新播放器。
2. 窗口稳定前不创建永久遮罩；等待超时则跳过，不阻断客户端。
3. 视频完整播放到媒体结束事件后交接给 Codex；不因目标窗口尚未出现或内部 loading 未完成而暂停视频。历史配置中的 `holdAt` 仅为兼容保留，不再作为启动播放门禁。
   淡出开始于 12.7 秒、结束于 13.65 秒，可按完整模板调整。
4. 新进程正常完成动画后显示桌宠；如果用户已明确隐藏或结束本次桌宠，尊重其意图。
5. 用户选择预览时，允许不启动、不激活 Codex 而独立测试视频。
6. 监听式覆盖不是嵌入或捕获 Codex 窗口，不保证其首帧完全不可见。

### 4.2 桌宠规则

- 默认构建接入完整 Mac 桌宠的本地增强版与 35 动作；原版和静态 PNG 为明确选择的对照/降级。
- 气泡按实际文本宽度和行高紧凑排版，长正文限高滚动，进度变短后收回冗余空间。
- 菜单采用 Apple 风格圆角卡片、23px 行高、圆角悬停、矢量勾选及细线 chevron；
  宽度根据最长选项的实际字体宽度加必要槽位与内边距计算，不恢复固定 218px 最小宽度。
- 菜单与气泡使用 12px 圆角、细边框、轻量阴影和深浅色配色；90ms 淡入尊重减少动态效果。
  这是 Qt 自绘卡片，继续使用 QMenu 的键盘与子菜单机制，不宣称 AppKit 原生菜单或系统毛玻璃。
- 气泡先定文本宽度再测高度；进度条按实际 6px 高度计入，详情为右下角小型操作。
  后续修复不得通过统一加高弹窗制造空白；沿用用户已认可的紧凑布局。
- WebP 后台顺序解码、受限预取与字节 LRU；真实绘制不等待解码，切换等待时保留前帧。
- 边缘保留源素材描边，以预乘 alpha 正确合成；不得把源底色仍存在描述为完全消除。
- 桌边小崽负责启动与显示调度，动画播放器和动作菜单由辅助应用提供，不宣称已原生重写。
- 桌宠不应抢走编辑器的键盘焦点；拖动、落地、右键与隐藏行为仍需实机验收。
- 获取固定发布包并校验 SHA-256、签名、动作清单；不启用第二套自启动监视器。
- 不强制终止可能持有任务的外部进程，区分桌边小崽启动与既有独立实例。
- 增强版只保留手动额度查询入口，移除上游自有对话/历史；未做真实账号验收，不代表能跟随现有 Codex 对话。

### 4.2.2 自主活动与拖拽松手（0.4.0）

- 在原有 Qt 辅助应用中新增独立行为层，复用 16ms 动画 tick，不增加解码线程或界面重绘体系。
- 空闲每 12–24 秒尝试一次随机菜单动画或移动；若被任务、隐藏、点击、菜单或气泡阻塞则重新等待，不积压行为。
- 轻跳、双跳、短冲刺与浮游弧线在同一屏幕可用区域内进行，自主位移回原点。
- 松手后按最近 150ms 拖动样本计算方向和惯性，限制在 96px 内；增强清单接入方向飞行/快甩跑步，以短混合衔接拖拽姿态和回待机。25 动作兼容清单保留旧三次衰减跳跃；不是跌落到屏幕底边的重力模拟。
- 手动操作可随时中断；任务、隐藏、减少动态效果或屏幕变化可终止位移。首帧就绪后开始移动，等待超过 5 秒取消。
- 保留已认可的菜单、弹窗与样式，仅增加「自主活动」子菜单；两个开关保存在辅助应用现有 QSettings。
- 禁止自主触发 `choose()` 的声音/台词、额度查询或聊天任务；工作分类仅复用画面，不伪装真实任务状态。
- 更复杂的变身、翻滚、挥剑等角色肢体动作需要相应授权素材或原创帧；轨迹组合不能代替新素材。
- 0.5.0 已接入 4 新待机 + 6 左右走/跑/飞，总计 35 动作；素材和来源通过独立构建 overlay 合并，原始上游只读。
  位移只在素材运动段执行，首帧就绪后按播放器时间轴同步，收尾停在屏内终点，不循环起步段；0.5.1 经确认接入方向飞行/快甩跑步、约 160ms 姿态短混合及收尾回待机；不是生成补帧。
  WebP 逐帧时长与位移共用已呈现时钟；首帧、过渡或解码等待不抢跑，卡顿不追赶积压，失败超时回退。
  详见[扩展素材准备](扩展动作素材与运行时接入.md)。

### 4.2.3 额度气泡（0.6.2）

- 参考本地 `bailong-desktop-pet` 的额度小气泡；宽度预算为 284px、短内容继续收缩，不打开独立宽工具窗，深浅主题沿用已认可样式。
- 不后台刷新额度、不读取对话数据、不发起模型任务。
- 桌宠对话与历史功能移除，既有用户文件不清理。真实额度和桌面体验待手动验收。
- 实现及隐私边界见[额度气泡](额度气泡说明.md)。

### 4.2.4 桌宠对话与历史（不纳入当前范围）

- 不提供桌宠自己的对话输入框、对话线程或历史浏览/存储 UI；避免与 Codex 主会话重复并造成“桌宠历史就是 Codex 历史”的误解。
- 不提供正文读取/展示功能，不读历史数据库。用户已授权为任务跟随有界读取 rollout；正文所在行会临时经过内存，仅提取生命周期字段，不保存或记录正文。已有桌宠历史不删除或改写。
- 若未来 Codex 提供经验证的会话深链/继续会话能力，可评估以“跳转或接续 Codex 会话”替代独立聊天；在此之前保持气泡式轻互动。

### 4.4 本机任务跟随（2026-11-03）

用户明确放开为任务跟随读取本机会话文件。增强 helper 通过只读 rollout 事件按 turn_id 聚合开始、完成、中断，
开始播放工作开场，执行中持续轮换工作差分，完成后恢复普通待机。宿主心跳限于正常联动；暂停/退出/失联降级，预览和检查不读取会话。
不提取/展示/保存正文，不读取索引或认证数据库，不启动第二个 Codex，也不自动查额度。
来源是兼容性的本机文件，15分钟静默降未知，不推断完成；暂不绑定前台会话、不识别批准等待、无完成通知。
详见[任务跟随](Codex任务跟随.md)。真实桌面任务验收和长时资源仍待完成。

### 4.5 直播弹幕回复与本机语音聊天（2026-11-07，在线回复决策）

- 目标仍面向抖音和 B站直播间，但平台弹幕接入尚未交付。现有语音聊天由本地 ASR 识别，使用用户配置的 OpenAI-compatible 在线模型生成回复；桌边小崽显示回复，并可用本地参考音色朗读。
- 直播模式仅接收直播平台输入，不自动发送评论，也不监听麦克风；另提供用户主动按键触发的一轮本机语音聊天测试，不读取 Codex 正文，不保存录音、识别文本或完整弹幕历史。
- API Key 只能保存在 macOS 钥匙串；模型厂商、Base URL 和模型名称保存在本地设置。用户需主动配置并发起调用，语音识别文本会发送到所选服务商；费用由服务商/中转站按其价格收取。没有自动切换服务商。
- 支持标准工具调用的服务可由天气工具查询 Open-Meteo；不支持工具调用的兼容端点仍可普通对话，但不能回答实时天气。
- 首选开发与验收硬件为 Apple Silicon M4、24GB 内存、256GB 内置存储的 Mac；需求确认时可用空间约40GB。Intel 16GB MacBook Pro（2020，macOS 15）不作为第一版实时推理目标。
- “低延迟”以 ASR、在线首段回复文字及首段可听音频的 P50/P95 实测定义，不承诺零延迟。网络、服务商负载、模型和 TTS 均会影响体验。
- 详细范围、进程边界、平台适配和验收指标见[直播语音桌宠方案](直播语音桌宠方案.md)。

### 4.6 数字个体与本地记忆（2026-11-07）

- 角色身份由用户编辑和确认；模型不得自行改写。身份和记忆按桌宠实例 ID 分开保存为 Markdown，不复制给克隆实例。
- 语音中明确说“记住……”会进入本机规则判断：低风险普通内容自动保存，完全重复内容去重，冲突或支付/医疗/身份等敏感内容进入待审核，密码、密钥、验证码等凭证拒绝保存。手动新增仍先进入审核；默认不保存完整对话、录音或自动推测的个人特征。
- 身份和记忆默认不发送给在线模型；用户可逐项允许分享。模型只得到本轮允许使用的内容。用户问“你是谁/你会什么”时，优先用本机身份和真实能力状态回答。
- 当前不包含通用自主后台 Agent、自动执行目标、向量数据库、直播平台接入或发行包集成。已接入的自动化仅限明确“记住”请求的本机低风险记忆判断；用户可手动建立本地目标、编辑步骤并跟踪进度；模型生成建议草案和用户审核流程仍待实现。
- 通用动作审批规则已有纯 Swift 策略与测试，但还没有工具执行器：风险类别、用户请求来源和可撤销性必须由宿主判定，模型不能自报低风险；对外发布、支付、凭证、权限、删除/覆盖及未知动作不得自动执行。
- 详细流程、Swift 模块职责、Markdown 文件格式及安全边界见[数字个体与本地记忆方案](数字个体与本地记忆方案.md)。
