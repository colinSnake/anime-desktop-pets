# 架构与设计决策

更新日期：2026-11-07。本文区分现有实现与目标架构，产品范围见 [PRD](prd.md)。

## 1. 当前结构：轻量 Monorepo、多运行时

当前 Monorepo 包含一个 SwiftPM 原生宿主和一个 Python/PySide6 桌宠运行时。Swift package 位于
`apps/companion-macos/Package.swift`，Python 业务逻辑位于 `apps/pet-runtime/`：

| 模块 | 职责 | 主要路径 |
| --- | --- | --- |
| `DragonCore` | 配置验证、按进程管理的生命周期状态机、控制消息类型 | `apps/companion-macos/Sources/DragonCore/` |
| `DragonCompanion` | AppKit 应用、启动协调、视频、桌宠、窗口与本地控制 | `apps/companion-macos/Sources/DragonCompanion/` |
| `DragonCoreTests` | 不依赖真实 Codex 窗口的核心测试 | `apps/companion-macos/Tests/DragonCoreTests/` |
| `pet-runtime` | 播放增强、多宠生命周期、IPC、素材库和 Qt helper 业务逻辑 | `apps/pet-runtime/` |
| 语音运行时（checkout 演示） | 本地 ASR/TTS、临时录音、播放；在线模型请求由 Swift 宿主执行 | `apps/speech-runtime/`；本地 LLM 已移除，Python 环境和权重尚未纳入发行包 |

```text
用户 / 菜单栏 / petctl
          │
          ▼
    本地控制与 Coordinator ◄── NSWorkspace：进程启动/退出
          │                  ◄── CoreGraphics：窗口几何信息
          ├── LaunchSession：按 PID 维护生命周期
          ├── BootPlayer：AVPlayer 视频覆盖层
          └── PetController：原生桌宠 / 实验性外部 App
```

当前不依赖前端开发服务器，也没有已实现的 Studio。在线模型管理、Keychain 凭证和 Chat Completions 客户端位于 Swift 宿主；这不等于接入官方 Codex Agent。

语音聊天与未来直播语音是桌边小崽的可选能力，不并入动画 helper。当前宿主提供语音设置和“模型管理”入口：本地麦克风录音由本机 ASR 转写，Swift 宿主将识别文本发送到用户配置的 OpenAI-compatible 服务；返回文本交由桌宠呈现，并可选择本地参考音色 TTS。API Key 只存 macOS 钥匙串，Speech Runtime 不接触该 Key。直播平台适配尚未实现。具体数据流、费用和验收边界见[直播语音桌宠方案](直播语音桌宠方案.md)。

## 2. 单一协调器，不运行相互竞争的监视器

`Coordinator` 持有唯一的 Codex 启停观察入口，向 `BootPlayer` 和 `PetController` 分派动作。
`DragonCore/LaunchSession` 是按 PID 组织的纯状态机，可脱离 AppKit 验证。
播放器回调带实例身份，避免旧播放完成或失败事件误清理新播放器。

运行模式：

- `--launch`：启动或复用 Codex；打开应用默认使用此模式。
- `--watch`：观察后续启动；已有进程不重播动画。
- `--preview-animation` / `--preview-pet`：独立预览，不作为真实联动验收的替代。
- `--check`：只检查媒体、配置与客户端，不创建窗口或启动服务。
- `--control-test-server`：隔离控制接口测试，不注册 Codex 观察器。

预览、启动与观察模式持续运行；视频结束不是应用退出。切换模式前须结束旧实例。

## 3. 启动视频与焦点交接

`NSWorkspace` 发现并启动真实客户端，`CGWindowListCopyWindowInfo` 读取窗口位置与尺寸，
不获取屏幕截图。窗口连续两次采样的边界稳定后，才创建覆盖层。
`AVPlayer` 播放用户选择的本地视频，淡出后露出真正的 Codex 窗口。
本方案不镜像、捕获或嵌入官方窗口；取消动画不终止 Codex。

正常完成、跳过、超时与错误共享清理路径，目标是不留下遮罩或阻塞输入。
真实声音、键盘焦点和多屏交接需要人工验收，编译通过不能证明这些体验正确。

监听器只能在真实窗口出现后覆盖，不能保证第一帧完全无闪现。
未来如需更严格的“先电影、后客户端”时序，应另行设计受控启动入口；不能通过静默重启既有进程实现。

## 4. 桌宠后端

### 原生后端（显式静态降级）

独立编写的 AppKit 非激活透明面板，使用本地参考 PNG 与小幅呼吸动效，支持点击气泡、
拖动、菜单、位置保存与屏幕范围约束。创建时尊重系统减少动态效果。

这不是导入上游桌宠源码。图像读取基于 ImageIO/NSImage 支持的本地格式并限制尺寸/帧数，
不宣称已经兼容上游全部 WebP、动作清单或 25 动作播放器。

### 外部后端（默认完整桌宠，待真实桌面验收）

默认构建将基于固定 `0.4.1-mac.3` 源码编译的本地增强版复制进 `Contents/Helpers/`。
原始 App 留在 `.local/pets/` 不变，`--full-pet` 显式选择原版；当前增强版 build 13 / `dragon.10`，
`DRAGON_PATCH.json` 与源码 SHA-256 输入清单标识来源。宿主在打包前拒绝与当前源码不一致的冻结 helper。
后台解码、文本布局、菜单和多实例适配均在辅助应用内部，见
[增强层设计](桌宠增强与性能构建.md)。
动作清单包含 6 待机、15 互动、5 工作、3 特殊及 6 移动动作。
构建前校验发布 SHA-256、深度签名与清单，资源缺失即失败，不偷偷换回静态图。

运行时相对路径以桌边小崽资源目录解析。已有同 Bundle ID 实例则复用，避免重复桌宠；
显示时对该固定版本尝试连接同用户的 `bailong-desktop-pet-v1` Socket，
仅建立连接、不发送命令，清除其手动隐藏状态。该接口不是 Codex 私有任务 IPC。
状态同时提供 `petState`、`petError`，可见性依据窗口几何，而非把进程存在当成宠物可见。

启动回调尊重最新显示意图；桌边小崽或 Codex 退出时，对自有且支持窗口控制协议的增强实例正常请求退出，旧版仅尝试隐藏；
不强制结束外部进程，也不自动隐藏本来独立运行的实例。显示/隐藏命令是用户显式控制。
适配器无法读取其内部任务或动作语义，不能当作双向任务集成。
完整接入与未验证边界见 [完整桌宠接入说明.md](完整桌宠接入说明.md)。

### 4.1 多实例运行时

默认外部后端由单个 Qt `QApplication` 承载多个龙妹窗口，Swift `PetInstanceRuntime` 负责 helper
生命周期和本机控制协议。每个实例使用独立 ID、状态目录、位置和行为偏好；同一 `package.id + version`
可以被多个实例引用，媒体保持只读共享。`clone_pet` 只追加已验证的实例定义，克隆以 stopped 状态登记，
不会复制龙妹媒体或启动第二个 helper。并发运行数量默认受控制器上限约束，真实桌面多屏/Space、焦点和长期资源表现仍待验收。

## 5. 本地控制、数据与隐私

- 用户状态目录内只有一个进程锁，拿到锁后才允许处理遗留 Socket。
- Unix Socket 权限为 0600；请求上限 8 KiB，读写有边界和超时。
- 消息仅包含有限的类型化命令，不提供任意执行、任意文件写入或模型请求。
- UI 更新在主执行域，I/O 在串行队列；接受的连接使用有时限的阻塞读写，监听端保持非阻塞。
- 桌边小崽只写有大小上限的生命周期元数据日志，不读取认证、聊天、屏幕或模型数据。
- 外部上游 App 保留自己的额度与对话入口，用户触发后会使用其自己的账号/任务逻辑；
  本项目不自动调用，也未验证真实额度或聊天。
- 安装需显式确认，并拒绝已知旧监视器冲突；不自动下载更新或抓取账号。
- 资源目录只读，完整用户配置、位置与运行状态保存在用户数据目录。

## 6. 主题边界（未完成真实接入）

主题工具是另行安装的可选依赖，没有复制进仓库。
它通过 loopback CDP 修改运行时 CSS，依赖客户端版本，不是官方插件 API。
原创海报生成与主题应用是两个独立、需要确认的步骤。

现有 Codex 没有 CDP 时不自动重启。`scripts/theme.sh` 的应用和恢复需要 `--confirm`，
恢复前检查是否由本项目主题拥有状态，避免移除其他主题。
主调度器当前拒绝 `themeEnabled=true`，直到真实作品、兼容性与可读性验证完成。

## 7. 当前 Monorepo 结构与后续方向

```text
apps/
  companion-macos/          # 原生应用的 Swift Package
  pet-runtime/              # Python/PySide6 桌宠业务逻辑
integrations/
  bailong/                  # 固定上游元数据、来源说明与补丁
resources/                  # 本地媒体与审核后的生成素材
config/
scripts/                    # 保持现有根目录命令入口
docs/                      # 中文产品与工程文档
```

当前没有 `packages/` 目录，也没有单独的 Studio 工程，不能将后续规划写成现有结构。

采用 Monorepo 是为了共享版本、配置与发布流程，不是要求所有代码使用同一种包管理器。
拆分 `DragonCore` 时应建立独立 `Package.swift`，由应用通过本地路径依赖引用，
不能用越出 package 根目录的 target 源码路径拼接。当前仍保持一个 Swift package，避免无实际消费者的路径依赖开销。

先迁移有真实用途的模块；没有 Studio 时不创建空前端工程，也不引入 Turborepo/Nx。
如以后有多个前端包再评估 pnpm workspace；Studio 退出不能影响原生桌边小崽常驻。
迁移后必须重新检查资源路径、打包、安装、控制与测试脚本，保持用户入口稳定。

## 8. 未来任务状态适配（未接入）

增强桌宠与其 Mac 分支展示了生命周期元数据映射、去抖与异步播放思路。
借鉴设计，不复制授权不明确的源码。后续适配必须具备版本探测、会话/轮次识别、
未知状态、退避重连与完成去重，不写 Codex 数据库，不从回复词语判断完成。
不能承诺所有 Codex 版本兼容，也不应读取或保存聊天正文。

## 9. 未来模型服务（未实现）

模型为用户指定的 `gpt-image-2.5`。当前服务端点和协议未提供，无 SDK 或付费请求实现。
接入前核实认证、请求与返回格式、尺寸、费用和限制，并确认第一次调用。
密钥不写入示例 JSON、生成元数据或日志；图像生成可以独立失败，不阻断桌边小崽运行。

实施顺序和退出条件见[路线图](roadmap.md)。
