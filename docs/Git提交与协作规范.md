# Git 提交与协作规范

更新日期：2026-11-02。适用于本仓库后续提交；仓库边界以 [AGENTS.md](../AGENTS.md) 为准。
本规范不追溯改写已有提交，不自动安装 Git hooks 或修改用户全局 Git 配置。

## 1. 提交格式

```text
<type>(<scope>): <中文祈使说明>

说明修改原因、主要变化及影响范围。

验证：记录实际执行的命令与结果，并说明未执行、跳过或待验收项。
```

- `type`、`scope` 使用英文小写；多词 scope 使用连字符。冒号后保留一个空格。
- 说明与正文使用中文，命令、文件名、版本号和 API 等技术标识保持原样。
- 标题用“增加、修复、整理、同步、记录、移除”等祈使表达；避免“更新一下”“已完成优化”等含糊表述。
- 一次提交一个逻辑目的；实现、相关测试和必要文档应一起提交，无关重构或格式整理另行提交。
- 不能为追求小提交而留下缺少依赖的中间状态；首次纳入既有工程可作为一个工程基线，
  不凭聊天记录伪造逐项功能历史。

| type | 使用场景 |
| --- | --- |
| `feat` | 增加功能，或首次纳入既有功能工程基线 |
| `fix` | 修复缺陷 |
| `refactor` | 不改变对外行为的结构调整 |
| `perf` | 性能改进，注明真实测量边界 |
| `test` | 增加或修正测试 |
| `docs` | 修改说明、协作规范或验证记录 |
| `build` | 修改构建、依赖或打包流程 |
| `ci` | 修改持续集成流程 |
| `chore` | 其它维护事项 |
| `revert` | 回退已有改动，并注明原因和原提交 |

scope 可按影响范围选用 `host`、`runtime`、`pets`、`library`、`assets`、`branding`、
`workflow` 或 `project`；它描述本次逻辑范围，不必逐字对应目录名。

格式示例（不代表这些工作本轮已执行）：

```text
fix(runtime): 保留拖拽回待机期间的可见画面
docs(workflow): 记录 Git 提交与验证规范
```

## 2. 提交前检查

1. 先看 `git status --short`、`git diff` 和未跟踪文件，保留用户及其它会话的已有工作。
2. 明确一个逻辑目的，只暂存相关文件；功能、命令或当前状态变更须同步双语 README 与相关专题文档。
3. 检查是否误纳入 `.local/`、`build/`、`.build/`、第三方媒体、私有配置、密钥或用户数据。
   根 MIT 许可证不授予第三方素材再分发权；本机绝对素材路径也不属于可移植发行配置。
4. 使用 `git diff --cached --stat`、`git diff --cached` 复核实际提交内容，并运行
   `git diff --cached --check`。`.patch` 中空白上下文行的前导空格属于补丁格式，
   按 `.gitattributes` 检查，不自动修剪或改写固定上游补丁。
5. 按修改范围执行验证，正文说明结果与边界；提交后检查 `git status --short` 并报告提交编号及剩余改动。

## 3. 验证结果必须真实

- 源码回归入口：`./scripts/test.sh`；多宠和 IPC 回归入口：`./scripts/test-multi-pet.sh`。
- 现有构建的只读状态可用 `./scripts/dragonctl.sh --check`，不启动正常桌宠。
- 看实际退出码、失败和跳过信息，不把缺少运行环境导致的跳过写成完整通过。
- 只有本轮执行过的命令才写“本轮通过”；引用历史构建、自检或基准时明确日期、版本与来源。
- 未运行的检查写“未执行”及原因；失败不能隐去，修复重跑需说明最终结果和最初失败范围。
- 仅文档修改检查本地链接、版本/状态一致性和差异即可，不无故重建、安装或启动桌宠。
- 离屏、合成 fixture 和自动测试不替代真实桌面、多屏/Space、焦点、长期 CPU/RSS 或安装验收。
  不为验证读取账号、真实额度或聊天，不自动结束运行进程。
- 详细结果记录在[实际验证记录](实际验证记录.md)，方法见[测试与人工验收](测试与人工验收.md)。
  私有日志保留在忽略目录，正文只保留脱敏结论，不将“日志未提交”误写成“未执行”。

## 4. 授权与收尾

创建本地提交不等于获得推送授权。未明确要求不执行 `git push`、不改写已有历史、不添加付费调用，
不启用登录服务或主题，也不启动或重启桌宠/Codex。报告提交编号、逻辑目的、真实验证与未验收范围。
