# 额度气泡（0.7.2）

入口：桌宠右键 → **查询额度**，或双击桌宠。使用已认可的紧凑气泡；不打开独立统计窗口。

额度卡片沿用 DeepSeek 桌宠的“额度行 + 使用条 + 重置时间”信息层级，并加入手动刷新与查询时间。官方额度行按剩余额度显示主题色档位（充足/注意/紧张）；TiMi CC 余额以醒目的金额呈现，绝不伪装成百分比。卡片使用明确的标题分隔、主题色金额、低强调度重置/查询时间和按剩余额度着色的进度条；余额卡片底栏将来源与查询时间左右排列，长来源可悬停查看完整名称；订阅额度的查询时间保留在下方。

旧宿主的普通对话气泡使用艺术字体，文案按段水平居中，并在气泡内保持上下留白对称；长文超出阅读高度时仍从顶部滚动。旧版额度和任务结果采用圆体，字体与行距参与文本高度计算。当前 Electron 额度卡片的字体见下文，原生菜单仍沿用系统字体。

## 独立 Electron 视频预览

`pnpm run dev:pet-video-preview` 下，右键角色选「查询额度」或双击角色即可查询。卡片显示来源和查询时间，并可手动刷新或关闭。官方来源显示订阅窗口的剩余百分比和重置时间；TiMi CC 显示金额和币种，不显示进度条。仅这三种显式操作触发查询；启动、悬停、打开菜单和 `--check` 都不会查询。

- 官方账户继续使用已安装 Codex CLI 的 `app-server`、`account/rateLimits/read`。允许沿用旧版明确配置的 `BAILONG_CODEX` 绝对路径或从可信本机安装位置查找；不直接读取认证文件、不读取聊天和任务，忽略 `credits` 字段。
- TiMi CC 只读匹配当前 Codex 服务名、TiMi 根地址及当前 CC Switch 已启用模板。只发固定 `GET https://timicc.com/v1/usage`，不执行模板 JavaScript，不跟随重定向，不查询其他供应商。默认使用匹配的 CC Switch 服务凭据；仅当两边引用同一个 TiMi 专用环境变量时才读它。不会将通用环境变量 `OPENAI_API_KEY` 转发给 TiMi。旧模板缺币种时仍按 USD；明确返回的常见币种按实际币种显示，未知币种不显示金额。
- 调用使用 Python 3.11+ 标准库。查询由可信主进程按需启动，最多一个在途查询；关闭、隐藏、开始拖动或退出会取消并回收预览自有子进程。气泡只接收经校验的窗口数值、金额/币种、时间或固定失败代码；不接触凭据、路径、原始响应，不保存结果或朗读。中转配置不匹配或查询失败时不改查官方账户。

本次用临时配置、合成 SQLite、假 CLI 和模拟 HTTP 验证。真实账户返回、授权与桌面卡片仍待用户主动验收。

## 新工作区迁移

macOS 工作区自有视频播放器使用上面同一固定查询适配器。右键、双击、手动刷新触发，开卡时可播额度动作（系统减少动态效果时跳过）。最多一个在途请求在全部工作区实例间共享；每只桌宠保留自己的卡片和查询状态。

2026-11-19 对照旧 macOS 样式整理显示：额度卡片采用 12 px 圆角、细描边和柔和阴影；余额标题、金额和来源分开，底栏显示来源／币种和查询时间。订阅继续按窗口显示进度和重置时间。Electron 卡片的标题、状态提示、金额、百分比、来源与时间，和龙妹的悬停名字气泡、普通对白、任务短句一样优先使用本机测试上首软糖体，缺失时回退至 `Yuanti SC` 等系统圆体。刷新、关闭图标及原生菜单保留系统字体。素材准备核验说明和 SHA-256 后仅复制到当前会话私有临时目录，可信主进程复核后提供固定同源字体路由；缺字体不阻塞播放。不改查询、朗读或取消逻辑。

合成验证覆盖卡片、并发、取消、迟到结果丢弃和退出等待。显示的有限数值只进当前窗口；凭据、原始响应及路径不进 renderer，结果不落盘、不朗读。真实账户数据未用于迁移回归。

## 查询来源（旧宿主）

- **官方账户**：支持查询。保留上游只读 Codex CLI `app-server` 的 `account/rateLimits/read` 流程，显示服务提供的订阅用量窗口、剩余比例和重置时间。当前桌宠解析器尚未展示该响应可选的 workspace `credits` 字段。OpenAI 官方 Usage 页面可查看已用额度、credit balance 和重置时间，具体内容取决于账户方案。只有 TiMi CC 中转在本桌宠卡片中显示 `USD` 余额。
- **TiMi CC 中转**：读取当前 Codex `config.toml` 的服务地址，匹配 CC Switch 当前 Codex 服务及其已启用的只读 GET `{{baseUrl}}/v1/usage` 模板。仅支持 HTTPS `timicc.com` 根地址、Bearer `{{apiKey}}` 的已知模板；不猜测其它服务端点。
- 显式请求时只读打开 `~/.cc-switch/cc-switch.db`，校验选中服务地址一致，再从配置的环境变量或该服务的 `settings_config.auth.OPENAI_API_KEY` 获取凭据。未修改 Codex/CC Switch 文件、不访问钥匙串、不执行 CC Switch 的 JavaScript。CC Switch 无需保持运行，但其数据库和匹配配置必须存在。
- 中转解析模板约定的 `remaining`、`quota.remaining` 或 `balance`，单位取 `unit`、`quota.unit`，缺省按该 TiMi 模板的 `USD`。显示「中转剩余额度 / TiMi CC · 剩余金额 单位」，不把余额当百分比、不绘制订阅进度条或伪造重置时间。
- 其它中转、未匹配/关闭模板、缺少凭据、401/403、404、网络失败、未知响应格式均给出对应原因，不再统一提示稍后重试。此适配基于本机已配置模板，未宣称 TiMi 对所有账户保证该接口。

## 隐私与运行边界

仅用户点击菜单或双击后查询；不后台刷新、不因任务跟随自动联网、不发送提示词或启动模型任务。
认证仅发送给匹配的 TiMi HTTPS 端点；拒绝重定向，避免凭据被带到其它地址。响应限1MiB。
额度数值只进入当前气泡，不持久化；错误日志仅保存脱敏状态码/阶段/耗时，不保存服务器错误正文、密钥、账号或余额。
任务观察器与额度请求相互独立；额度交互期间暂缓自动姿态切换，关闭气泡后继续跟随。

旧实现曾核对本机 TiMi 模板与接口失败阶段；迁移本轮未读取真实配置或请求真实余额。真实返回格式、余额及桌面体验由用户主动点击验收。
