# 直播语音桌宠方案

更新日期：2026-11-07。**本日用户最新决定覆盖下文早期“回复 LLM 完全本地”的规划：文本回复改用用户配置的在线 OpenAI-compatible API/中转，本地只保留 ASR 与可选 TTS。** 已实现模型管理与语音流程接线，但真实服务商、钥匙串授权、真实天气调用和真实扬声器仍待配置后验收；直播平台适配、发行包集成也未交付。产品范围见[PRD](prd.md)，当前实施顺序见[路线图](roadmap.md#8-m5直播弹幕回复与克隆音色朗读需求已确认架构更新)。

## 1. 已确认范围

- 开发/首轮验收主机：Apple Silicon M4、24GB 统一内存、256GB 内置存储；当前约有40GB可用空间。
- 输入目标：抖音和 B站直播间弹幕。接收弹幕必须联网；语音识别/TTS 在本地，回复模型由用户配置的在线服务提供。
- 处理：本地过滤、去重、限流；语音回复经用户配置的在线模型生成简短中文回复。直播弹幕在线 LLM/是否回复策略须在直播接入实施时单独定义。
- 输出：桌边小崽显示回复，并以用户有权使用的参考音频克隆音色朗读。
- 直播模式不向直播间发送消息、不监听麦克风，不读取 Codex 对话正文，不保存完整弹幕历史。直播间尚未就绪时，另支持用户主动按键录音的一轮本机语音聊天测试；该测试录音仅保存在临时目录并在处理结束删除。
- 不自动切换服务商。在线 API 请求仅在用户配置并主动发起时执行，可能产生费用，费用由服务商或中转站收取。
- 2020 Intel MacBook Pro、16GB、macOS 15 作为备机，不纳入首版低延迟承诺；可用于平台适配、UI 和非实时回归。

## 2. 集成决策

它是「桌边小崽」里的可选功能，不是另一个面向用户的独立产品，也不是官方 Codex 插件。工程上不要把直播连接、LLM 或 TTS 塞进当前 PySide6 动画 helper：模型和网络故障不能拖住动画、拖拽或菜单。

独立进程 `apps/speech-runtime/` 仅承载本地 ASR/TTS。Swift 宿主通过 OpenAI-compatible Chat Completions API 生成回复；API Key 仅存于 macOS 钥匙串。平台连接未交付，发行包也未包含 Python/MLX 环境和模型：

```text
桌边小崽 Swift/AppKit 宿主
  ├─ 提供参考音频、准确转写、扬声器偏好与单轮演示入口
  ├─ 现有 Python/PySide6 pet helper
  │    └─ 经独立权限 socket 接收限时、限长的单条回复呈现请求
  └─ 独立 Speech Runtime
       ├─ 本地 ASR 转写（语音聊天）
       ├─ 回复文本回到 Speech Runtime
       ├─ 本地 TTS / 参考音色缓存
       └─ 音频设备播放、取消和资源清理
  └─ Swift/AppKit 在线模型客户端
       ├─ OpenAI / DeepSeek / 自定义兼容中转
       ├─ API Key 由 macOS 钥匙串提供
       └─ 标准工具调用可委派 Open-Meteo 天气查询
```

宿主是控制面，Speech Runtime 是数据面。宿主负责单轮演示生命周期和配置入口；Python 语音服务维护本地推理及可选播放。桌宠 UI 不直接持有模型，也不接触平台凭证。现有多宠 IPC 是控制协议，不承载 PCM、模型数据或高频弹幕；演示回复通过独立、权限受限的本机 socket 请求显示，不复用多宠控制协议。

目前不调用 Codex Agent，也不加载本地 LLM。语音转写文本会发送给用户配置的 API/中转；在线模型的能力、跨轮记忆和工具调用由所选服务端决定。官方 Codex 订阅凭证不能直接当作 OpenAI API Key；需通过用户配置的中转地址和该中转提供的 Key 接入。天气工具由应用调用 Open-Meteo，仅当模型发起标准函数工具调用时工作；不支持工具调用的中转仍可普通聊天，但天气请求会明确说明无法查询。语音 PCM 解码失败时不得把空 WAV 继续交给 ASR。Speech Runtime 不持有在线 API Key。

### 设置与凭证边界（M5.4）

状态栏菜单中的「直播语音设置」打开轻量 AppKit 窗口。`speech-settings.json` 位于桌边小崽受保护的用户数据目录，权限为 `0600`，只保存 schema 版本、所选平台、直播间标识、麦克风设备 UID、用户选择的参考音频路径，以及显示/朗读偏好；不保存弹幕历史、生成回复、音频内容、Cookie、访问令牌或密码。未知平台、控制字符、超长字段、符号链接设置文件及超过64KiB的配置均拒绝读取/保存。缺少配置时保持安全默认值：平台尚未连接、服务不自动启动、参考音频为空。

麦克风选择列出 macOS 可用输入设备并默认选中系统默认设备。用户可以运行4秒检测查看实时输入电平；检测录音只写临时 WAV，结束或关闭窗口时删除。按键语音聊天使用同一输入设备和音频引擎，最长20秒。设备选择与聊天录音均需系统麦克风权限；无设备、权限拒绝、设备切换失败及无有效输入格式分别提示，不以权限已授权代表采集到声音。

当前界面提供本机单轮演示，不是直播控制台：用户需主动选择参考音频、填写准确转写并点击演示；演示不会连接直播间。保存设置不会启动模型或打开音频设备，扬声器播放默认关闭。B站接入开发中，抖音接入待评估。第一版没有收集平台凭证的必要。若后续某个合法接入方案确实需要认证，凭证必须独立存入 macOS Keychain，JSON 仅保留 Keychain item 标识；诊断与普通日志不记录凭证。

用户主动发起的语音回复可以在 Codex 任务活跃时显示，允许替换工作提示或上一条语音回复，不会被工作动画的普通气泡隐藏策略立即隐藏；不清空任务状态，也不放开后台自主移动。拖拽、甩动、隐藏、鼠标/菜单/对话框交互及人工消息/额度气泡仍受保护。若这些交互暂时阻止呈现，宿主每500ms重试一次，最多等待约10秒；这期间不取消 TTS。超时会在设置窗口明确提示回复已生成/朗读但气泡未显示，不再把桌宠忙碌误报为模型失败。麦克风识别失败和没有识别到语音也分别提示。

模型启动、回复生成、音色合成和扬声器播放错误分别给出阶段提示。录音开始、文件交接、运行时启动、ASR 结果、回复和呈现阶段写入本机受限诊断日志；只记录阶段、固定错误码、字节数和字符数，不写录音/参考音频路径、音频内容或识别/回复文本。最终状态栏保留本轮 ASR 文本，便于区分识别与后续失败。

语音状态向用户呈现时采用稳定阶段：未配置（缺 API Key 或 ASR；启用朗读时缺参考音频/TTS）、已停止、启动中、等待平台、已连接、思考中、正在朗读、重连中、失败。当前单轮演示窗口只报告本次演示结果；平台状态尚无实现，不能把语音子进程存活等同于平台已连接。

首个可测原型可先把全部 Python 语音逻辑放在一个独立服务进程里，避免过早拆多个服务；只有音频播放与 Qt/Swift 的平台职责确有隔离需要时再拆进程。不能为架构整洁制造不必要的 IPC。

## 3. 流程与队列

```text
直播事件 -> 规范化 -> 去重/清理 -> 限速/合并 -> 在线回复策略
  -> 在线模型回复（支持时调用天气工具） -> 本地 TTS -> 播放
  -> 界面显示与桌宠 speaking 状态
```

统一消息对象只保留处理所需字段，例如平台、短期去重 ID、显示名（若用户启用）、文本和接收时间。默认不落盘原始弹幕、房间历史、Cookie 或访问令牌；诊断只记聚合计数、阶段耗时和错误类别，不记弹幕/回复正文或音频。

队列必须有界并允许策略配置：过滤刷屏/重复内容、按窗口合并相似弹幕、控制每分钟回复数、跳过过期低优先级消息。回复生成不得控制任意系统命令或任意桌宠动作，只能给出短文本、是否朗读和白名单呈现状态。新高优先级消息、用户拖拽/菜单、暂停、服务停止均可取消当前生成或播放。

## 4. 模型候选与选择方法

首轮唯一 TTS 候选是 Apple Silicon 上的 `mlx-audio` 运行路径和 Qwen3-TTS 0.6B Base 8-bit。原始权重来自 ModelScope `Qwen/Qwen3-TTS-12Hz-0.6B-Base`，固定 revision `fda1995a3162ad0488393cc366b82ca59c91c08e`、Apache-2.0；本地用 `mlx-audio==0.6.4` 转成 MLX 格式。原始快照约2.3GiB，转换后约1.9GiB。模型已在 M4 上成功加载，但尚未用参考音频验证克隆质量、首音频延迟或实时率。只有首选失败/不达标且空间预算仍满足时才评估一个备选；不并行下载 GPT-SoVITS 等模型。

LLM 首轮候选已收敛为 ModelScope `Qwen/Qwen3-1.7B`、Apache-2.0，固定 revision `4855588ea1a12789f2e965e5f52a9e4a24c94b2a`，通过 `mlx-lm==0.32.2` 转为 4-bit MLX。M4 上单模型短提示初测已通过；与 TTS 共存仅做过一次合成链路内存检查，尚未以真实弹幕评价回复质量或确定最终模型。不要按单模型分别运行的峰值推断同时运行预算。

首轮离线基准至少记录：

- 设备完整芯片型号、macOS 版本、电源状态、后台负载和环境温度条件。
- 模型准确来源、版本、量化、许可、下载大小、安装后大小、首次加载时间。
- 同时加载 LLM + TTS 的内存压力、生成实时率、首 token/首音频延迟 P50/P95。
- 参考音频格式、长度、采样率、是否提供准确转写；不得提交或上传参考音频。
- 中文数字/专名、多音字、长句、标点停顿、短句连续生成、取消后的资源回收。

基准数据未达到门槛前，不接真实直播、不把“支持流式”当作低延迟证据，也不下载多个大模型做无界对比。

## 5. 延迟和资源预算

目标是低延迟，不承诺零延迟。建议先以模型预热后的体验作为试验门槛：消息到首段回复文字 P50 ≤1.0秒、P95 ≤2.0秒；消息到首段可听音频 P50 ≤1.5秒、P95 ≤3.0秒。测量要分解网络事件等待、过滤、LLM 首 token、TTS 首块、播放缓冲，不能只报模型吞吐量。完整回复应分段生成并边生成边播放。

注意：`mlx-audio` 当前 Qwen3-TTS 实现会对每一段完整输入文本先做 prefill，再开始流式音频块生成；这不是 LLM token 到语音的端到端流式。把回复切得更短可以更早启动第一段，但多次生成会重复调用开销，需实测首段长度/延迟/自然度的折中。公开 issue 也记录过 Base 克隆路径速度异常和长句语速漂移，因此必须固定依赖版本、做短句与重复运行测试；不能用上游单次吞吐数据替代本机验收。

约40GB可用空间可启动精简基准，但并不意味着可安全容纳多个模型、构建缓存和历史下载。每个候选都要记录实际下载与展开体积；模型、虚拟环境、编译缓存和临时文件统一放到明确的本地目录并提供清理/保留策略。实现下载前先检查空间，设定系统剩余空间底线；未确认模型具体大小前不写固定总量承诺。不得为了腾空间整体删除 `.local/`、`.build/`、用户数据、唯一素材或验证证据。

服务运行时需设置消息队列上限、模型并发上限、音频队列上限、最大回复长度与空闲卸载策略；桌宠动画和 Codex 正常使用优先于语音服务。M4 上的持续 CPU/GPU/内存/温度测量是进入日用版本的门槛。

## 6. 平台接入和稳定性

B站优先作为首个适配器：先核实官方开放平台的申请条件和数据范围，再验证社区 WebSocket 客户端的协议、许可、登录方式、速率限制和持续可用性。两种路径不得混为一个“稳定官方 API”承诺。

抖音作为独立适配器后接。官方能力、开放权限和目标直播间范围必须先确认；依赖网页逆向/未公开协议的方案只能实验性启用，可能随签名、页面和风控变化而失效。不得将 Cookie、签名或登录状态写入仓库、日志或模型提示词。平台适配器可以分别禁用，异常不能影响本地合成测试或另一平台。

如平台许可、数据使用条款或接入授权不清楚，不实现真实账号接入；继续用合成弹幕完成下游验证。

## 7. 计费、隐私与失败行为

- ASR 与 TTS 在本地；在线模型和 Open-Meteo 查询需要网络。在线供应商/中转可能对请求和输出计费，连接测试也可能产生费用。
- 仅在用户配置 API Key 并主动聊天或点击测试时联网；不自动换供应商。发送给模型的内容包含识别文本，界面必须披露该数据边界。
- 当前不能为任意自定义模型统一预估费用；用户应在对应服务商/中转站查看模型单价、余额与预算限制。设置窗口必须明确费用由服务商决定。
- 参考音频只存在用户选择的位置或受保护的本地数据目录；注明用户须有权克隆和使用该声音。模型许可证、代码许可证不替代音频授权。
- 日志不写弹幕正文、生成回复、Cookie、令牌、参考音频路径或音频内容。
- 断网、平台掉线、模型错误、输出设备不可用时显示非阻塞状态；服务可重启或关闭，桌宠原有功能继续可用。

## 8. 当前执行阶段

1. 用户在应用的“模型管理”窗口设置兼容 Chat Completions 的服务商、Base URL、模型名和 API Key；Key 由 macOS 钥匙串保存。先核对具体服务商的价格与预算，再由用户主动测试，连接请求可能计费。
2. 用新版 checkout 构建进行真实语音单轮验收：选择并检测麦克风，录音、查看本地 ASR 文本、观察在线回复显示，并按用户选择验证本地 TTS。记录 ASR、网络回复和首段音频的分段耗时，不把网络耗时混作本地模型性能。
3. 服务商/中转兼容性、工具调用和天气查询逐项验证；天气仅在模型发出标准工具调用时访问 Open-Meteo。不得声称接入官方 Codex Agent。
4. 再审查 B站可用且合规的弹幕接入方式，完成后独立评估抖音。直播功能未完成前，不连接账号或直播间。
5. 规划 ASR/TTS 权重的安装、更新与删除，以及发行包运行时边界；完成失败恢复、长时资源、隐私、素材许可与真实设备验收。

上述待办不得被离线单测、构建或模拟 API 测试替代。不得未经用户配置和确认发出真实请求；实际执行证据只追加到[实际验证记录](实际验证记录.md)。
