## 任务目标

当前只需要修复一个问题：

- 桌宠第一次启动后，自主跳动／动画正常。
- 对桌宠完成一次拖拽并松手后，后续再次快速拖拽松手时，甩动弹簧／跳动可能不再触发。

请重点复现并修复这条完整路径：

```text
启动
 -> 第一次快速拖拽松手
 -> 甩动弹簧运行
 -> 弹簧结束并回到正常调度
 -> 第二次快速拖拽松手
 -> 甩动弹簧再次运行
```

不要只调整阈值，也不要强制每次松手都跳动。需要找到第一次拖拽结束后残留状态、事件状态或动画时钟没有正确清理的根因。

## 重点审查内容

请沿着真实事件链路审查，而不是只看纯物理函数：

1. `mousePressEvent`、`mouseMoveEvent`、`mouseReleaseEvent` 的状态转换。
2. 第一次松手后是否仍残留：
   - `release_spring`
   - 物理单调时钟或时间戳
   - `motion`
   - 速度采样队列
   - 拖拽锚点
   - `dragging`
   - `presentation`
   - 当前动作和镜像状态
3. 第二次按下时是否完整重置了上一次甩动状态。
4. 第二次松手是否仍然经过既有位移和速度双门槛，而不是被旧状态短路。
5. 弹簧运动是否独立于动画首帧解码、姿态混合和工作／待机换片。
6. 弹簧结束后是否回到正常外层调度，而不是留下会阻止下一次拖拽的完成标记。
7. 交互中断、再次拖动、窗口隐藏、减少动态效果和屏幕边界变化是否正确清理状态。

必须保持既有语义：

- 轻拖轻放不触发甩动。
- 明确快速拖拽松手才触发甩动。
- 甩动保留水平和垂直速度。
- 地面、顶面和侧墙碰撞规则不被回退。
- 甩动姿态在弹簧收敛前不能被普通待机提前清掉。
- 不通过降低门槛或强制跳动掩盖状态清理问题。
