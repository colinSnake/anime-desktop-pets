# 多厂商模型迁移第一段：协议核心实施计划

**目标：** 按用户本轮明确要求参考独立多厂商设计，先落地可测试的连接／模型／路由和四协议核心，不退回单服务数据结构，不以不可用的 UI 枚举冒充接入。

**架构：** 沿用已确认的 Electron／Fastify 主栈；原设计中的 Swift 宿主直连仅是当时宿主约束，不能覆盖后来主栈决定。服务内部将配置校验、路由快照、协议编码解析和有界 HTTP 分离。此段不挂生产路由／凭证存储／renderer 桥，正式聊天仍禁发；后续凭证及页面接线必须消费此核心，不能各自拼厂商 JSON。

**技术：** TypeScript、Node.js 24、内置 fetch／Web Streams、pnpm 10.32.0；不安装依赖。

**依据：** `../specs/2026-11-16-model-management-multi-provider-design.md`。保留原稿和其他未提交改动，不将其全文改写为新栈设计。

## 文件职责和接口

- `apps/app-service/src/models/config.ts`：schemaVersion=2、32连接／每连接33模型、双层默认、能力未知、受限兼容项和地址校验；纯函数 `validateConfiguration`／`resolveRoute`，路由指纹不含显示名，但含协议／地址／鉴权引用／模型 ID／兼容项。
- `types.ts`／`common.ts`：规范消息／工具／回复／用量与固定错误；私有原生往返数据仅留 WeakMap，按连接和路由指纹限定，跨厂商只编码公共消息，不泄漏签名或 response ID。
- `chat-completions.ts`／`responses.ts`／`anthropic.ts`／`gemini.ts`：显式协议路径、鉴权、消息和工具往返、结束／拒绝／用量、分页模型发现。不执行工具，不按模型名字猜能力。
- `protocols.ts`：固定四协议注册表；不通过域名猜测或失败自动切协议。
- `client.ts`：首次 await 前固定配置／消息／预算；在线调用时才读取注入凭证；不读取磁盘、环境变量或真实账号。最多3个活动请求，正文128KiB、响应1MiB、发现累计4MiB／8页／256模型；文字2048 token／60秒、语音160 token／25秒；已知输出能力只下调预算。取消／超时／关闭拒绝迟到结果，禁止自动重试、重定向和原始错误泄漏。
- `apps/app-service/test/model-*.test.ts`：配置／路由、四协议矩阵与本地假 HTTP 服务。测试不访问外网，不使用真实凭证。

## 实施补充（2026-11-18）

- 允许先保存缺Key的API-key连接；请求／发现缺引用时在vault读取前返回固定错误。每条已配置连接的凭证版本引用独立，不因显示名或其他连接变化串用账号。
- 对照官方SDK格式补齐Responses公共assistant使用easy-message文本、同路由保留必要item ID／status／phase；Gemini可缺原生调用ID和参数，但不伪造同路由原生ID，工具结果按原调用顺序输出。私有原生信息始终不出现在规范回复JSON中。
- 独立只读代码审查发现3处协议问题，逐项先写失败回归再修复：Gemini使用`parametersJsonSchema`映射通用JSON Schema；无原生ID的同名并行调用按原顺序配对；Responses `incomplete/content_filter`明确为拒绝。预算耗尽且无可见正文单独返回length，不报告空成功。
- 分阶段核心不挂生产路由，不提供磁盘配置写入、凭证仓库或页面；连接撤销、持久化冲突／恢复、发现刷新合并及业务用途接线仍在后续纵切实现，不把普通内存快照等同这些功能。
