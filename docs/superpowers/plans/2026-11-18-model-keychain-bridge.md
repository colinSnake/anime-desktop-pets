# 多厂商模型迁移第三段：macOS Keychain 与可信管理桥

继续已确认的独立多厂商设计。以当前未提交的第二段实现为工作基线，保留相关文件和验证，不重写设计原稿或重复搭架构。

- [x] 先写 Keychain 适配器的合成进程回归：固定可执行、零参数、精简环境、stdin 路径、命名空间、协议边界、缺项、拒绝／无效输出／超限／超时和子进程收尾。然后实现 macOS Security.framework 小型助手及受限 TypeScript 适配器。仅在显式变更凭证或内部未来请求时访问，锁定或需交互时失败，不打开系统提示。仅对系统默认 Keychain 的固定应用 service 与随机 account 精确新增和读取；删除只用于撤销同一未发布且持有匹配收据的新条目。没有更新、扫描或明文回退。通过构建阶段原子发布原生助手，自动化仅用非法输入验证二进制协议入口，永远不让合法指令触达真实 Keychain。
- [x] 先写本地服务注入测试，覆盖固定路径、回环鉴权、未知字段／query／大小边界、缺 Key 保存、替换失败隔离、双层默认、删除、脱敏与关闭。实现 `/v1/models` 和三个固定管理动作 `save`／`default`／`remove`，只使用隔离仓库；凭证存在状态来自引用，不探测系统 Keychain、不表示连接通过。返回配置前去掉凭证引用。不建立模型请求客户端，不加发现、测试连接或聊天路由。
- [x] 先写可信主进程传输回归，覆盖固定方法、验证输入与有界响应、拒绝额外字段／重定向、传输中断的写入结果未知。接入 `ServiceProcess` 固定方法与可信模型目录；不接 preload、IPC handler 或 renderer 模型配置／凭证输入。编译成品的 Node fork 烟测只用临时模型目录、显式缺 Key 保存和原生助手非法协议测试。
- [x] 执行定向、`pnpm run check:cross-platform`、项目检查和空白检查，记录真实结果；保持桌宠布局和播放器及旧资料隔离。若受影响，复跑可信 Fusion/offscreen 移植回归。

macOS 适配器用独立子进程调用系统 API，使禁用 Keychain 交互的设置只作用于该助手；凭证材料只经受控管道传递，不在 argv／env 中。以固定路径从已发布的构建输出加载，不从 bootstrap／renderer 指定二进制。依照 macOS SDK 的默认 Keychain 与限定搜索范围接口，当前针对开发产物；签名后的授权、重建后的访问延续与真实项生命周期仍须单验收。Windows/Linux 不接 Keychain 后端或生产模型目录。
