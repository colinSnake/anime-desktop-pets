# macOS Codex 启动视频迁移计划

迁移 H03 的显式客户端启动和旧视频播放。继续使用仓库已有的本机 `resources/media/startup.mp4`（含原音轨），不转码、不改媒体授权。普通 `dev:desktop` 只打开工作区；原生菜单「打开 Codex」和独立 `dev:desktop:codex` 入口明确请求启动。只在未检测到 Codex 的冷启动路径播放；已经运行或运行状态不确定时直接调用系统打开，不盖住现有会话。不把系统接受打开请求当成窗口或内容已就绪，不迁任务跟随、窗口匹配和 AX。

1. 先写离线失败测试，验证固定启动命令、重复点击合并、热启动无视频、媒体验证失败时仍打开、切换和退出后的迟到事件无效。用假窗口与时钟验证首帧前不显示、8 秒加载与 30 秒总上限及完成／跳过／崩溃清理。所有命令由测试注入，不运行系统 `open`。
2. 在 Electron 主进程装配固定 macOS `open -b com.openai.codex`，无 shell、自定义路径或额外参数。只允许原生菜单和显式 CLI 模式进入。窗口和命令并行；跳过只关动画，失败或超时关动画并给固定反馈；退出只等自有命令和销毁自有窗口。
3. 播放窗口使用隔离内存 session、无 preload、无通用 IPC。固定 `pet-startup://player` 只允许读取页面、样式、脚本和有大小上限的单个 MP4；媒体用单段 Range 流式读取，拒绝符号链接、非普通文件和非法范围。只消费自身主 frame 的固定播放状态信号；首帧后非激活显示，跳过按钮／Esc／Cmd+. 可关窗。复用旧片比例和音轨，无桌宠接管或真实桌面测试。
4. macOS 构建可选复制现有忽略的本机原片；没有媒体的 checkout 仍正常构建。测试复制、缺失、超限和链接，验证构建产物中的固定资源与安全边界。运行定向回归、完整 `check:cross-platform`、可信 Fusion/offscreen Qt、项目和 diff 检查。
5. 同步双语 README、迁移和退役清单、路线图、开发及验证文档。旧 Swift 宿主与冻结 helper 不变；真实播放、音量、焦点、冷／热启动和多屏／Space 留待用户自行验收。
