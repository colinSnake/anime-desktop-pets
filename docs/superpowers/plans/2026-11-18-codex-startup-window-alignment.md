# macOS Codex 启动动画窗口对齐实施计划

继续迁移 H03。显式冷启动的动画先沿用鼠标所在屏幕的居中布局；首帧显示后短时尝试只读对齐。固定 macOS 助手按 `com.openai.codex` 取得唯一可见进程，只从当前屏幕上的窗口中选唯一、可见、零层且足够大的窗口；只输出有界整数矩形，不返回窗口标题、进程标识或截图，不调用权限请求。外部 Codex 窗口的 AX 调整不在本批。

1. 先为主进程探针、显示器几何、对齐生命周期和构建隔离写失败回归。合成覆盖非法输出、超时／取消、负坐标显示器、窗口跨屏或超出工作区、全屏形状、稳定样本、串行查询和结束后迟到结果；不执行真实窗口查询。
2. 实现独立无参助手 `codex-window-bounds`，只在 macOS 构建暂存；主进程用固定参数执行，有输出、耗时、取消边界。既有存在性探针和状态栏观察保持原样。构建冒烟用非法参数验证前置拒绝。
3. 播放首帧非激活显示后，最多尝试 12 次、总计 8 秒，等待两个连续相同的有效矩形和落点。矩形须完整落在恰好一个显示器工作区且不覆盖整屏；在其内居中放置上限 1280pt 宽的 16:9 动画窗，仅 `setBounds` 一次。无法匹配时保留原居中播放；跳过、播放结束、故障、启动失败或宿主退出时取消定时器和自有助手，不应用迟到结果。无 IPC、无窗口焦点或外部窗口写入。
4. 实现后运行定向回归、完整 `check:cross-platform`、可信 Fusion/offscreen Qt、项目及 diff 检查。同步双语 README、迁移和退役清单、路线图、开发及实际验收记录。旧 Swift、冻结 helper、生成源码保持原样；真实焦点、冷启动、多屏／Space、权限与外部窗口调整仍待验收。
