> 实施按 `superpowers:executing-plans` 顺序推进；已有设计确认，不重新评审方案，不自动提交。

**目标：** 先交付 macOS 固定数据根与显式迁移，再交付按桌宠实例隔离的已完成聊天历史。

**架构：** 主进程使用固定选择记录和目标收据识别唯一权威根。迁移仅在服务确认退出后持有既有 writer 门禁，在目标同卷校验和发布；SQLite 历史只由服务写入，回看与在线上下文分开。

**规格：** [本机业务数据与聊天历史设计](../specs/2026-11-20-adpets-local-data-design.md)。Node 24、pnpm 10.32.0；无真实数据、Keychain、厂商调用或桌面启动；其他平台保持原行为。

1. 数据根：先在 `apps/desktop/test/local-data-root.test.ts` 覆盖新旧选择、完整复制、互斥、坏数据、失败及重启；再实现 `local-data-root.ts` 和共用格式校验。目标发布前同步已确认的选择记录；未发布且安全可判定才撤销，任何歧义均停写。
2. 迁移接线：主进程固定无参 IPC、原生确认、停止和退出；`AdvancedPage.tsx` 仅显示状态，打开所选目录，不接收任意路径。确认配置和清理条件，完成阶段一测试。
3. 历史：先以临时 SQLite 覆盖提交去重、分页、实例隔离和清空；在在线完成点写入，固定服务/IPC 只开放分页、清空。回看状态不参与上下文组装。补服务、桥和 UI 验证。
4. 验证：用临时源码副本运行 `pnpm run check:cross-platform`，用合成输入做页面检查，更新双语 README 和实际验证记录；真实退出、迁移及 Keychain 留给授权后验收。
