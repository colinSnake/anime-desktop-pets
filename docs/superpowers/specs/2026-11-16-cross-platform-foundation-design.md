# 跨平台 TS/Python 架构与迁移设计

> 2026-11-16 后续优先级修正：用户要求先完整迁移现有 macOS 功能，并按新设计改善页面；Windows/Linux 播放器阻塞保留但暂缓移植，不作为 macOS 业务迁移前置。本文历史实现范围/验证不变，后续顺序以[macOS 功能迁移清单](../../macOS功能迁移清单.md)为准。

日期：2026-11-16。状态：用户已确认长期统一 TS/Python，支持 Windows、macOS、Linux，并接受 Linux 首版优先 X11/XWayland、原生 Wayland 能力受限；已授权先更新文档并开始开发。

## 1. 目标与非目标

- 长期主开发语言为 TypeScript/Python；React/CSS 承担管理 UI，Electron 承担桌面宿主，Node.js/Fastify 承担本地应用服务，Python 保留动画与推理职责。
- 当前 Swift/AppKit/SwiftUI 应用仍是既有可用实现，迁移基础不等于替代版已经交付；保留旧构建、数据及回退路径。
- 不修改官方 Codex，不迁移真实用户资料，不安装、不启动真实桌宠、不启用登录服务、不执行付费请求。
- 首阶段不迁聊天、记忆、模型管理、语音推理或 Qt 播放器；不把诊断 worker 称为完整桌宠。

## 2. 模块边界

| 路径 | 职责 |
| --- | --- |
| `apps/desktop` | Electron 主进程、安全 preload、窗口与进程监督 |
| `apps/workspace-ui` | React/TypeScript/CSS 管理工作区；只消费窄桥接 API |
| `apps/app-service` | Fastify 本地服务、安全边界、状态快照与 Python 监督 |
| `packages/contracts` | 版本化请求/响应、跨平台能力状态及运行时校验 |
| `apps/runtime-bridge` | 纯标准库 NDJSON 诊断 worker 与独立 guardian，不导入 Qt、MLX 或用户配置 |
| `apps/pet-runtime`、`apps/speech-runtime` | 既有 Python 实现，本阶段保持不变，后续按接口接入 |

Electron 主进程启动独立 utility process 运行应用服务；经受限 IPC 完成引导，传入每会话随机凭证。React 通过 preload 的固定方法调用主进程，主进程请求本地 Fastify；页面不得获得凭证、端口、文件系统、任意 IPC 或进程启动能力。Fastify 仅绑定 `127.0.0.1` 随机端口，不提供开发服务器、不开放 CORS。业务入口是版本化路由，领域逻辑不得堆入路由。

## 3. 首阶段行为及失败处理

- 工作区显示平台能力、真实本地服务状态和诊断 worker 状态；未迁移页面明确标注未接入，不显示可用的聊天/模型/语音功能。
- Python 诊断仅由显式点击触发；服务常驻并不自动启动宠物、录音或读取用户资料。
- NDJSON 使用协议版本、请求 ID、固定命令、消息大小上限和超时；stdout 仅传协议，禁止回显输入或凭证。并发探测共享同一进行中的操作。
- guardian 作为独立标准库监护进程创建实际 worker。父服务死亡导致 stdin EOF 时，guardian 仍独立执行自有 worker 的 EOF/终止/强杀与 wait；不依赖服务能运行清理。输出在拼接前检查上限，首次协议故障后清空缓冲并只排空，不继续累计。
- worker 缺失、协议错误、超时和异常退出返回明确失败状态；正常 EOF 退出。关闭服务取消待完成操作，先请求退出，再仅针对自己创建的子进程执行有界终止与回收。
- 应用关闭窗口即退出本阶段开发壳；退出时先收服务/worker，再退出 Electron。初始化失败不得留下后台服务或显示伪成功。服务崩溃清除连接状态，桥接失败显示错误，不无限重启。
- 不提供任意命令执行、任意 URL 请求或文件路径接口。导航、弹窗及权限请求默认拒绝；仅可信主 frame 可调用桥接。CSP 禁止远程脚本和网络连接。

## 4. 平台承诺

- Windows/macOS：目标完整支持，但必须分别验证窗口、透明、拖拽、缩放、托盘、权限与安装；本机测试不可代替其他系统。
- Linux：区分 X11、XWayland、原生 Wayland、未知会话。完整桌宠目标首先验证 X11/XWayland；Wayland 全局定位/置顶/窗口跟随受限，不通过环境名声称已验收。
- 首阶段各平台只声明目标/限制，实际宠物控制和语音均为未接入；不能因 Electron 能启动就声称三端交付。
- 现有 MLX 语音入口及 macOS arm64 锁文件不构成跨平台后端；后续拆 ASR/TTS 接口并分别验证。
- Python interpreter 本阶段由 `PET_PYTHON` 或平台默认命令提供；用户无需 Python 的独立发行包、签名、公证、更新均为后续工作。开发构建不生成可发布安装包。

## 5. 数据与迁移

本阶段不创建产品配置、聊天库或凭证记录，不访问既有产品数据。以后每类数据只有一个权威写入方，迁移需格式版本、备份、显式确认和回退验证。既有多厂商模型管理设计保持独立，不把其 Swift 实现作为跨平台新投资；后续审阅并迁入 TS 服务，不在本阶段顺带实现四协议。

## 6. 验收与阶段

1. 基础：协议与能力单测、Fastify 真实本地请求、安全拒绝矩阵、真实 Python 进程探测/错误/超时/回收、React 静态与客户端校验、TS 检查及生产资源构建。
2. 播放器接入：在不改变解码/物理线程边界的前提下接现有 Qt helper，验证三端构建和窗口最小矩阵。
3. 产品迁移：聊天、配置、角色、记忆、模型、任务适配逐项移交写入权；保留原回归语义。
4. 发行：各平台独立构建、凭证安全存储、签名/安装和真实桌面验收；达到门槛后退役 Swift。

所有记录区分自动测试、构建、真实桌面与发行证据。未执行 Windows/Linux、Electron 桌面启动、Qt 播放、语音、长期资源或安装验收时，必须明确写未执行。

## 7. pnpm 与 Qt 预检补充（2026-11-16）

用户后续明确要求只用 pnpm，固定 pnpm 10.32.0，根 workspace 定义与唯一锁文件分别为 `pnpm-workspace.yaml` / `pnpm-lock.yaml`，构建脚本只批准锁定 esbuild 版本。服务在所属包输出并通过桌面包的显式 `workspace:*` 依赖导出入口；禁止依赖 npm 遗留平铺或 `shamefully-hoist` 维持构建。

继续推进播放器接入前，先增加不导入 Qt、不启动窗口、不读写用户资料的 `check:qt` 必要条件检查。它只发现 Python/模块/适配器源码，不验证动态库、动画素材、字体、真实 IPC 或桌面；Windows 既有 POSIX IPC 必须显式阻塞。检查输出不包含路径/异常/密钥；模块缺失不得自动安装。此增量不修改既有冻结 helper 输入。

审查后的安全/构建补充：Qt 预检使用 `-I -S -B`，不自动执行环境 site 初始化、`.pth` 或 `sitecustomize`；直接发现解释器明确的 package 路径，不加载第三方包。Node 严格验证/重建固定报告。新构建先完整输出到专属暂存目录，所有步骤成功才备份并提升两包 dist，普通失败回滚，恢复失败保留备份；不承诺掉电/强杀时跨目录原子性。
