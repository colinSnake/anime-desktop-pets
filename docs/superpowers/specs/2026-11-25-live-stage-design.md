# 桌边小崽直播台：首版设计与开发交接

2026-11-26 · 用户确认将六套最新 2D 布景作为正式版本，无需兼容迁移。本文同步记录最新范围；实际交付与验收分别见[使用指南](../../本机直播台使用指南.md)和[实际验证记录](../../实际验证记录.md)。

## 1. 做什么

把「直播管理」的主流程从填写房间草稿改为**搭台、打开画面、操控桌宠**。当前实现提供 **一个 16:9 舞台、一只龙妹、六套 2D 布景、三个主播互动动作和一个 OBS 浏览器源地址**。不接平台账号仍可开启本机画面和手动互动；弹幕演练仅在用户提交时调用第一个已保存服务商默认模型，与真实平台事件明确区分。

「直播台」是节目画面，不是截图、桌面镜像或已连接的平台直播间。OBS 负责场景编排、录制及推流，开播和停止推流由用户在 OBS 操作。每次显式开启本机舞台后，支持环境在后台用已保存的音色准备固定动作台词，不阻塞画面，也不自动发声。Agent 演练回复在用户提交后才生成和合成。弹幕演练只有用户点击提交才调用第一个已保存服务商的默认模型，可能计费；不接入真实弹幕、礼物、麦克风或桌面音频，也不发平台消息、不控制 OBS。

## 2. 舞台与操控

舞台以 1920 × 1080 为设计坐标，按 16:9 等比布局。图层从后到前：**原创布景 → 透明 WebM 龙妹 →（前三套布景的）桌沿前景 → 对白**。前三套沿用桌面构图；蓝天草原、森林篝火和录音棚按最新 2D 定稿分别站在草地、林间空地和演播毯上，不放桌子。角色锚点与对白安全区按布景调整；对白留在安全区，不被桌沿盖住，画面中不出现控制按钮、诊断信息、地址、私聊或桌面窗口。使用本项目原创布景图层、CSS 和已有获准的本机动画，不依赖在线字体、图片或脚本。后三套背景源 SVG 和优化 WebP 随应用资源打包；人物动画仍取自已锁定的本机原片准备，不把整套原片复制到资料根。

「直播管理」主区展示舞台状态和最少操作：

- **布景：**正式版本含暮色小屋（默认）、雨夜阁楼、云海露台、蓝天草原、森林篝火、录音棚六套。用数值框和加减键按百分比摆位；每套单独记忆龙妹横向位置和大小，选中项及摆位显式保存后下次恢复。森林的横向上限为 55%，避免角色摆位压到右侧篝火；三套新背景把角色落点提高至场景地面。舞台停止时可编辑；运行中可点布景卡不停台切换，直到下一场景的双层素材解码后再同步替换，保持同一 OBS 地址和动作状态。
- **输出：**「开启直播台」「预览舞台」「复制 OBS 地址」「关闭直播台」。预览只在用户点击后打开隔离的只读窗口，与 OBS 使用同一舞台页面；复制由现有可信工作区的固定操作完成。状态使用「未开启／准备中／舞台可用／不可用」等本地措辞，不显示「已开播」「已连接平台」。
- **互动：**只突出三项主播动作。启用舞台后可用；动作首帧呈现后显示对白，片段播完且满足最短阅读时间后，清对白并回到循环待机。互动不驱动原桌面桌宠，不改实例位置、行为偏好或启动状态。
- **弹幕演练：**在管理页输入一条测试内容后，只有点击「发送演练弹幕」才经 Pi 调用已保存的默认模型。模型只看到这条弹幕，不带聊天历史、私有角色资料或附件；生成文本与对应音频就绪后才一并发布成字幕与 OBS 节目声轨。失败不触发预设回复；手动动作优先，触发手动动作、关台或暂停会撤销演练。它不代表接入了真实平台。

| 操作 | 固定动作 ID（现有目录） | 固定台词 |
| --- | --- | --- |
| 打招呼 | `01`（招手／打招呼） | 嗨，我是龙妹，欢迎来直播间！ |
| 开心一下 | `18`（庆祝） | 今天也要开开心心！ |
| 比个心 | `20`（比心） | 给你比个心～ |

默认待机 `idle`。连续点击不积长队：新主播指令可替换未完成的旧动作；弹幕演练不可抢占手动动作。舞台先显示新动作首帧再替换画面；坏片段回到待机，不冒充动作播放成功。阶段性验收只需要按以上清单，不为首次上线接齐全部 35 段。

## 3. 模块与数据流

```text
工作区「直播管理」
  └─ 固定桥：读写六景摆位 / 显式启停 / 三种动作 / 弹幕演练
      └─ Electron 主进程：舞台会话、动作代次、白名单素材、回环只读源
          ├─ 可信本机服务：读写权威业务根中的舞台配置；按用户显式提交调用 Pi/模型并合成回复
          └─ 舞台网页：只读画面快照 + 允许的舞台媒体
              ├─ 本机预览窗口
              └─ OBS 浏览器源
```

| 位置 | 职责 |
| --- | --- |
| `apps/workspace-ui/src/pages/LivePage.tsx` | 沿用现有工作区外壳；呈现布景、会话和操控。无桌面桥的普通网页环境只显示未连接状态，不模拟已开启。 |
| `packages/contracts/` 与 `apps/desktop/` | 固定能力和输入校验。复用可信工作区主 frame 校验；舞台控制和原桌宠显隐／启停分开。舞台会话由 Electron 主进程持有，不新增常驻守护进程。 |
| `apps/app-service/` | 当现有业务根和写锁可用时，负责版本化配置的私有读写；OBS 不连接 app-service，不获知其鉴权信息。 |
| 独立舞台网页资源 | 只接收必要的布景数值、动作及对白快照。复用现有 `clip-catalog.json` 的来源、锚点及首帧／换片原则，不加载带桌面 IPC、拖拽或额度能力的原播放器页面。 |
| `apps/app-service/src/live/` 与桌宠 Agent | 校验用户手动提交的单条弹幕，只使用首个已保存服务商默认模型；不读取聊天历史、私有角色资料或附件，生成回复再交给本机语音合成。 |

### OBS 输出边界

- 独立 HTTP 监听只绑定 `127.0.0.1` 随机端口，严格验证 Host；每次显式开启生成独立、不落盘的随机会话标识。示意地址为 `http://127.0.0.1:<port>/stage/<session>/`。OBS 仅使用这个本机地址；关闭后旧地址不能重用，再开需复制新地址。
- 只暴露带会话范围的舞台页、固定构建资源、只读快照和白名单媒体。媒体按固定 ID 解析，经现有可信本机素材准备／校验，支持浏览器所需的有界 Range；不开放目录、任意路径、网盘 URL、转发代理或任意写入。现有工作区桥、业务根服务端口和密钥完全独立。
- 页面与资源均不引用第三方，设置限制外部加载的内容安全策略、`no-referrer` 及防缓存；不在日志中记录完整舞台地址，不开启跨源 API，OBS 页面没有 preload 或 Node 权限。管理页或预览关闭不等于平台断开，也不等于停止推流。
- 舞台用同源短轮询读取最新快照（约每 250 ms，最多一条在途，超时 2 秒），不为每条动作建持久事件流。会话由 URL 区分，快照具备单调动作代次和剩余有效时间；页面首次载入／重连从待机开始，不重放之前的互动，只接纳后续新动作。状态失联时清除对白、停止媒体并显示中性停用画面，不展示本机路径或异常正文。
- 关管理窗口不影响已显式开启的舞台；点「关闭直播台」、全局暂停或应用退出先阻止新动作，再吊销访问、关闭本项目监听并回收本项目预览和临时素材。解暂停／重启不自动开启。已关闭指的是本机舞台；需要紧急切掉 OBS 画面或停推时，仍由主播在 OBS 隐藏源／停止推流。

OBS 参考：[OBS 官方 Browser Source](https://obsproject.com/kb/browser-source)。首版设置流程：在 OBS 添加「浏览器源」，粘贴管理页复制的本机地址，设置宽 `1920`、高 `1080`，在预览里确认画面；无须登录平台或点击推流。

### 持久化与素材许可

六套正式布景在当前权威 `~/.adpets` 业务根独立保存到固定路径 `live/stage-profile.json`：文件内容采用 `schemaVersion: 2`、六个 `selected` ID 及六组 `position`／`scale`。横向锚点默认为 50，比例默认为 100；森林范围为 25–55，确保保留篝火构图，其余横向范围为 25–75；缩放范围均为 75–125。显式「保存布景」经可信服务原子写入；目录 `0700`，文件 `0600`。运行时只读写 schema v2，不自动读取、转换或迁移旧 schema；文件不存在时直接使用六景默认配置。损坏、符号链接或写入未确认时提示重读，不自动重置。重启读取已存的六景布景，但不恢复开启状态、地址、动作或对白。

不保存平台房间草稿、凭证、观众正文与身份，不引入遥测。开发和自动化可用项目自制的占位素材；公开使用龙妹动画、背景、字体或参考音色之前，分别确认使用权限，不能把本机素材可播当成可公开直播或再分发。素材缺失时管理页说明原因，不自动下载；关闭后不删除任何原片或用户资料。参见[第三方来源与素材边界](../../../THIRD_PARTY_NOTICES.md)。

## 4. 实施顺序与验收

六套观众侧 16:9 布景稿已于 2026-11-26 定稿：暮色小屋、雨夜阁楼、云海露台、蓝天草原、森林篝火和录音棚。后续以此套素材作为当前版本，不保留三景兼容入口或配置迁移。实现和验收关注 1920 × 1080 显示、布景分层、角色安全摆位、对白安全区及运行中换景，不以旧稿覆盖最新版。

| 顺序 | 独立交付与验证 |
| --- | --- |
| **1. 六套布景与舞台** | 六张正式卡片、六套资源白名单和配置都必须齐全；三套新景无桌沿，并按各自地面锚点显示。覆盖六景启台、运行中不停台切换、桌沿层解码失败时保留旧画面、角色与对白安全区。 |
| **2. 本机控制、保存和演练** | 用临时业务根验证 v2 配置、六套独立摆位、旧配置文件保持原样且不被读取、重启不自启、关闭后旧地址失效及固定权限边界。演练只按显式用户动作生成，不发送聊天历史、私有角色资料或附件；网络模型调用可能计费。 |
| **3. 验收 OBS** | 经用户明确授权后，在 OBS 本机预览逐景核对六套、三个动作及可选声轨；不推流、不录麦克风或桌面。OBS 实际电平、监听及听感仍需手动验收。 |

自动化优先使用合成视频、有界状态快照和临时目录。实现后运行对应 TS／构建回归及 `pnpm run check:cross-platform`，将实际命令、失败、跳过及未覆盖边界写入[实际验证记录](../../实际验证记录.md)，同步使用指南和中英文 README。离屏预览不是 OBS 实测，OBS 本机预览也不是公开推流验收。

## 5. 后续阶段与准入条件

1. **真实平台接入。** 优先按 [B 站直播接入准入方案](2026-11-24-bilibili-live-admission-design.md)确认项目审核、主播授权、事件资格及数据用途；从单房间只读文字事件、脱敏计数验收开始。获准后再启用规则匹配（例如问候触发预设动作），不把来信原文、用户资料、礼物或付费留言自动公开播出。收事件、公开回应、转交在线模型是不同的授权边界；未获准不打开相应能力。不使用 Cookie／爬取替代官方流程。抖音、竖屏和自动回复另作准入确认。当前没有平台账号连接或真实观众弹幕接入。
