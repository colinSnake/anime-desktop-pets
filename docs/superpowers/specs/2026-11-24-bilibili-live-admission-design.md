# B 站直播接入：准入复核与候选方案（2026-11-24）

**结论：先推进合成本地演练；真实场次和线上模型转发默认不上线。** 当前只有直播事件的去重、时效、限速和手工回合优先级，没有平台凭证、官方场次所有权或专用输出。已有的聊天本机播报不是直播输出。

## 官方证据与尚未确认的条件

- [快速开始](https://open-live.bilibili.com/document/849b924b-b421-8586-3e5e-765a72ec3840)：开发密钥在入驻审核后提供；项目另有提交审核流程。接收消息种类需提前申请；默认 client 模式为单房间连接。没有验证本项目申请状态，也不假设当前账号具备任一权限。
- [应用 API 列表](https://open-live.bilibili.com/document/eba8e2e1-847d-e908-2e5c-7a1ec7d9266f)及[长链数据协议](https://open-live.bilibili.com/document/657d8e34-f926-a133-16c0-300c1afc6e6b)：互动项目用已审核的项目 ID 和主播身份码开启；返回场次和长连信息。长连心跳与项目心跳用途不同，主动退出须结束项目场次。普通房间号不替代授权，也不作为可任意探测的地址。
- [长链命令说明](https://open-live.bilibili.com/document/f9ce25be-312e-1f4a-85fd-fef21f1637f8)：普通弹幕事件与表情、礼物、付费留言等应分开处理；帧可能携带不需要的用户资料。首版只考虑当前明确授权的单房间普通文字，不将事件整包传给 Agent。
- [开放平台管理规范（细则）](https://open-live.bilibili.com/document/f6017467-1182-fd2b-7a96-793b9afb911a)第 12 节：项目需如实披露必要数据用途及范围；对向第三方展示以及未经授权使用账号、消费和弹幕等数据有明确限制。本次未找到足以确认「将真实弹幕正文发送给用户选择的在线模型」得到允许的证据。**平台接收授权不等于转发授权；删掉昵称也不自动改变正文的数据边界。** 在平台及相关用户授权未独立确认前禁用真实弹幕到在线模型，包括自动回复和“仅去标识化文本”两种模式。

只读取官方公开文档；未打开账号、提交审核、发送凭证、启动场次或连接直播间。若控制台与公开文档不一致，以平台对本项目确认的准入、数据用途与上线要求为前提，不默认执行。

## 选项及建议

| 方案 | 结论 |
| --- | --- |
| 仅填房间号，使用网页监听、账号 Cookie 或绕过项目授权 | 不采用；无法明确场次、授权范围和可靠退场。 |
| 一开始接官方平台并把真实弹幕交给现有在线聊天 | 不采用；混入私聊资料和计费路径，也没有真实弹幕转发依据。 |
| 先合成演练，再接官方单房间只读，最后分别验收对外处理和输出 | 推荐；不以个人账号、第三方服务或真实发布为实现前置，不误报已连接。 |

## 拟实施顺序与验收门槛

1. **合成演练。** 在现有直播调度上增加固定、无账号、无出站、默认不发声的演练入口：只使用内置合成事件、虚拟提供方和可丢弃的本机输出，显示接纳／去重／过期／限流／停止等计数；不允许 renderer 注入任意直播文本、URL 或凭证。在接线前用确定性时钟验证交换连接代次、停止、手工优先、没有私聊上下文、无记录正文及无真实模型调用。此阶段不需要真实平台授权。
2. **官方只读接入。** 在审批、所需消息类型及数据用途都核对之后，选择单房间 client 模式。凭证只在受保护的本机进程和系统凭证库，renderer 不接触身份码回读、开发密钥、长连地址或握手票据。独立进程拥有明确的开始、心跳、停止和清理；校验来源房间、帧类型、大小、时间和代次，停止后拒绝旧事件；关闭场次结果未知时不自动重开，也不报告退出成功。只用脱敏计数验收首次真实连接，不把真实弹幕正文转发给模型、显示给第三方或持久化。
3. **专用输出。** 输出来源与聊天和气泡独立，默认关闭；先验收合成文本、有界队列、取消和退出，确认不会读出私人资料或录音回流。真实公开播放单独启用且可立即停，不自动把回复发送回直播平台。真实内容转交外部生成服务和公开播放分别要求数据与用途已明确获准；未确认时保持本机合成演练，不换非官方通道规避限制。

**复核：** 每个阶段单独可验收，直播不会变成普通聊天的隐式输入或绕开材料审批。后续可在假房间先把停止、限流与输出走通；本阶段仅复核方案，不宣称直播功能已交付。
