# 桌宠统一 Agent 内核设计（2026-11-24）

## 决策与范围

用户确认以 GitHub 开源内核重新设计，允许验证后淘汰旧 Agent 实现和其专属数据；不要求保留旧执行链或强制迁移旧 Agent 数据。保留现有模型管理、Keychain、桌宠素材、项目与有效聊天资料，避免无意义的数据破坏。本次完成内核替换、普通文字与材料工具统一循环、持久运行状态、Agent 配置入口、语音/直播通道的可测试调度基础及旧运行依赖退役。真实麦克风、ASR/TTS 新设备流程、B站/抖音账号接入不是本次交付，不声称已经完成。

## 选型证据

- 官方仓库：https://github.com/earendil-works/pi 。Agent 包 README 固定到 `v1.6.0`（`faac585884ae2c013a6b1400f3e9e77f10b34bac`）：https://github.com/earendil-works/pi/blob/v1.6.0/packages/agent/README.md 。
- 2026-11-24 核对 registry 发布包：`@earendil-works/pi-agent-core@1.6.0`，MIT，Node >=22.19.0；项目仍固定 Node 24.x 和 pnpm 10.32.0。使用同版 `@earendil-works/pi-ai` 的协议类型/事件流，不启用其内置 provider、Shell、MCP 或 coding CLI。
- 包有自定义 streamFn、Agent 事件、顺序工具执行与 abort。版本包声明优先于可能漂移的 main 分支文档。
- Pi 不是语音框架、平台直播 SDK 或权限沙箱；取消依赖宿主适配器遵守 signal，故仍由宿主控制超时、资源占槽和清理。相较旧 DSH 外部 worker + 回环模型转发，减少了执行与转发层，允许直接复用现有受保护 provider；这是架构收益，不是未经测试的稳定性保证。

## 唯一执行链

输入（文字 / 已识别语音 / 已筛选直播事件）→ 会话与运行准入 → Pi Agent → 服务拥有的模型适配器 / 只读材料工具 → 事件与结果 → UI / 有界语音输出适配器。普通文字和带材料任务共用同一 Pi 循环。旧独立任务接口如仍被已有桥使用，仅作为兼容输入映射，不保留另一套循环；无固定 verify_task_tools 预调用、无隐式服务商切换与自动重试。

- Pi 永远不获取 API Key、credentialRef、真实 URL、全盘文件路径。自定义 streamFn 回调调用现有 ModelManagement；每轮出站继续复核连接版本、实例与逐项资料授权。
- 仅提供本轮已授权内存材料的 list/read/search 三个固定只读工具。参数、工具次数、循环轮数、返回长度及总上下文有界；未知工具/坏参数不执行。材料不是指令。
- 普通“你是谁？”走模型而非正则截获。查看本机资料保留显式命令/按钮，与在线文字语义分开。
- 请求去重、同实例互斥、全局并发上限、超时、取消、停机门禁继续由产品控制。拒绝或取消必须终态化；清理未确认不释放执行槽、不伪装成功。

## 持久化与安全

`~/.adpets` 已存在，不另建兼容根或回退：

```text
~/.adpets/
  models/                    # schema v2 与脱敏探测记录；凭证正文仍在 Keychain
  agents/<pet-id>/agent.json  # 版本化、严格校验、实例隔离的声明配置
  skills/                    # 受控技能来源；本次不启用任意代码技能
  agent-state.sqlite         # 脱敏运行账本，不保存提示词、音频、弹幕、Key
  chats.sqlite               # 现有已完成会话；不为换内核强制清空
  workspace/                 # 现有角色身份/记忆/目标及桌宠配置
  live/                      # 平台配置预留，默认不连接
```

新账本记录产品在线聊天（含材料）；未从聊天开放的旧任务兼容路由沿用原任务账本。新账本与现有 chats.sqlite 职责分开，避免本轮改写成熟历史 schema。目录 0700、文件 0600；拒绝符号链接/非普通文件，事务与唯一键去重、并发安全；重启将未终结运行标记 interrupted，不自动重放。只持久化元数据与状态，不回放旧运行作为上下文。配置与账本失败时关闭执行，不以静默内存降级掩盖丢失。技能不自动下载、执行或授予工具。

旧代码与私有数据分开退役：删掉当前产品 DSH 依赖、回环/worker 链和只服务旧链的构建/合成工具。不得递归清空 ~/.adpets、删除 Keychain 或模型配置，也不自动清理可能仍运行的旧进程目录；运行时不做兼容导入。专属旧数据只在精确归属且服务停止的情况下才可清理，本次无必要不触碰私有用户数据。

## 语音互动可行性

- 链路：显式麦克风授权 → ASR 最终文本 → 同一 Agent 回合 → 气泡/回复 → TTS。ASR/TTS 不加载在 Agent 的模型回调中，沿用单独进程/会话生命周期。
- 允许只使用最终文本，不假设 Pi 支持原生双向音频或当前四协议层具备流式能力；初版提供完整回复，不把伪造分块称为低延迟流式。将来服务商真正增量输出时扩展同一事件接口。
- 一次显式语音输入可取消本实例低优先级直播轮次，取消贯穿 provider、工具及输出；旧代次回复和音频不得在打断后播放。队列有界，暂停/关闭后不自动录音或补播。
- 不保存录音、识别正文或默认完整语音历史；在线授权和计费披露仍单独处理。首音/尾音、回声、设备切换、资源占用需真实设备验收。

## 直播可行性

- 平台适配器 → 本机长度/频率/去重/超时筛选 → 低优先级直播输入 → 同一 Agent → 有界气泡/TTS 队列。
- 直播输入视为不可信数据，绝不获得个人身份/记忆/目标、聊天历史或材料工具；只含明确选用的公开角色规则。直播不得自动保存记忆，不对直播间发评论，不读取麦克风。
- 同实例手工输入优先；忙碌直播不堆无限队列，可明确丢弃。平台断开只中止直播所属轮次，不能取消另一个手工会话。
- B站和抖音分别核验平台接口/条款及登录凭证要求；本次不接账号、不抓未授权页面、不承诺两个平台均可接入。合成调度验证不代替真实平台验收。

直播接线前仍需把平台级去重、频控和持续会话预算放在接入层，并给手工输入保留独立预算。初版调度器用有界、不淘汰的事件表验证拒绝与取消语义。[后续阶段](../plans/2026-11-24-voice-draft-live-admission.md)为直播单独加入 TTL 和滚动启动上限；实际平台仍需稳定事件 ID、平台级去重及授权和长期验收。播报队列需要自己的发布代次，不把 Agent 回合内的输出门禁直接延用到回合结束后的设备播放。

## 复核与验收门槛

1. 普通文字与材料任务实际导入并执行锁定 Pi 包，所有模型请求仍仅经原 ModelManagement。
2. 空响应、refused/length、未知工具、坏参数、provider 抛错、超时和中途取消不能伪装成功，错误正文不泄露；有界且无额外探测费用。
3. 持久去重、实例隔离、重启 interrupted、权限/符号链接拒绝有回归测试。
4. 语音打断直播、显式输入不被直播抢占、旧代次输出丢弃、调度器不读取私人上下文有合成测试。生产直播适配器仍须独立验证不会载入私人资料或工具。
5. 固定 IPC、现有资料授权、模型配置和聊天项目语义不回退；构建不再打包 DSH/worker。
6. 跑针对性测试、typecheck、完整 check:cross-platform；记录真实命令/失败/跳过。无需启动真实 Electron、结束用户进程或发起付费请求。
