# 桌宠 Agent 与模型核心能力同步

**状态：2026-11-23 实施只读核心；真实桌面与供应商尚待验收。** 本稿落实 2026-11-23 用户确认的方向：模型管理弹窗按 Ape Agent Harness 的布局和核心模型能力对齐；每只桌宠是独立 Agent，并可由用户主动发起受限任务。本文不授权真实模型请求、桌面预览、系统权限申请或未经逐项确认的工作区写入。

## 本轮交付与后续边界

- 弹窗保持 480 px 目标宽度、520 px 高度上限与固定头尾，窄窗单列。全局默认及清空确认仍在编辑详情，发现移入「已保存连接」，原高级分组删除；不把保存和联网合并。原生 Edit 与右键 Paste 不暴露剪贴板接口。
- 聊天附件按白名单和保存路由能力校验。图片/PDF 只走 Responses；原始附件、任务文件与凭证不写入历史，也不实现普通聊天工具执行。文件签名检查只识别类型，不等同于恶意文件扫描。
- 本轮独立 Agent 只运行用户显式发起的只读文本任务：固定列出／分段读／搜索，本机名称和角色资料不出站，文件以编号标识；只保存任务元数据和供审阅的最终文本，不保存原始指令。原设计中的私有工作树、结构化差异及逐项应用审批未开放；没有写回、后台自动启动或通用工具。重启不重试。应用工具边界不等于 OS 沙箱。

## 目标

1. 模型弹窗保留当前多服务商连接、模型发现、安全凭证、连接默认与全局默认语义；删除「连接选项与高级设置」折叠入口，按 Ape 弹窗的尺寸、固定头尾、滚动正文、双列字段和模型参数折叠重排。
2. Ape 的推理等级、图片输入和 PDF 输入配置必须贯通模型编辑、严格配置校验、不可变路由和实际请求。界面不可把未实现或未确认的能力显示为可用。
3. 每个桌宠实例以其现有 `petID` 作为 Agent 身份边界。聊天仍是日常对话入口；用户可以显式创建和运行任务，查看任务进度、取消、审阅产物并批准有副作用的操作。
4. 保留凭证、实例资料、历史聊天和运行时的现有安全不变量；Ape 是参考实现，不作为运行时依赖、数据源或信任根。

## 当前基线

- 目标仓库已有 schema v2 多连接模型配置、四种协议适配器、Keychain 凭证引用、逐连接修订和路由指纹、保存后显式连接测试，以及按实例隔离的身份、记忆、目标和聊天。
- `ModelEntry` 还没有推理等级和输入模态；协议适配器的公开 `ModelMessage` 只有文本。聊天合同限制为 64 KiB，SQLite 历史只保存文本回合。
- 现有 DSH Runtime 是 macOS 开发工作区中的隔离文字回合执行器。它只接受当前用户文本和一次绑定的模型回调，不派发 Agent 工具，不拥有任务工作区。
- Ape 的图片/PDF输入字段只对 OpenAI Responses 开放；Ape 的模型配置、任务附件和任务运行不是一项单独的 UI 移植。
- 参考仓库工作树含有未提交的任务权限和执行改动。本设计仅采纳本地已存在的稳定架构原则；不复制、执行或依赖未提交代码及其测试结果。

## 模型管理界面

### 布局

- 弹窗宽度目标为 480 CSS px，最大高度 520 CSS px，并受视口高度约束；标题栏与底栏固定，中间表单独立滚动。
- 添加时保留「第三方模型提供商／自定义模型 API」分段选项。服务商和接口协议并排；接口地址与 API Key 使用整行；模型参数使用可折叠区，每个模型内使用双列字段。
- 编辑态沿用同一尺寸与骨架。窄视口保持内容可滚动，双列在可用宽度不足时改为单列，不裁切字段、状态或按钮。
- 间距、控件高度、字体层级、边框、焦点态、页头与页脚比例按 Ape 当前实现对齐；产品自身颜色、图标、无障碍命名和键盘行为沿用桌边小崽设计系统。像素验收以提供的截图和参考实现为准。

### 字段与既有语义

- 主表单展示服务商、接口协议、接口地址和选填的 API Key；按用户后续确认，不再显示「鉴权方式」。无已绑定 Key 则不发鉴权头，接口在显式测试时决定是否接受。HTTP 仍只允许当前服务端规则认可的 loopback 地址。
- API Key 使用原生密码输入框；用户可直接输入、粘贴或使用系统编辑菜单。输入值只在本次保存命令中短暂传递；列表、读取、错误、日志及持久配置均不得返回 Key 正文。页面隐藏或离开时清空输入并撤销未完成的测试同意。不新增通用剪贴板接口。
- 原折叠区整体移除，但不能借 UI 改版删除仍被配置或请求使用的能力：不展示工具能力、输入类型和输出 Token 字段，不因隐藏而清除已有配置；多模型连接的连接默认模型在模型列表外显式选择；全局默认在连接列表操作中设置/清除，并保留清空确认及“不会自动回退”的语义。
- 保存默认不联网。保存后测试仍须当前草稿明确勾选；地址、模型、协议或 Key 变化后使测试同意失效。发现模型继续是独立、显式的连接操作。

## 模型能力和请求

### 配置与路由

- 在 `ModelEntry` 中加入可选 `reasoningEffort` 与 `inputModalities`。schema v2 及已有配置文件保持兼容；旧文件缺省字段按“自动/未声明”解释，不做破坏性迁移或伪造能力。
- 接入时严格拒绝未知字段、重复模态、无效等级、跨协议能力和不匹配的模型选择。输入模态首批只支持 OpenAI Responses 的 `image` 与 `pdf`；PDF 依赖图片能力。其他协议保持文本输入，直到其编解码、体积限制与真实合成测试单独通过。
- 推理等级由本项目的受审能力规则按协议、端点和模型 ID 决定；没有匹配规则时显示自动/不发送推理字段。保存值不是供应商支持承诺。实际请求只发送该协议已验证的参数形式。
- 能力字段进入模型配置校验、编辑草稿、路由快照和路由指纹。修改模型等级或输入能力后，旧聊天选择/执行授权不能被误认为同一路由；请求前服务端重新校验已保存配置。

### 附件生命周期

- 仅用户通过聊天输入区显式选择本轮附件。沿用 Ape 合同：每次最多 5 个文件、每个最多 5 MiB、总计最多 15 MiB；纯文本附件最多 20,000 字符，正文与纯文本附件合计最多 60,000 字符。合同同时限制扩展名/MIME、字节数和 UTF-8 解码。
- 图片仅支持 PNG、JPEG、WebP；文档支持 PDF 和已有合同允许的纯文本/源码扩展名。文件名做有界净化；不接收路径、URL、HTML、归档文件或任意 MIME 数据。图像/PDF 以协议规定的数据形式进入 Responses 请求；纯文本在服务端解码后作为当前用户消息内容。服务端重新验证字节、签名/尺寸与模型能力后才可出站。
- 固定聊天请求体预算按 15 MiB 原始附件的编码开销加字段预算设上限，不沿用当前 64 KiB 文本请求上限；模型客户端对编码后请求体单独设硬上限，超限在网络出站前拒绝。传输仅接受固定聊天 DTO 和用户选定的内容，不新增路径读取或通用文件 IPC。
- 附件字节只存在于当前显式回合的内存/受限传输中；不写 SQLite、会话草稿、崩溃日志、分析事件或 Harness 会话目录，不作为后续回合的隐式上下文。用户后续要引用文件须再次附加。含附件的回合不作为可重放模型历史；未知结果不自动重发。
- 上传/编码失败、附件超限、模型能力不符或路由修订变化时，停止在首次 Provider 请求前并返回有界错误。Provider 已接受请求但结果未知时不得自动换路由、重放或宣称取消成功。

## 桌宠 Agent 与任务

### 身份和会话

- Agent 的身份、角色资料和可用授权绑定当前已登记的 `petID`。每个运行请求还绑定会话/任务 ID、模型路由快照和配置修订；跨实例请求无效。
- 日常对话继续使用现有聊天路由和本机资料边界。Agent 任务使用单独的任务合同、生命周期和执行入口，不把通用工具、文件访问或任务状态塞进普通 `OnlineChatInput`。
- 任务由用户明确创建、选择范围并启动。任务进度、阶段、工具请求和结果有明确终态；用户取消会中止本轮模型调用和自有 Runtime。停止未确认或 Provider 结果未知时保留未知态，不自动重试。
- 任务记录按实例保存在应用私有本机数据中，包含用户明确提交的任务正文、必要的有界事件/结果、状态和待审变更；不保存原始附件字节、Key 或未授权文件。应用退出时先请求 Runtime 收敛；结果未知的任务恢复为需用户核对，不在启动时自动继续。用户可显式继续已确认安全的任务，但每次继续创建新的 attempt 并再次复核当前路由与权限。
- 同一桌宠实例最多一个活动任务，全局同时活动任务不超过三个。新任务/继续前检查任务归属、当前实例注册、模型连接修订和权限版本；不符合时要求用户重读并明确确认，不借用其他实例或旧路由。

### 范围与权限

- 任务的文件范围必须由用户在系统选择器显式指定；默认没有工作目录、项目、账户 Home 或任意文件授权。renderer 不接收系统文件路径，只拿到有界文件引用/元数据。
- 基础能力分为只读和变更提案两类。只读仅可读取当前任务被选中的内容；变更提案须在任务开始前由用户对该任务明确授权，Agent 只能在任务私有暂存区生成变更，不能直接覆盖工作区。应用每个变更前都展示目标相对路径和差异并取得确认；拒绝或撤销后不应用该副作用。
- 第一阶段不得开放任意 shell、任意子进程、MCP 服务、网络工具、子 Agent 或后台定时运行。它们不因接入 Agent 名称、Harness SDK 或模型返回工具调用而自动启用；需要各自的权限合同、进程级隔离和独立审查后才能加入后续阶段。
- Agent 不得直接写入身份、记忆、角色知识、目标、模型连接、Keychain 或应用配置。资料改动只能生成类型化提案，沿用当前应用的人审、修订冲突、撤销和结果核对流程。
- 任务产物先进入任务私有暂存区。只有用户审阅并确认后才应用到被授权工作区；任务失败、取消或结果未知时保留可核对状态，不在后台继续执行。

### 执行器隔离

- 不扩展现有文字 DSH Runtime 的权限，也不把 DSH 的目录、工具默认值或持久化策略照搬进产品。
- 新任务 Runtime 必须由可信主进程/服务启动、每任务独占并有界回收；renderer 只调用固定操作。模型凭证只由服务的已保存模型路由读取，Agent Runtime 不接收 Key 或可重建凭证的引用。
- 工具请求必须是本项目定义的类型化 DTO，经服务端授权策略逐项校验；未声明工具、越权路径、失配实例/任务/修订、超时和过量数据均拒绝。工具调用的结果、差异与终止状态经过验证后才交给 UI。
- 在支持的操作系统上必须证明进程级文件/网络边界；若某平台无法提供等价隔离，该平台仅开放已验证的只读能力，不以应用层路径检查宣称为 OS sandbox。
- 任务输入、工具参数、输出和日志不得包含 API Key；禁止记录原始附件字节、未授权文件正文或其他实例上下文。清理失败时阻止复用该 Runtime，并向用户显示可恢复的有限状态。

## 错误与兼容

- 模型字段校验错误在表单指出字段，不回显密钥。配置保存冲突要求重读；未知持久化结果只允许核对，不自动再次提交。
- 任务错误使用固定错误码区分拒绝、限额、Provider 失败、取消、清理未确认和结果未知；不把异常正文或上游响应直传 renderer。
- 现有配置、默认模型、聊天历史、个人资料与授权保持原状。不得自动导入 Ape 配置或任务、扫描其数据库、复用其存储目录或读取真实凭证。

## 验收

1. 模型弹窗：在桌面和窄视口复刻 Ape 的布局层级；页头/页脚固定、表单滚动、双列响应、无“连接选项与高级设置”入口，所有保留能力均可访问。
2. API Key：自动化验证键盘输入、粘贴文本、保存 DTO 一次性携带、离开/隐藏时清空，以及读取/日志中不出现密钥。真实 OS 剪贴板与 Keychain 权限另列人工验收，不以合成事件冒充。
3. 模型：旧 schema v2 配置继续读取；新增推理等级正确进入对应 Responses 请求；图像/PDF字段仅对合格模型启用；篡改请求、超限或路由变更均在 Provider 出站前拒绝。检查请求正文不得包含非必要本机路径或凭证。
4. 附件：PNG/JPEG/WebP/PDF 与允许的纯文本扩展名，覆盖每文件/总量/字符数边界、UTF-8、伪造 MIME、无效 PDF/图像数据、取消选择、跨实例、取消和未知结果；SQLite 与日志不含附件字节。
5. Agent：至少验证实例隔离、每实例单活动任务/全局并发上限、用户发起、任务状态与重启恢复、只读默认、暂存变更确认与撤销、路径逃逸/符号链接拒绝、取消/清理、结果未知不重放、Key 不可见，以及每个支持平台的隔离证明或能力降级。
6. 按仓库指南运行定向测试、`pnpm run typecheck`、`pnpm run test:cross-platform` 和 `pnpm run check:cross-platform` 中与本任务相关的门槛；另做桌面/窄窗截图验收。真实服务、Keychain、剪贴板、系统沙箱和在线供应商测试必须单独标记是否执行。

## 分阶段实施

1. **模型 UI 与配置**：迁移弹窗布局、修复 Key 粘贴回归、补齐推理和模态能力合同/保存/快照/Responses 编码；更新模型设置与相关测试。
2. **多模态聊天**：接固定、限额的当前回合附件传输和 Responses 编码；落实不持久化、不隐式重放、退出与取消清理。
3. **Agent 任务基础**：引入按 `petID` 隔离的任务记录、用户发起/取消/状态、只读文件范围与差异审阅；确认每个平台的隔离能力后再开放写入。
4. **后续能力门**：仅在每项独立设计和安全验收后扩展 Skills、MCP、子 Agent、任意命令或后台运行。此门不阻止前述核心 Agent 任务交付，也不代表这些能力已获准默认开启。

## 明确不做

- 不迁移 Ape 的企业/项目外壳，不修改参考仓库，不复制其未提交实现或依赖。
- 不把普通聊天 Runtime 变成通用工具执行器；不开放自动资料写入、桌面自动化、任意 shell 或后台自主运行。
- 不自动导入旧会话、角色资料、模型配置、密钥或 Ape 的任务/权限数据。
- 不以自动化测试替代用户授权的真实桌面、系统隔离、剪贴板、Keychain 或付费供应商验收。
