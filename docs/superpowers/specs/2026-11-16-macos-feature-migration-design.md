# macOS 功能迁移与新工作区设计

日期：2026-11-16。状态：用户已确认 macOS 功能优先、Windows/Linux 播放器阻塞暂缓，以及“页面按新设计改进，不照搬旧页面”；用户回复“可以的”，已确认按本文首批方案进入实现；后续进度与未覆盖边界见[实施计划](../plans/2026-11-16-macos-pet-workspace.md)。

## 1. 目标与取舍

- 按[功能迁移清单](../../macOS功能迁移清单.md)恢复现有 macOS 的行为、资料语义和安全边界，长期主实现为 TS/Python，不留下依赖 Swift 业务服务才能工作的替代版。
- 不保留旧页面的布局缺点；保留用户熟悉的功能名、角色身份、快捷键及关键操作语义。
- 在既有 Electron/React/Fastify/Python 边界内逐批迁移。不用“先搭齐九个空页面”冒充完成，也不一边重做物理/解码一边迁业务。
- Windows/Linux 实际播放继续 `blocked`，原因不删，暂不移植。旧 macOS 未完成的真实验收、完整直播接入等维持原状态，不借迁移扩建范围。

## 2. 备选与推荐

1. **直接复刻旧 UI、随后重画**：最容易对照，但会把已有表单堆叠与布局问题搬进新栈，造成二次返工；不采用。
2. **先重画所有页面、之后接业务**：视觉统一快，但空壳多、错误/权限/取消状态容易漏；不采用。
3. **统一设计基础，按业务纵切实现（推荐）**：先配置与实例，再角色/记忆、模型/聊天、任务/语音、宿主交接。每批包含页面、领域、持久化/运行时边界和验证。视觉体系统一、功能逐项对照，不把界面完成度和功能完成度混成一个指标。

## 3. 界面方向：安静、温暖、角色优先

- 使用低饱和暖灰画布、清晰的内容面板与克制的青绿色强调色；少量角色色用于头像/选中态，不把所有区块都做成大彩色卡片。深色主题保持同一层级，提供跟随系统/浅色/深色三种选择。
- 不逐像素复刻旧 SwiftUI，也不把运行概览的展示型大标题延伸到每个业务页；业务页用紧凑标题、状态、主操作和真实内容。
- 桌面布局采用固定侧栏 + 弹性主区；详情按需要用次栏或独立编辑区，不让所有设置无限纵向堆叠。窄窗口将次栏收起，必要时允许页面滚动；具体尺寸与断点在实现中用离线渲染验证，不凭说明宣称视觉通过。
- 提取语义 tokens（颜色/间距/字体/圆角/层级/焦点/运动）和窄 API 的通用组件。表单、错误、空态、开关、菜单、确认框只实现一套；不复制近似页面。

### 导航与页面分工

| 分组 / 页面 | 新页面重点 | 不改变的契约 |
| --- | --- | --- |
| 陪伴 / 桌宠 | 角色/实例网格、清晰状态、添加入口、所选实例的偏好与控制；最常用操作不藏进高级表单 | 启停/显隐/暂停语义、实例上限、克隆停止态、删除确认与素材引用保护 |
| 陪伴 / 聊天 | 对话为主，底部稳定输入区；角色与模型选择清晰但不抢占对话面积；取消和生成中状态可见 | 临时有界历史、不保存完整聊天；本机优先、在线分享边界；中文组合输入、换行/发送与复制/撤销 |
| 角色 / 身份 | 简洁资料摘要 + 分组编辑；身份/表达风格/边界分开，保存反馈邻近编辑内容 | 名称/字段上限、默认关闭分享、修订恢复、核心身份不被适应层改写 |
| 角色 / 记忆 | 类型导航、搜索/筛选、来源/引用/版本、待审核独立入口，选中条目再编辑 | 事实/知识区分、冲突隔离、人工确认、在线授权与撤回 |
| 角色 / 能力与目标 | 当前可用/未授权/未实现分层展示，目标和进度可解释 | 运行时能力事实，不展示假可用状态；保留现有目标推进与权限边界 |
| 设置 / 模型管理 | 服务商/模型列表与配置详情分层；连接状态、刷新和错误可定位 | 密钥不读回页面；取消/时限/验收预算；现有功能迁移不等于四协议设计已实施 |
| 设置 / 语音互动 | 聊天输入/语音输出/互动气泡三个清晰区块，展示参考音频、转写与授权缺项 | 录音显式授权，朗读开关独立，关闭/取消后的资源清理 |
| 设置 / 直播管理 | 聚焦已有来源与房间设置，明确完整平台接入未完成 | 不用假“已连接”填充尚未实现的能力 |
| 设置 / 高级 | 数据位置、导入与回退说明、诊断、权限、开发状态；危险操作独立 | 不自动迁移/接管进程/申请系统权限；拒绝任意路径与命令执行 |

页面分组不代表删掉原有九类入口；实际某批未迁移时，入口明确说明未接入或暂不呈现操作，不能放置假保存、假测试连接按钮。运行概览收敛为高级里的诊断视图，而不是永久占据产品首页。

### 交互质量底线

- 标准编辑快捷键、键盘导航、可见焦点、语义 label/状态提示、减少动态效果；不能只靠颜色表达启用/失败。
- “未保存”“已保存待应用”“已应用”“运行中”分开，异步返回需匹配操作代际；失败不覆盖用户草稿，不让旧回复回写新页面/新角色。
- 删除确认指明实例且说明不删素材/历史目录；不在通用弹窗里写含糊“确定吗”。保存成功就地反馈，错误给出可恢复入口。
- UI 验证分为组件/客户端逻辑测试、离线渲染检查、真实 Electron/Qt 桌面验收；静态截图不能证明业务接通，组件测试不能证明最终美观。

## 4. 模块与数据流

保持 `workspace-ui → 受限 preload/main → app-service → 领域服务/存储/受控 Python`。React 管交互与草稿；领域约束、存储、在线请求和副作用不放组件。Electron 管平台窗口、受信文件选择、安全存储和自有服务生命周期；Python 保留动画物理/解码和现有 macOS 推理，不承担第二份权威实例清单。

当前桥只有四个无参方法。后续新增业务方法必须逐项定义类型和运行时 schema，校验两端输入，限制字符串/集合/消息体、未知字段和可选动作；不能为了表单方便暴露 `invoke(channel,args)`、任意路径、通用 HTTP 或 shell。现有鉴权、Origin/Host 拒绝、无远程导航与 CSP 继续生效。

存储默认隔离。第一批只使用合成旧资料夹具和新开发根；未来真实导入另获明确同意，先备份后导入独立新根；新旧宿主不能共享写入。详细来源和回退边界见迁移清单第 4 节。凭证、PID/socket、任务租约和未完成请求不是可直接复制的配置。

## 5. 首批实现边界（M1a，已确认）

### 做什么

1. 对照 `PetCore/PetInstances.swift` 与 Python 现有实例格式建立 TS 实例模型与白名单偏好，保持稳定 ID/包引用、登记上限、克隆默认停止与删除条件。
2. 实现隔离开发根的版本化存储与读取/新增/克隆/删除/偏好保存领域操作；读写失败保留原文件，格式未知/损坏/符号链接拒绝。明确实际运行事实来自受控运行时，不从旧清单 `lastState` 推断“运行中”。
3. 在现有安全桥中逐项增加有界业务方法与 Fastify 路由，用假运行时与临时目录测试；登记只能引用服务端认可的包 ID/版本，M1a 的包集合来自合成夹具/显式开发配置，素材选择与导入留给 M1b。不允许页面提交目录、脚本或可执行路径。
4. 实现新工作区布局基础、桌宠实例列表与详情编辑、空态/错误/确认/反馈；其他模块保持未迁移状态。素材导入、真实多宠和运行偏好应用依赖 M1b，不显示伪可用控件。

### 不做什么

- 不解除当前播放器隔离，不接入真实资料、旧 registry、Keychain、在线账号或真实音频；不将每会话随机 profile 直接改成用户资料根。
- 不在 M1a 内一次做完多宠进程管理、素材包导入、任务/聊天/语音或新的启动视频；不把“实例可登记”叫作“多宠已运行”。
- 不修改冻结 helper 输入，不构建/安装 `.app`，不自动开真实桌面或关旧宠。

### 通过条件

- TDD 覆盖旧格式合成夹具与往返、32 项上限/重复 ID/包引用、克隆停止态、运行态删除拒绝、损坏/未知版本/非普通文件保护、失败保留原文件、并发写入/过时操作；白名单偏好不能包含命令/路径。
- HTTP/桥接拒绝未知方法/字段/越界参数，仍保持认证/来源/Host 拒绝矩阵；无凭证/原始路径泄露。
- UI 测试覆盖选中态、空/错误/保存/确认、草稿保留与操作代际，未接入能力不能显示已生效。
- `pnpm run check:cross-platform` 及受影响旧测试真实执行后记证据；跳过不算通过。真实预览与视觉验收另由用户选择安全时机。

## 6. 整体完成门槛

以迁移清单逐项完成而非时间点判定：新栈有行为等价实现、相关回归、数据/权限/失败处理与真实 macOS 验收；旧版本可回退，新资料增量的回退限制透明。达到门槛后才讨论退役 Swift 及恢复 Windows/Linux 播放器移植；本设计本身不解除任何现有阻塞。

### M1b 开发纵切补充（2026-11-16）

- 只为显式配置的开发角色接通逐实例 `start` / `stop`；每实例各自持有新 `PlayerRuntime` 和随机会话 profile，最多同时三个。命令不写配置 revision，不自动恢复，不接管现存桌宠。
- 阶段为易失运行状态；启动中允许显式停止/取消。失败或进程退出未确认时保守占槽且禁止删除；正常停止确认后才能删除并释放运行时。
- 显示大小、位置、活动、全屏隐藏仍仅保存待应用；素材导入、暂停、窗口显隐/尺寸与真实桌面验收不属于此纵切。Windows/Linux 播放器仍 blocked。


### M1b 行为偏好已确认纵切补充（2026-11-17）

本轮用户批准仅迁移保存的 scheduledActivity / movement，不扩建架构或任务功能。每次显式启动采用最新保存值，运行中新增 ID/revision 固定应用入口；首帧/应用确认后才记录易失行为状态，失败不伪报、不写配置 revision、不丢草稿。适配层仅变化时调用旧行为 setter，保留任务/减少动态效果门禁及真实松手甩动例外；不更改冻结 helper、不导入旧任务状态。私有 player v3 拒绝旧协议。暂停/恢复需后续连同启动/观察模式和任务租约单独审查迁移，本批不能视为 P04 或 T01 完成。

### P04 会话级暂停门禁补充（2026-11-17，部分开发接入）

用户批准的有界下一段仅在新服务中增加易失 session linkage 状态，不恢复任务跟随或旧客户端观察。暂停请求同步封闭服务端启动门禁，然后停止服务拥有的 PetLifecycle 实例及独立诊断 PlayerRuntime；覆盖 renderer 两个启动入口、实例显隐与运行偏好应用。停止未确认时返回失败并保持 `stop-unconfirmed`，不可解除，仍允许显式停止重试、配置保存和关闭清理。成功解除仅开放门禁，不自动启动、不恢复暂停前实例集合。状态不进磁盘、不增加 revision；固定输入仅有 `expectedRevision`。完整旧版 P04（任务租约、启动/观察模式恢复、客户端状态与不补播动画）仍待迁移，不能把这一部分描述为完整行为等价或真实桌面验收。
