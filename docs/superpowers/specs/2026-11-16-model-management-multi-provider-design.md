# 模型管理：多厂商、多模型与多协议设计

日期：2026-11-16。状态：**设计待审，尚未实现**。本轮只整理方案，不修改业务源码、运行配置或钥匙串，不启动、重建、安装应用，也不提交或推送。

用户要求：参考所给截图；支持多个厂商、每个厂商多个模型；厂商与模型可折叠；配置在页面内完成，不出现应用内配置弹窗；输入控件与桌宠内容区按钮等高。用户进一步要求参考 `deepseek-ai/deepseek-harness`，先理清不同厂商、不同协议的接入方式。

## 1. 核心决定

1. **厂商是预设，连接是实际路由，协议决定请求格式，模型是连接内的资源。** 不根据显示名称、模型名前缀或域名猜协议。
2. 一张厂商卡片代表一条独立连接。同一厂商可有多个连接，分别使用不同账号、地址或协议；每条连接使用独立凭证引用。
3. 第一轮目标覆盖四种 API-key 协议：OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Gemini 原生 API。每种都必须完成请求、回复、错误、工具往返及模型发现的协议级验证，不能只列一个选项。
4. DeepSeek 兼容 Chat Completions 的连接走对应适配器；Harness 的 DeepSeek 专用 Messages 路径不被当作通用 Anthropic 实现的同义词，单独列入后续适配。未实现的协议不出现在可保存的选项中。
5. 保留 Swift 宿主直连所选服务的架构；不引入 Node 常驻进程、整套 Harness 或新的转发服务。借鉴边界与测试方法，不复制完整智能体系统。
6. 所有在线用途使用统一路由；本地规则优先、授权上下文过滤、字符与历史上限、取消与重试约束保持有效。
7. 页面展开、折叠和草稿编辑不联网、不读密钥、不影响运行中的模型配置；保存只更新本地配置与必要的钥匙串项目。

## 2. 现状与参考边界

### 2.1 本仓库现状

- `ModelProvider.swift` 的 `ModelProviderSettings` 只保存一个服务，字段为 `provider`、`baseURL`、`model`、`availableModels`；`ModelAPIKeyStore` 使用单一钥匙串项目。
- `ModelProviderClient` 当前按 Chat Completions 编码请求及解析 `choices/message`，不能直接承载其他原生协议。
- `ModelDiscoveryClient` 当前按 Bearer 鉴权请求兼容 `/models` 列表；`ModelCatalogRefresher` 已有变更检测和迟到结果保护，应延续到逐连接粒度。
- `CharacterChatModelCatalog` 与选择器当前为单服务契约；仅增加配置数组而不改变选择器、凭证解析和请求入口，不能交付多厂商功能。
- 聊天、语音、目标建议、记忆审核、自主气泡、合成验收入口存在不同调用点，必须逐个接到统一在线边界。
- 桌宠卡片按钮与 `ManagementControlStyle.compactHeight` 当前为 26pt；共享常规按钮为 34pt。本设计使用前者，不让输入框出现仅外层变高、可见边框仍矮的情况。

## 3. 数据与标识

### 3.1 最小数据结构

新格式文件为现有状态目录内的 `model-providers.json`，初始 `schemaVersion = 2`；旧单服务 `model-provider.json` 只作转换输入与保留备份，不双写。这里升级的是配置格式，不新增数据根目录。

| 对象 | 拟保存字段 | 约束 |
| --- | --- | --- |
| 配置根 | `schemaVersion`、`revision`、`connections`、`defaultConnectionID` | 新格式显式版本化；未知版本拒绝覆盖 |
| 连接 | 稳定 `id`、`revision`、`displayName`、`preset`、`apiProtocol`、`baseURL`、`authMode`、`credentialRef`、`models`、`defaultModelEntryID` | 同一厂商可重复；地址和协议必须显式有效 |
| 模型条目 | 稳定 `entryID`、请求用 `modelID`、显示名、可选容量、能力声明、受限兼容选项 | 单连接内 `modelID` 唯一；不同连接可以同名 |
| 聊天临时选择 | `connectionID`、`modelEntryID`、所确认的路由指纹 | 只作用于当前聊天，不回写全局默认 |
| 凭证 | 钥匙串中的独立项目 | 配置只存不透明引用，不存明文、密钥前缀或密钥哈希 |

- 容量的绝对数值上限不是按厂商猜测：首轮统一接受 1…2,147,483,647，编码和预算计算做溢出检查；这只是数据有效性上限，不表示模型具有该能力。
- 模型 API ID 可编辑，`entryID` 不变，因此显示名或 API ID 修改不会留下悬空默认引用。实际 API ID 变化仍使旧聊天路由确认失效，不能偷偷把旧选择换成另一个模型。
- 连接显示名不参与路由和钥匙串定位。单纯改名不使选择失效；地址、协议、鉴权身份或 API ID 改变需要重新确认在线选择。
- 上限建议：32 条连接；每条最多 33 个模型条目，包含默认模型，以无损容纳旧格式的“默认模型 + 最多 32 个附加模型”。新格式不再维护另一份重复的附加模型数组。
- 新配置文件大小上限 1MiB；模型 API ID 延续 256 UTF-8 字节上限，连接/模型显示名上限各 128 UTF-8 字节，Base URL 延续 2048 UTF-8 字节上限；容量只接受合理范围内的正整数，不接受无限值或负数。
- 空白草稿允许暂存于页面内，但连接保存时至少有一个有效模型，且本连接默认引用必须存在。配置可以完全为空，此时全局默认为空，在线功能明确提示未配置。

### 3.2 默认值只有一个解释

- 配置根只保存全局默认连接；每条连接保存自己的默认模型。全局有效模型由这两层解析得到，避免两套默认模型互相冲突。
- 卡片上的“设为默认”只作用于已保存版本；若需同时采用未保存草稿，必须通过明确的保存操作一并提交，不以切换默认隐式保存其他字段。
- 在非全局连接里修改其默认模型，不影响全局默认；在全局连接里修改默认模型，会改变后续使用全局默认的请求。
- “设为全局默认模型”在一次本地提交内同时设置默认连接和该连接的默认模型，不留下半完成状态。
- 删除默认模型必须在同一内联操作中指定替代模型。删除全局默认连接时必须明确选择替代连接，或确认清空默认并停用依赖默认值的在线分支；不静默选择第一项。
- 已选择的模型或连接被删除、改址或改协议时，后续发送提示重新选择，不回退到其他厂商。

## 4. 协议适配与统一调用边界

### 4.1 拟议模块职责

下列名称为设计职责，不代表文件已经存在。实现时沿用现有模块，只按职责拆分，不扩大 `Coordinator` 或 `ModelManagerWindow` 的业务责任。

- **配置仓库**：版本解码、校验、原子提交、逐连接变更检查、迁移；不发网络请求。
- **凭证仓库**：按连接引用读写钥匙串；可注入合成实现供测试使用，不把已保存的密钥正文交给 UI 模型。用户新输入的 Key 仅在安全输入草稿中短暂保留，保存或取消后清空。
- **路由解析器**：选择全局或聊天临时模型，验证引用与路由指纹，生成固定请求快照。
- **统一模型客户端**：用途预算、取消、超时、工具轮次、响应大小上限及错误映射；不拼厂商 JSON。
- **协议适配器**：地址规则、鉴权头、消息/工具编码、回复/终止状态/用量解析、模型发现；不保存默认值，不直接执行业务工具。
- **模型管理页面状态**：已保存快照、逐连接草稿、展开状态、校验和操作结果；不直接读写磁盘、钥匙串或 HTTP。

统一请求包含用途、普通消息、经授权的上下文、工具白名单及预算。统一回复区分正文、工具调用、正常结束、达到上限、拒绝和协议失败。目标建议与记忆审核在收到协议归一化的正文后，再执行现有领域 JSON 解析与安全校验。

### 4.2 首轮协议矩阵

| 协议 | 鉴权与版本职责 | 请求与回复职责 | 兼容边界 |
| --- | --- | --- | --- |
| Chat Completions | Bearer；本机显式无鉴权连接例外 | 消息角色、函数工具、`choices/message`、结束原因 | 输出预算字段等受限兼容选项由适配器处理，不全局混发 |
| Responses | Bearer | 输入/输出条目、函数调用与结果、输出状态、输出预算 | 不是换一个路径后继续解析 `choices`；不借用其他服务的 response ID |
| Anthropic Messages | API Key 头及必需版本头 | system 与消息分离、content blocks、tool use/result、停止原因 | 不发送 OpenAI 专用字段；不自动等同 DeepSeek Messages |
| Gemini 原生 | Google API Key 头及显式版本路径 | contents/parts、system instruction、函数声明/结果、候选结束状态 | 不使用 OpenAI 的角色与工具结果格式；保留同请求工具往返需要的签名 |

首轮以完整单次回复接口接入现有 UI，不额外承诺逐 token 流式展示。只接受流式返回的特殊端点需单独适配，不因“同一协议”就标记为已支持。工具循环内部若必须携带原生元数据，由适配器在内存中保留，不暴露为聊天正文。

OAuth 登录、Azure 部署与 `api-version`、Bedrock SigV4、Vertex 身份、DeepSeek 专用 Messages、图片/文件上传、任意自定义鉴权头、任意原始 JSON 参数和完整推理控制台均不在首轮交付范围。不能仅添加 UI 枚举就宣称支持。

### 4.3 地址、兼容项与模型能力

- `baseURL` 表示协议定义的根/前缀，协议适配器负责追加资源路径，保留中转服务的部署前缀，不重复追加 `/v1`，也不跨域解析到别处。输入标签和示例随协议变化。
- 新配置拒绝把生成接口完整路径冒充根地址；旧配置迁移仅规范化已知 Chat Completions 尾缀。禁止猜测、连续请求多个候选路径来探测协议。
- 远端仅允许 HTTPS，HTTP 仅允许现有 loopback 范围；拒绝 URL 内嵌用户名、密码、查询参数和片段。API Key 不放入 URL。
- 首轮鉴权为 `apiKey`；可显式选择仅本机 loopback 的 `none` 模式，此时不伪造 Key，也不发送鉴权头。远端自定义鉴权留待单独设计。
- 连接默认兼容选项可被单个模型的受支持选项覆盖；只提供当前适配器真正读取的字段，不提供任意字典。切换协议不得静默保留不兼容字段，保存前要求清理或确认转换。
- 工具能力区分支持、不支持、未知，并保留来自预设、用户声明或发现结果的来源。发现出模型 ID 不等于已验证工具、推理或视觉能力。
- 未知能力按普通文本使用；需要工具的功能明确提示尚未启用/确认，不让模型编造实时结果。旧配置迁移也标注能力未知并提示变化，不保留宽泛的 400/422 自动重发机制。
- 上下文容量和最大输出能力可留空；不凭模型名字填入未经确认的大数值。单次输出上限由现有用途预算与已知模型限制共同约束；未知时保留用途预算，而非无限制输出。字符上限不能冒充精确 token 计算。
- 推理/工具/结构化输出的支持并非四种协议统一保证；首轮只展示已经实现且有测试的配置项。正文为空、只有推理内容、被拒绝或达到长度上限均需明确处理。

## 5. 路由、并发与隐私

### 5.1 按用途解析

| 用途 | 选择来源 | 保留约束 |
| --- | --- | --- |
| 文字聊天 | 当前聊天显式选择，否则全局默认 | 本地身份、记忆及能力规则先执行；需要在线时才读凭证 |
| 语音回复 | 全局默认 | ASR/TTS 仍在本机；只发送已授权的转写和上下文 |
| 目标建议 | 全局默认 | 仅发送用户确认的目标文本，不执行目标 |
| 记忆审核 | 沿用触发该轮审核时已经确认的聊天选择；无显式选择则全局默认 | 不因全局设置变化把待审核内容自动转给新厂商；已有 opt-in、凭证过滤与证据校验不变 |
| 自主气泡 | 全局默认 | 保留 opt-in、频率与事件枚举边界，不附带用户正文 |
| 连接测试 | 当前明确点击的连接草稿 | 有费用提示，仅发送合成最小内容，不带聊天、记忆或语音数据 |
| 合成模型验收 | 验收明确选定并固定的连接 | 复用既有请求账本与合成内容约束，不扩张到真实用户任务 |

现有 `ModelRequestLedger` 是显式授权的合成验收请求预算，不是日常聊天的通用额度系统；改造不得把这两者混为一谈或重置已有账本。

### 5.2 一次请求固定一份快照

1. 在首次异步等待前固定连接/模型标识、配置版本、协议、地址、兼容选项、预算及对应的凭证引用版本。
2. 仅在线分支按该引用读取凭证，随后请求及其有界工具循环始终使用同一快照。不从可变页面状态再次取地址或 Key。
3. 普通保存只影响后续请求。更换 Key 时建立新引用版本，避免旧快照读取到新账号凭证；旧引用在仍需读取它的请求结束后再受控清理。
4. 删除连接属于明确撤销：取消该连接的未完成操作，发送前再次检查撤销状态；忽略迟到回复，不把失败请求转发至默认连接。网络取消不能保证服务端已经停止生成或不计费，界面不作此保证。
5. 单纯页面折叠不取消请求；取消编辑则放弃草稿并取消该草稿的测试/发现。所有异步结果核对操作 ID 与草稿版本，不能污染新草稿。
6. 列表刷新、切换页面、保存配置和模型切换本身不产生生成请求。不因 400、422、超时、401 或额度不足自动切协议、换 Key 或换厂商；重试保留既有明确边界。

### 5.3 对话切换与日志

- 跨连接切换保留已有聊天显示，不清空对话；发送前明确提示后续问题及允许携带的历史会发送到哪个服务。
- 出站聊天历史仅复用现有有界的用户正文与最终回复，经既有授权规则过滤。厂商私有 response ID、签名、原始工具块与推理块不跨连接传递。
- 同一请求中的工具调用 ID 必须与结果配对；业务层只执行现有白名单工具，并保留轮次和调用数量上限。不执行模型任意给出的 URL、命令或工具名。
- 原始历史不可被编码器原地改写。协议元数据仅作必要的短期回放，不写入长期记忆、配置或常规日志。
- 所有带凭证或用户内容的请求拒绝 HTTP 重定向。日志仅保存必要状态、经脱敏的错误码及请求标识，不输出 Key、请求头、完整 URL 私有路径、原始服务错误正文或聊天内容。
- 页面进入、离线预览、折叠和目录读取不触发钥匙串授权。不能承诺操作系统在用户明确保存或在线使用凭证时永不出现自己的安全授权界面；“不弹窗”约束应用内配置流程。

```text
      协议、API Key 状态与替换输入
      > 自定义设置：接入地址与当前协议的有效兼容项
      模型目录：本连接默认模型 / 添加模型 / 获取模型列表
        > 模型卡片：显示名与 API ID（独立展开）
            模型 ID、显示名称、可选容量与已实现的能力项
      页面内状态与错误
      取消 / 测试连接（可能计费） / 保存

  + 添加厂商连接     + 添加自定义连接
```

- 多张连接、多张模型卡片允许同时展开；展开状态属于会话 UI 状态，不作为用户业务配置保存。
- 首次无配置显示空态和添加入口，不把软件默认示例当作“已配置”。新增/编辑/删除确认均在页面内完成，无 sheet、alert 或新配置窗口。
- 删除待确认区域标明对象、默认值影响及是否删除其独立钥匙串项目；明确确认前不执行。取消删除不改变配置。
- 聊天的模型选择器按连接分组，显示同名模型的连接来源；保留其既有独立选择控件，不把本次管理页“无配置弹窗”扩大为移除所有原生下拉菜单。
- 使用共享 26pt 可见控件表面统一单行输入、选择控件和卡片动作按钮；多行说明按内容增高。避免 macOS 原生边框外再套一层看似变高的空框，保留焦点、键盘和辅助功能语义。
- 宽屏模型字段两列，窄屏改为一列；名称、地址和错误可换行；浅色/深色、滚动和最小工作区尺寸都纳入离线预览检查。

### 6.2 草稿、保存与失败

- 新建预设建议：OpenAI 使用 Responses、DeepSeek 兼容连接使用 Chat Completions、Anthropic 使用 Messages、Gemini 使用原生协议，自定义连接初始选择 Chat Completions 并明确显示。预设不是协议限制；旧配置始终保持原协议。具体官方地址与模型示例在实现前核对，不把过时示例当作已发现模型。
- 每条连接独立草稿。编辑其他连接不会覆盖未保存内容；折叠不丢草稿。离开管理页时保留当前会话草稿，关闭工作区会丢弃未保存内容，页面上持续显示该说明，不用弹窗拦截。
- 提供商预设只在新建时填入建议值；编辑已有连接时更换预设不能静默覆盖已修改地址或模型。协议切换的字段转换以页面内差异和确认操作完成。
- 既有连接的 Key 输入留空表示保留原凭证，不代表删除；删除 Key 是独立的内联确认操作。新连接允许先保存不含 Key 的配置并明确标记“缺少 Key”，在线请求在发送前阻止，不伪造配置成功即连接成功。
- 取消恢复该连接的已保存快照、清空新输入的 Key，移除新建但未保存的卡片；不更改其他草稿。
- 保存先做完整校验，再写入新凭证项目并提交连接配置；只有两者成功才发布新的有效配置和收起编辑区。凭证失败不写配置；配置失败保留旧连接与旧凭证，并清理/标记未引用的新凭证，避免假成功。
- 钥匙串与 JSON 没有跨存储原子事务。新凭证使用新引用，配置提交作为生效点；意外退出造成的未引用新项目不影响旧配置，后续只可清理本应用明确拥有且无引用/无在途使用的项目，不批量扫描或删除用户钥匙串。
- 删除连接成功与删除凭证成功分别报告；凭证清理失败时内联提示残留项目，不声称 Key 已删除，也不恢复已被用户撤销的连接。
- 配置仓库在进程内串行化提交，磁盘发布时用短期文件锁与版本复核避免跨进程丢失更新；钥匙串授权及网络操作不占用该文件锁。
- 按连接版本检测并发编辑冲突，合并其他连接的独立修改；同连接已变更则保留草稿并内联提示重新加载，不整份覆盖。保存期间暂时禁用该草稿的冲突操作。
- 配置状态区分“已保存、缺少 Key、尚未测试、测试失败”；保存有效与真实连接成功是两种状态。服务端错误按类别脱敏展示，不回显完整响应。

## 7. 模型发现

1. 只由用户点击触发；使用当前连接草稿的协议、地址及新输入 Key，否则延迟读取该连接保存的凭证。输入新 Key 时不先读取旧 Key。
2. 每种适配器独立定义列表地址、版本、鉴权及解析；保留中转部署前缀。不得依赖一次生成请求推断模型清单。
3. 首轮读取有大小/数量上限的一页；服务返回下一页标识时提示“仅获取首批，可手工添加其余模型”，不暗示得到完整目录。实现分页前不自动遍历未知链接。
4. 结果先显示为草稿候选，用户选择后合并。保留手工模型、自定义显示名和默认模型，按本连接 API ID 去重，超过条目上限明确提示，不静默截断后宣称全部导入。
5. 无效结果、不可用/不支持的列表接口、认证错误和取消都保留原目录。发现结果不能擅自覆盖用户声明的模型能力或容量。
6. 结果回写必须匹配连接 ID、连接/草稿版本、协议、地址、凭证版本和操作 ID。更换地址、Key、删除连接或取消编辑后，旧结果不得加入其他草稿或自动保存。
7. 远端返回的模型名、显示名和错误均是不可信文本；限制长度，不执行其中指令，不写 HTML，不渲染为可执行路径。

## 8. 旧单服务配置转换

这是同一产品当前配置格式的升级，不是对历史产品目录或标识的兼容迁移；只涉及现有 `AnimeDesktopPets` 数据，不读取其他旧目录。

1. 仅在已保存的旧 `model-provider.json` 确实存在且通过现有校验时，构造一个连接及去重后的模型条目；缺少文件意味着空态，不自动新增 OpenAI 连接。转换用固定命名空间生成可重复的连接/模型条目标识，不使用密钥或凭证正文作为标识输入。
2. 映射原服务类型、地址、默认模型及附加列表；原协议固定映射为 Chat Completions，不因新预设出现而换协议或换模型。
3. 新格式读取为优先；若已存在但损坏或版本未知，明确报错，不自动回退旧文件、更不覆盖有效数据。
4. 列表读取只在内存中解释旧配置，不读取旧密钥正文、不写新文件。第一次用户明确保存或首次确需在线使用时，才执行需要的凭证转换。
5. 凭证转换为该连接独立的钥匙串项目，新项目写入成功后再原子发布新格式。失败保留旧文件、旧 Key 与未保存草稿；原 Key 不作为其他新增连接的默认凭证。
6. 首次发布新格式时保留原 `model-provider.json` 内容作为不含 Key 的备份，不重写或删除它；校验其私有权限，新 `model-providers.json` 使用 0600，并延续拒绝非普通文件等安全校验。旧 Key 暂保留，不在迁移中删除；恢复旧配置不依赖反向转换密钥。
7. 转换幂等；重复进入、取消保存、进程中断及再次尝试不会复制多张卡片或修改默认引用。新格式和旧备份并存时不同时双写，也不支持旧版本继续写新配置。
8. 已配置服务的工具能力无法由旧文件确认，转换后标为未知，内联说明工具功能需要用户声明/测试；原连接不因此失去普通文字能力。此变化需随实际交付更新中英文 README 与相关专题说明。
