# 本机业务数据与聊天历史（macOS）

> 2026-11-24：聊天侧栏新增按桌宠实例隔离的项目文件夹和会话。`chats.sqlite` 从识别的 v2 原位升至 v3，只追加项目及会话归属表；已完成的会话不改写、不移动，列在「未分配会话」。项目索引只存 ID 和名称，不记录所选父目录或绝对路径。清空聊天历史不删除项目记录或文件夹。

## 使用方法

> 2026-11-24 实机验证：通过原生入口完成旧 Electron 业务根迁移并保留旧资料。重开后，已保存的模型无需重填 Key 即可完成一次普通文字聊天，完成轮次写入 `~/.adpets/chats.sqlite`。见[实际验证记录](实际验证记录.md#2026-11-24macos-真实桌面迁移与服务商调用)；此结果不代表其他连接或迁移资料组合均已验收。

- **新安装**：首次启动在当前系统用户主目录使用 `~/.adpets`。`~` 不是系统 `/`、文稿目录或 Git 仓库。已有 Electron 工作区不会自动搬动，仍使用原业务数据。
- **迁移现有工作区**：先发送或自行保留未保存的内容，再从「高级 → 迁移本机数据」选择「迁移到 ~/.adpets」，在系统对话框点「迁移并退出」。应用确认本地服务退出后才复制和切换；收到完成提示后手动重开。旧业务文件保留作为备份，草稿和迁移前的内存聊天不会补录。原来可用的模型不要求为了迁移重新填 Key，但能否实际调用以重开后的授权和服务商状态为准。
- **从历史续聊**：使用新数据根后，打开「聊天 → ··· → 聊天历史」。列表只显示当前桌宠的会话，每页五个，按最后一次完成时间排序；继续翻页使用该页读取时的固定边界，等待中的回复更新列表排序时不会重复翻到已见条目。每条显示聊天图标、稳定编号、时间和右箭头，不显示正文。点整行查看最近六个完成的问答，可用「更早消息／较新消息」每次翻阅最多六轮。翻页只读取本机历史，不触发模型请求，也不增加模型回放范围。「返回历史」恢复会话列表分页和焦点。即使正在看旧页，点击「继续聊天」也回到同一会话的最新状态；若此窗口尚未为该会话选模，先在输入区选择一个已保存的模型。之后可以随时为下一条消息换模型，发送时才联网，新回复归入原会话。其他会话的草稿不会被替换，进行中的回复不会被续聊操作取消。
- **清空与重新开始**：「清空历史」需二次确认，只删当前桌宠的已保存会话。保留当前显示的消息、未发送的草稿及角色资料。窗口内其他会话的草稿可从「聊天 → ··· → 恢复草稿 · 会话编号」找回，保留文本与选区；从该草稿发送会开启新会话，不会回放已清除的记录。草稿不会跨重开恢复。「清空本轮聊天」保留已保存的会话和未发草稿，只清当前窗口的消息，从新会话开始。删除桌宠后不能再从应用打开该实例的历史，但不会自动删除库内数据。
- **数据目录异常**：如果应用不能确认权威数据根、目标已被占用或迁移结果不明，请保留 `~/.adpets` 和原应用资料。不要手动合并、直接覆盖、移除锁或用旧版本写回。发布前确认失败可以保留旧工作区；崩溃留下未确认的发布记录或写锁时会保守阻断，需单独核对。若仅聊天库异常，先保留数据库。新聊天收到的回复仍会展示并提示历史未确认；无法读取原会话时不会静默发送一条缺上下文的续聊，也不会自动重发。

## 模型测试记录

已选定的业务根中，测试记录和模型配置独立校验。若测试记录不可读，应用仍可打开，已保存的模型仍可编辑和用于聊天；模型管理显示灰色「状态不可用」并暂缓测试。保留原文件，可点「重新读取测试记录」再次核对，不会联网、删除或自动重建损坏文件。显式迁移仍在发布前校验旧记录，拒绝复制坏文件。取消复测或未从本机桥收到确认时，状态点保留上一次已确认的结果；重新读取时以磁盘为准，不把已不存在的结果留在界面中。

模型配置和已完成的连接测试分开保存。显式测试后保存连接 ID 与修订、模型条目与 API ID、测试时的输出设置、UTC 时间及成功或脱敏错误类别；不保存 API Key、Keychain 引用、厂商正文、推理、聊天或角色资料。最多保留 512 组测试输入，文件上限 1 MiB。测试不更改模型配置或路由修订，也不会自动保存草稿。

刷新或重开仅从磁盘恢复记录，不补发测试。状态点只采用与当前保存的连接修订、默认模型 ID 和输出设置一致的记录；草稿测试不覆盖已保存模型的证据，编辑连接、换 Key 或删除后，旧修订记录不再返回。后续明确失败替换同一输入的旧成功，取消不会抹掉最后一条完成记录。这是历史测试结果，不保证服务商当前仍可用，也不自动授予聊天或 Agent 能力。旧版本只存在于内存的结果不能补造，需要用户再次显式测试。

测试前确认收据存储可读并独占收据写锁；损坏、权限异常、符号链接或残留写锁会在请求厂商前拒绝。测试期间只占收据锁，不占模型配置短写锁；不偷锁、不自动重试。结果经私有临时文件、文件同步、原子重命名与目录同步后才确认；落盘失败不伪报保存成功，厂商仍可能已经处理并计费。显式迁移会先校验再复制测试记录，源文件保留；新建及已选中的旧版 `~/.adpets` 均准备权限为 0700 的 `agents/`、`skills/`，记录文件为 0600。

本机若仍使用有写入锁的旧 Electron 根，不要手工 `mkdir ~/.adpets`、复制配置或清锁来绕过门禁；这样会使启动无法确认目标所有权。需使用「高级 → 迁移本机数据」的原生确认和服务退出流程。本轮不因参考 Ape 的 `~/.apex` 而读取、复制或复用其模型凭证及用户资料。

## 存储范围

| 位置 | 用途 |
| --- | --- |
| `~/.adpets/models/` | `model-providers.json` 保留 schema v2 服务商、模型、默认值和 Keychain 凭证引用；`model-probes.json` 保存有界的脱敏连接测试记录。Key 正文仍仅在 Keychain。 |
| `~/.adpets/agents/<实例 ID>/agent.json` | 首次在线轮次生成并严格检查实例的 Pi 声明；不导入或执行 Ape/Codex Agent，不覆盖不兼容文件。身份、记忆及目标仍在 `workspace/characters/`。 |
| `~/.adpets/agent-state.sqlite` | 本机 Agent 运行账本，记请求 ID、实例、来源、时间及状态，不保存实际输入、回复或凭证。重启核对未终结记录，不补发。 |
| `~/.adpets/skills/` | 私有 Skill 资料预留目录；不自动扫描、安装或启用外部 Skill。 |
| `~/.adpets/workspace/` | 保存桌宠实例、偏好、身份、记忆及目标；保留稳定 ID 和修订。 |
| `~/.adpets/chats.sqlite` | 本机服务单写；客户端只可按已登记实例分页读取摘要、读取指定会话或确认清空；回复由服务追加。数据库受目录和文件权限保护，**未加密、不同步**。 |
| `~/.adpets/live/` | 私有预留位置；不表示直播管理和平台授权已接入。 |

原 Electron `userData`、窗口位置、缓存、原片和素材库不搬；退役的 DSH 运行时临时目录不搬。既不导入旧 Swift、Codex、Ape 或 DSH 的对话，也不导入独立合成测试账本。Windows/Linux 不启用这一存储切换。

迁移在目标同卷的私有暂存目录验证白名单格式和引用，文件同步后整目录发布；原 Electron 配置下的选择记录必须与目标收据一致才能使用新根。旧 workspace 和模型写入门禁在切换成功后保留，不能将旧配置作为并行写入源。应用不因选中的目录缺失而自动重建或退回旧库。

服务只保存完成的普通对话正文，不保存未发草稿、失败或已取消轮次、本机资料问答、记忆提案、SDK 日志、原始请求或识别出的疑似凭证。取消以服务终态为界；已提交的成功轮次不会因界面随后关闭而回滚。若界面没收到确认，原轮次重试或换模型后发送同一条未修改的问题时，会先在本机核对已保存的回复；找到时直接恢复，不再调用模型。只有未找到回复，才按本次明确选定的模型发送。未找到本机回复不代表服务商从未处理上一请求。识别到原来逐问答保存的精确表结构时，服务首次打开聊天库会在事务里清除旧问答表并启用会话结构；**旧聊天不迁入**，不会改动模型、角色资料或其他应用。无法识别的库不转换。清空不是对系统备份或其他副本的安全擦除。

在已登记的同一桌宠及会话内，服务为每次显式发送读取至多五个可回放的普通问答，按原有请求预算截取；renderer 不传已保存的历史正文。切换到另一个已保存模型也可续聊。曾附带授权角色资料的整轮可以本机回看，但不会用作模型回放；本轮角色资料仍按现存逐项授权重新校验。本机查询和记忆提案不会出站。旧工作区未迁移前没有持久续聊，沿用原来的窗口内同模型上下文。

## 本机身份查询（2026-11-24）

聊天欢迎页用「查看本机身份」明确标识本机快捷查询；发送「查看本机身份」（可带中英文问号）调用固定本机端点，不用模型，也不计入在线历史。「你是谁？」是普通聊天，按当前选模及逐项资料授权发送；无模型时提示选模，不消耗草稿。

服务先核对实例仍在登记队列中，再读取该实例资料。已有自定义身份时仍只展示安全的名称与角色；没有自定义身份时，使用当前已登记实例的安全名称介绍自己，并提示从「聊天 → ⋯ → 桌宠 Agent → 身份」设置。名称缺失或疑似凭证时不回显名称。查询不会创建身份记录、增加资料修订、自动授权或在空态时转为在线请求。
