# Anime Desktop Pets

[English](README.md) | [简体中文](README.zh.md)

面向 macOS 的动漫风格桌宠系列：当前白龙是 Codex 的角色；Claude、DeepSeek、Grok 角色计划沿用同一美术风格加入。
目前只有 Codex 角色与桌边小伙伴功能已接入。桌边小伙伴与 Codex 并行运行，不修改官方应用包、不改 `app.asar`，不接管 Dock，也不自动重启 Codex。
本项目不是上述平台的官方产品或插件。

**GitHub Description (EN)：** An anime-style macOS desktop-pet collection for AI assistants: a white dragon for Codex, with Claude, DeepSeek, and Grok characters planned in the same art style.

**GitHub Description（中文）：** 面向 AI 助手的 macOS 动漫风格桌宠系列：当前为 Codex 打造白龙角色，Claude、DeepSeek 和 Grok 角色计划以统一美术风格加入。

**GitHub Topics：** `desktop-pet`、`anime`、`macos`、`codex`、`claude`、`deepseek`、`grok`

> **当前状态：本地开发原型。** 默认构建接入本地增强的完整白龙 Mac 桌宠，
> helper `dragon.30` 的日常轮询覆盖全部15个互动差分和6个待机差分；工作差分只在任务中或手动菜单选择时播放。`dragon.22` 起，只有拖动位移至少 24px 且松手速度达到 280px/s 才触发甩动弹跳；轻拖轻放停在落点，拖动姿态最多每 50ms 重算一次。
> 0.6.10 提供单 Qt 进程内共享像素缓存预算与单解码闸门。0.6.9 在 0.6.8 基础上优化姿态过渡：切换时只测量一次透明边界并复用桥接参数，避免逐帧扫描造成额外开销。
> `dragon.30` 拖拽／跑飞回默认待机改为280ms平滑渐变，待机首帧就绪才开始；拖拽相关切换固定用户尺寸与原动作校准，不再按翅膀／尾巴外框临时放大缩小。侧身、抬腿等自然姿态轮廓仍会变化，不强行拉伸成同一外形；减少动态效果不强制渐变。
> `dragon.30` 每次甩动独立50%随机奔跑／飞行，允许连续重复，不新增动作偏好菜单；松手专用384px短循环和60ms局部接缝混合减少等帧，撞墙以镜像同步朝向，不重启素材。甩动力度决定高度与衰减，大屏兜底平滑落底，不再超时硬跳；原35段素材及共享48MiB/8MiB像素预算不变。
> `dragon.25` 修复轻放仍走旧落地／疲惫飞行分支；轻拖或停住采用普通姿态，拖动与甩动均跳过停止／疲惫收尾。
> 使用真实的 35 段角色动画；原先的 PNG 呼吸效果仅作为明确选择的降级模式。弹簧收尾直接回到待机，不插入额外落地动作。
> 跟随现有 Codex 任务、原创海报生成与应用内背景仍未接入。
> 桌宠由独立辅助应用负责播放与交互，实际桌面、焦点和多屏体验仍需人工验收。

## 桌宠增强

默认 `./scripts/build.sh` 打包增强版（build 24 / `dragon.30`）；`--full-pet` 明确选择未修改原版，
`--native-pet` 为静态降级。原始下载 App 和源码仓库不变，增强版使用独立暂存源码与新签名。

- 多行气泡按内容和屏幕自适应，超长内容滚动；不再提供独立对话输入窗口。
- 拖动姿态最多每50ms判断一次；至少24px位移并达到280px/s才触发甩动弹跳，轻拖轻放保持落点。
- 日常静默轮询洗牌轮转15个互动和6个待机差分；工作差分留给任务和手动入口，走/跑/飞仍是独立移动分支。
- WebP 在后台顺序解码，预取 8 帧；QImage/QPixmap 缓存预算为 48 + 8MiB，GUI 不等待解码。
- 菜单使用 12px 圆角卡片、23px 行高、圆角悬停与细线箭头；按最长标签计算宽度，勾选和文字垂直对齐。
- 气泡短内容收紧，长正文限高滚动，详情操作靠右；90ms 淡入遵循减少动态效果。
- 浅色轮廓在源素材里也存在；保留原稿，修正透明合成路径，不宣称已经重制源蒙版。
- 0.3.0 本机单次离屏基准：GUI 取帧 P95 13.92 → 0.18ms，峰值 RSS 372 → 301MiB；不代表总内存只有 56MiB。

完整构建、回退、指标限制及预览方式见 [桌宠增强与性能](docs/桌宠增强与性能构建.md)。

## 自主活动与松手弹跳

- 空闲时每隔随机 12–24 秒，轮转播放全部待机和互动动作；工作差分不进入日常轮询，走/跑/飞移动作为独立自主分支。
- 增强版使用左右走路、跑步、飞行素材；仅在动作的运动段位移，收尾定住并停在屏内新位置。增强代码的 25 动作兼容清单保留旧轻跳/双跳/冲刺/浮游轨迹，不是未修改原版 App 的新增能力。
- 轻拖使用默认普通姿态；明显移动才按方向走／跑／飞，50ms判断节流及进入／退出阈值滞回减少来回切片。按住时只循环有效运动段，不播放站立准备或停止／疲惫收尾；停住80ms后在下一次姿态判断回普通姿态。
- 甩动要求至少24逻辑像素位移，最近150ms（含松手前停顿）合速度至少280px/s。轻拖、慢拖、小幅抖动或停稳后放手，原地直接回默认待机，不再播放旧落地／疲惫飞行；关闭位移或启用减少动态效果同样不播。明确甩动保留屏幕边界内的重力反弹，每次明确甩动随机选择奔跑追羽毛或飞行，朝向跟随松手方向；所选有效运动段在同一姿态时钟内循环，直到弹跳真正结束才直接切回默认待机，不播疲惫收尾；每圈仅做60ms局部接缝混合，不重播160ms入场。三次衰减跳跃仅保留给25动作兼容清单。
- `dragon.26` 将明确甩动的最终落点固定为当前屏幕可用区底部（Dock占位时在其上方），不以拖动起点或松手高度为地面。动作播完与浮点末帧边界都不能提前取消未落地弹簧；地面下移时重新下落。轻放仍保留落点。
- `dragon.27` 的甩动弹簧使用独立单调时钟，复用现有16ms tick；短暂WebP缺帧和160ms姿态混合只保持旧画面，不再暂停上下位移。每次最多消费50ms，不追赶积压。普通自主／手动移动仍随已解码素材帧同步；不增加定时器、不整段预载，也不扩大共享像素预算。
- **右键 → 自主活动**：定时播放动作、允许蹦跳移动、表演一套动作。关闭定时播放仍可松手移动；关闭蹦跳移动同时关闭两类位移。
- 拖拽、任务、菜单/对话框、隐藏和系统减少动态效果优先；再次按住会立即停止位移。自主动作不会发出声音、弹台词、读取额度或启动聊天任务。

此处复用原有角色素材叠加窗口轨迹，没有生成新的角色帧，也不把其他应用窗口识别为物理落脚平台。
真实桌面的手感、多屏与焦点仍待人工验收。离屏预览命令见[运行时说明](docs/桌宠增强与性能构建.md)。

## 扩展动作（已接入）

[扩展素材与接入说明](docs/扩展动作素材与运行时接入.md)：4 个新待机可从「待机差分动画」选择，6 个新移动在「自主活动 → 走路 / 跑步 / 飞行」。日常静默调度轮转15个互动和6个待机差分，不包含工作差分；工作动作仍按任务或手动菜单播放。总计 35 动作。桌宠尺寸范围为 50%–150%。「表演一套动作」和走/跑/飞是互相独立的一次性手动命令，不受自动调度开关关闭影响；减少动态效果及任务/拖拽保护仍优先。姿态短过渡按透明边界稳定角色尺寸，并在终点回到目标原始姿态；菜单和气泡样式保持不变。松手与回待机使用当前画面快照和约 160ms 预乘 alpha 混合，WebP 按逐帧时长呈现；真实桌面手感仍待验收。

## 环境要求

- Apple Silicon Mac，macOS 13 或更新版本；目前仅在本地 arm64 机器完成构建与自动检查。
- Xcode / Command Line Tools，Swift 5.9 或更新版本。
- 本机 Python 3 供构建和检查脚本使用；完整桌宠自带独立 Python/Qt，无需另配 GUI 环境。
- 已安装 Bundle ID 为 `com.openai.codex` 的官方 Codex 桌面客户端。
- 自行准备有权使用的本地媒体；运行当前原型不需要模型 API key。

原生应用没有第三方 Swift 包依赖，不需要运行 `npm install` 或 `pnpm dev`。
可选主题工具另有独立依赖，不是基础运行的前置条件。

## 快速开始

以下命令均在项目根目录运行。本机路径为：

```bash
cd /Users/ming/Documents/coding/desktop-app/anime-desktop-pets
```

### 1. 导入本地素材

本机开发目录已经导入素材，通常无需重复操作。全新检出后需要自行提供有权使用的文件。
当前选定的视频文件名是 `startup.mp4`，不是 `start-up.mp4`。

```bash
python3 scripts/import-local-assets.py \
  --video /absolute/path/to/startup.mp4 \
  --pet-preview /absolute/path/to/preview.png
```

导入会复制到被 Git 忽略的资源目录，记录 SHA-256 和来源，不修改原项目。
已有不同素材需显式添加 `--overwrite`；不要在未确认内容时覆盖。

### 2. 构建与离线检查

```bash
# 首次显式下载固定版本，校验 SHA-256，约 701 MiB。
python3 scripts/prepare-full-pet.py fetch

# 首次重建增强辅助应用需专用 Python 3.12 虚拟环境，详见 docs/桌宠增强与性能构建.md。
# 默认 helper 不内嵌动作素材；保持素材留在本地目录。
python3 scripts/build-pet-runtime.py build
./scripts/build.sh
python3 scripts/clean-builds.py --dry-run
./scripts/test.sh
./scripts/dragonctl.sh --check
```

产物为 `build/Dragon Codex Companion.app`，使用本机 ad-hoc 签名，尚未公证。

2026-11-02 已提供本机拖拽安装镜像 `build/Anime Desktop Pets-0.6.10-arm64-local.dmg`（约114MiB）。
打开镜像后，将 App 拖到 Applications；如果旧版正在运行，请先从菜单正常退出，不必退出 Codex。
这是当前 Mac 的本地开发包，仍引用本工程 `.local/pet-build/source/outputs/白龙桌宠素材`，请保留项目与素材目录；
不是可移植或已获授权公开分发包。手动拖拽安装不启用登录项；不要为普通安装运行后面的登录服务安装脚本。

获取步骤只下载和校验，不运行上游应用。构建、检查和测试不会启动或重启 Codex、
安装登录项、应用主题或发送模型请求。
`--check` 检查资源、媒体元数据与客户端发现，不等于真实播放和焦点交接已通过验收。

### 3. 不退出 Codex，先预览动画

```bash
./scripts/dragonctl.sh --preview-animation
```

**该命令会持续占用前台，视频结束后桌边小伙伴应用仍保留在菜单栏。**
从菜单栏退出，或在**另一个终端标签页**进入项目根目录运行：

```bash
./scripts/dragonctl.sh --quit
```

等第一个实例退出，再预览桌宠：

```bash
./scripts/dragonctl.sh --preview-pet
```

同一时间只能有一个桌边小伙伴实例，切换启动模式前需要先退出。
完整桌宠提供真实的待机、点击、拖拽、落地动作及分类菜单。
原生静态降级模式仍支持拖动与台词，创建时尊重“减少动态效果”；
不能由此宣称上游完整播放器已实现相同系统设置适配。

完整构建也提供一条手动预览命令，会先安全退出旧桌边小伙伴并等待清理，避免单实例冲突：

```bash
./scripts/preview-full-pet.sh
```

它不启动或重启 Codex，也不会在当前仍是静态配置时冒充完整预览。

### 4. 与 Codex 联动

退出预览实例后，选择一种模式：

```bash
# 启动或复用 Codex；直接打开构建出的 .app 也是这个模式。
./scripts/dragonctl.sh --launch
```

或者：

```bash
# 观察后续启动，不替你退出或重开当前 Codex。
./scripts/dragonctl.sh --watch
```

两种模式也都在前台持续运行，通过另一个终端标签页或菜单栏操作。
**Codex 已经运行时，只显示桌宠，不补播启动动画。** 冷启动验收需要你主动选择时机退出并重开 Codex。
只关窗口不等于退出进程，再次激活或点击 Dock 不应重复播放动画。

| 控制参数 | 作用 |
| --- | --- |
| `--status` | 查看桌边小伙伴状态 |
| `--show` / `--hide` | 显示或隐藏桌宠 |
| `--dismiss` | 结束当前 Codex 会话中的桌宠显示 |
| `--pause` / `--resume` | 暂停或恢复桌边小伙伴调度 |
| `--quit` | 退出桌边小伙伴，不退出 Codex |

每次向 `./scripts/dragonctl.sh` 传一个参数即可。
Esc、Command+. 或跳过按钮可撤掉动画；媒体失败、等待超时会清理覆盖层，不阻塞 Codex。
观察器需要在真实窗口出现后覆盖，**不保证启动第一帧完全无闪现**。

## 配置与数据

完整模板位于 `config/companion.example.json`。用户配置与运行数据保存在：

```text
~/Library/Application Support/DragonCodexCompanion/
  companion.json       # 可选：复制完整模板后调整
  pet-position.json    # 桌宠位置
  companion.log        # 有大小上限的生命周期日志
  control.sock         # 当前用户的本地控制接口
  instance.lock        # 单实例锁
```

需要自定义时复制**完整模板**，修改后退出并重启桌边小伙伴，不必重启 Codex。
相对媒体路径以资源根目录为基准；`DRAGON_DATA_DIR` 可隔离测试数据，
`DRAGON_RESOURCE_DIR` 可指定另一套资源根目录。

源码模板保留原生降级配置；默认构建时改为外部后端，路径为
`../Helpers/BailongPet.app`，相对于桌边小伙伴资源目录解析。默认复制本地增强版与独立补丁元数据，
不注入补丁，并保留其签名和来源声明。

已有用户 `companion.json` 优先于包内默认配置。如果它明确选择 `native`，需要修改完整配置，
或先备份再移开它，才会使用新的默认后端；不会静默丢弃你的设置。
动画与交互由辅助应用负责，桌边小伙伴负责启动调度、显示/隐藏与状态，不强制结束可能有任务的桌宠进程。
生命周期、隐私和降级方式见[完整桌宠接入说明](docs/完整桌宠接入说明.md)。

增强版安装包默认引用本地 `.local/pet-build/source/outputs/白龙桌宠素材`，不重复打包约 1.25 GiB
动画。可用 `DRAGON_PET_ASSETS_DIR=/绝对路径/白龙桌宠素材 ./scripts/build.sh` 指定目录；
该路径保存在包内默认配置，适合本机开发构建。需要自包含 helper 时运行
`python3 scripts/build-pet-runtime.py build --bundle-assets`，包体会重新包含全部动作素材。
旧构建成功后会自动清理未运行的历史归档；也可用 `python3 scripts/clean-builds.py --dry-run`
预览，或不带参数执行清理。清理不会删除当前 App，也不会强退仍在运行的旧版。

## 原创海报与背景计划

用户指定的模型名称严格保留为 `gpt-image-2.5`。待提供 base URL、认证方式和请求协议后，
再核实输出尺寸、返回格式、费用与限制，并取得第一次付费调用的明确同意。
当前模板禁用，没有模型请求代码；密钥只放被忽略的本地 `.env` 或系统钥匙串。

视觉方向是“月白龙姬 · 紫雾工作室”：右侧原创月白龙娘、午夜梅紫背景和低干扰留白。
详见[海报设计说明](docs/海报设计说明.md)。目前没有生成原创海报，
不把视频抽帧、渐变或现有角色 PNG 当作原创生成作品。

`scripts/theme.sh` 调用另行安装的 `codex-theme-studio`，通过 loopback CDP 修改运行时 CSS。
它是**依赖客户端版本的非官方主题方式，不是官方插件 API**。编译需审核后的海报；
应用和恢复需 `--confirm`，不会静默重启未开启 CDP 的现有客户端。
主调度器目前拒绝开启 `themeEnabled`，待兼容性与可读性验收后再开放自动联动。

## 仓库结构与 Monorepo 方向

当前已采用轻量 Monorepo：Swift 宿主和 Python/PySide6 桌宠运行时分别位于 `apps/` 下，尚未拆出独立共享 `packages/` 或 Studio：

```text
apps/companion-macos/        # SwiftPM 原生宿主、DragonCore、核心测试
apps/pet-runtime/            # Python/PySide6 桌宠播放、多宠、IPC、素材库业务逻辑
resources/                  # App 品牌标识、本地视频、桌宠及未来海报
config/                     # 配置模板
scripts/                    # 构建、测试、基准、启动与安装入口
integrations/bailong/        # 固定上游哈希、来源说明与差异补丁
docs/                       # 中文产品与工程文档
```

后续按需拆分可选 Studio、共享 Swift 包与跨语言配置协议，保持根脚本入口稳定。
不为“采用 Monorepo”而给当前 Swift 应用强加 Node 工具链。
详见[架构说明](docs/架构与设计决策.md)和[开发路线图](docs/roadmap.md)。

## 多宠生命周期内核（MP1c）

新增实例模型与Qt生命周期控制器：独立尺寸/位置/行为偏好、单只停止与重启、启动/清理超时和
单控制器锁。同一份白龙素材可由多个实例共享，媒体不复制；每个实例仍有独立ID、状态目录、尺寸、位置和活动开关。
状态栏「宠物管理」中的「创建小分身」会登记一个停止中的新实例，之后可单独显示、隐藏和调整尺寸。
使用 `./scripts/test-multi-pet.sh` 运行独立离线测试（独立Swift scratch、合成离屏Qt动画），
实例运行链路与动作菜单修复已在本工程整合；接入边界见[多宠运行时](docs/多宠实例模型与生命周期.md)。

## 多宠控制通道（开发态）

新增类型化Swift客户端与Qt实例控制器的本机Socket互通：状态、单只/批量启动、单只/全部停止、
偏好更新、同包克隆与有确认的退出。开发CLI为 `scripts/pet-instances.py`，只连接显式profile中的已有控制器，
不冷启动、不自动重放结果不确定的命令。协议与预算见[控制通道说明](docs/多宠本地控制协议.md)。
宿主管理菜单和真实白龙窗口运行链路已接入；跨进程自动测试仍使用合成适配器，真实桌面与正式发布安装流程待验收。
独立验证入口为 `./scripts/test-multi-pet.sh`。
